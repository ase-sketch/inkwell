# Inkwell — 里程碑（milestones）

> 这份文档解决什么问题：把 Inkwell 切成可独立验收的里程碑。
> 当前状态：M0 ✅ / M1a ✅ / M1b ✅ / M1c ✅ / M2a ✅ / M2c ✅ / M2b ✅ / M2.5a ✅ / M2.5b ✅ / M2.7a ✅ / M2.7b ✅ / M3 ✅ / M4 ✅ / M5 ✅（全部收口）。原则：按「能验证的能力」切，不按「写完的模块」切；每个里程碑都能独立验收，不依赖后面里程碑的东西。
>
> **执行中的拆分与新增（2026-09-21 回写）**：
> - M1 拆为 M1a（访谈引擎行为闭环，已收口）与 M1b（Codex 式布局壳，已收口）。M1b 实际范围随用户试用扩大：会话归档/重命名、会话时间分组、设定类目全量可见、暖色编辑风视觉定稿、大纲/细纲文稿（计划见 .agents/notes/proposed/feature/2026-09-21-outline-documents-plan.md）。
> - **路线调整（2026-09-21 用户拍板，依据 docs/research/2026-09-21-feature-gap-analysis.md）**：① M2 扩为「卡文追问 + 长篇上下文策略 + Skill 双轨骨架」（见 M2 节）；② 新增 M2.5「码字基本盘」（字数统计/分卷/章节排版/敏感词自查），位于 M2 之后、M3 之前；③ 新增 M1c「代写引擎整体下线」，M1b 收口后、M2 开工前立即做（决策笔记 .agents/notes/proposed/simplification/2026-09-21-writer-engine-removal.md）；④ M1b 收口提交后推送 origin。
> - **M2 细化（2026-09-21 访谈拍板）**：M2 拆为 M2a（长篇上下文三件套）→ M2c（Skill 双轨骨架）→ M2b（卡文追问，以 skill 形态交付）三个串行子里程碑；知识库检索层并入 M2a，呈现层另立 M2.7（M2.5 后、M3 前）。决策与被否方案见 .agents/notes/proposed/feature/2026-09-21-m2-design-refinement.md

## M1c — 代写引擎整体下线 ✅（2026-09-21 收口）

**目标**：移除基座的代写能力（writer 代写引擎及其 RP/SillyTavern 文风预设），让「不代写正文」在代码层成立。
- 背景：writer.home/styles/ 53 个预设 + references/ 1 个在新壳不可达（profile 下拉为硬编码白名单），但 writer.profile.tsx 的 buildWritingPrompt 硬依赖该目录，单独删预设会连锁 15+ 个 profile 契约测试红——必须整体下线（备选与实测证据见决策笔记）
- 范围：移除 writer / rp.writer / director / simulator.* 等代写相关 profile；清 writer.home、ACKNOWLEDGEMENTS.md 预设段、引用它们的测试、leader.default 里的「与 writer 协作」流程
- 文风参考改由写作 skill 项目（oh-story-claudecode、chinese-novelist-skill 等，见 spec 参考集）承载，经 M2 的 Skill 双轨骨架接入
- 验收标准：代写相关 profile 与资产移除后 profile 编译通过；app/ 与 server/ 测试不劣于基线（HANDOFF 登记的 9 条既有 server 红中相关项随之消解或更新）；访谈主流程（leader.default + interview.new-book）不受影响
- 排期：M1b 收口后、M2 开工前
- 粗估：0.5–1 个周末

## M2 — 卡文追问与长篇能力 ✅（M2a ✅ / M2c ✅ / M2b ✅ 均已收口）

**目标**：写作中卡住时，agent 基于当前章节与世界状态追问，帮作者自己找到出路。
**细化拍板（2026-09-21，决策笔记 .agents/notes/proposed/feature/2026-09-21-m2-design-refinement.md）**：拆为 M2a → M2c → M2b 串行执行，各自独立验收；朋友实证的知识库需求，检索层并入 M2a，呈现层另立 M2.7。

### M2a — 长篇上下文策略（三件套）✅（2026-09-22 AI 门禁收口，手工验收待用户）

**目标**：拒绝全文盲喂，建立「恒定注入 + 按需注入 + 可核验锚点」的长篇记忆机制。
- 未决伏笔/问题清单恒定注入：基于伏笔账本（promise.service.ts），每轮对话恒定注入未决伏笔摘要
- 提及实体按需注入：扫描对话输入与当前章节，正则/别名命中 lorebook 条目即注入该条目
- 条目锚点规范：lorebook 条目带来源标注（AI 沉淀 / 人工修改）+ 章节号 + 原文引用锚点；AI 沉淀流程（访谈沉淀、对话提取）按规范写入——朋友「AI 维护 + 人工纠偏」需求的地基
- 验收标准：在一部 ≥30 条设定条目、≥5 条未决伏笔的文稿上聊到某角色，抽查 3 轮对话的注入内容——恰好包含该角色条目与相关伏笔、不含无关条目；随机抽 5 条 AI 沉淀条目，每条均有来源标注与章节/引用锚点
- 粗估：1–1.5 个周末

### M2c — Skill 双轨骨架 ✅（2026-09-22 收口，真实 LLM 验收通过）

**目标**：打通 markdown 技能包的扫描与运行时注入，让方法论（追问库/审稿量表）以作者可手搓、可分享的形态交付。
- `.nbook/skills/{name}/SKILL.md`（YAML frontmatter：name/description）目录扫描，按描述匹配/显式唤起注入上下文
- 约定目录即拷即生效（无管理 UI）
- 红线机制：skill 仅作分析参照——交互型 profile（leader.default 等）物理上不持有 manuscript/ 正文写入工具（开工先核查现状再补齐）；profile 系统提示词置顶声明
- 验收标准：① 往 .nbook/skills/ 拷入一个新 SKILL.md 文件夹即生效，对话中可唤起并注入其内容；② 交互型 profile 工具清单中无正文写入工具；③ 删除该文件夹后不再注入
- 粗估：0.5–1 个周末

### M2b — 卡文追问模式 ✅（2026-09-22 收口，真实 UI+LLM 验收通过）

**目标**：写作中卡住时，agent 基于当前章节与世界状态追问，帮作者自己找到出路。
- 编辑器划词触发（主入口）：选中文本 → 「卡文追问」→ 带选段 + 当前章节上下文 + M2a 世界状态发问
- 追问脚本以 skill 形态交付——卡文三连问（意图/阻力/代价）为首个内置 skill
- 聊天里可手动进入追问模式（兜底入口）
- 顺带修 UI/UX 巡视归属 M2 的 UX-1/3/4/5（聊天空态、术语泄漏、会话二义性、入口语义，见 docs/research/2026-09-21-uiux-review.md）
- 验收标准：在真实文稿上划选一段触发卡文追问，agent 的追问引用所选文段与当前章节具体内容（非泛泛提问），呈现三连问结构；作者回应后追问逐层深入；聊天手动进入同等有效
- 粗估：1 个周末

## M2.5 — 码字基本盘 ✅（M2.5a ✅ / M2.5b ✅ 均已收口）

**目标**：补齐写作工具的基础码字体验（Inkwell 本质是写作工具，码字体验算核心面）。
- 字数统计（编辑器内实时 + 全书/分卷汇总）、分卷（卷章树支持建卷与章节归卷）、章节排版（首行缩进等中文排版习惯）、敏感词自查（可配置词表，扫描并定位标出）
- **内联 AI 编辑（inline.editor / NovelPromptBar）去留与边界重设计**：统一划「哪些辅助不算代写」的线（候选方向：提案卡确认制）；2026-09-21 拍板从 M1c 移入——M1c 实测其为整个内联 AI 编辑功能本体（提示条 UI + 851 行 controller + 主对话面 ~135 处会话注入 + 兼容层），非孤立 profile M2b 侦察补充（2026-09-22）：inline.editor 当前不在写域白名单内、仍可写 manuscript/，届时一并登记处置。
- 验收标准：① 码字时可见实时字数与全书统计；② 能建卷并把章节归入卷；③ 章节预览/导出符合中文排版习惯；④ 对一章文稿跑敏感词扫描能标出命中位置
- **2026-09-22 细化设计拍板（两轮访谈，全选推荐；决策笔记 .agents/notes/implemented/feature/2026-09-22-m2.5a-writing-fundamentals.md）**：
  - 切分 M2.5a 四件套 → M2.5b inline.editor 提案卡重设计（含写域红线登记），串行独立验收
  - 字数：编辑器底部状态栏（当前章+选中），口径=去空白与 Markdown 标记的字符数；全书/各卷汇总在文稿树面板顶部
  - 分卷：新建卷按钮 + 拖拽归卷 + 右键菜单兜底；移动复用既有 rename 端点零新 API
  - 排版：阅读预览（复用缩进设置 + newsprint 样式）+ 导出 txt（单章/整卷/全书），不做 docx
  - 敏感词：内置小词表 + 作品自定义 .nbook/sensitive-words.txt，手动扫描、结果面板标出命中可跳转
  - inline.editor（M2.5b）：提案卡确认制（DiffWorkbench/审批卡先例），登记 profile-write-scope 收掉直写 manuscript 穿透
  - **M2.5b 机制拍板（2026-09-22）**：摘 edit/write 工具 + profile 级 propose_edit 自定义工具（不用 approvalRequired——整卡粒度且批准后 server 真实执行，与逐条采纳冲突）；就地提案卡逐条采纳/全部采纳/再改一版；采纳经作者保存通道落盘（USER_LOCAL_ACTOR）；契约唯一事实源 shared/inline-proposal.ts。决策笔记 .agents/notes/implemented/feature/2026-09-22-m2.5b-inline-proposal-cards.md（2026-09-22 收口：真实 LLM 全链路验收通过，含流式快照两个 live bug 修复记录）
- 粗估：1–2 个周末

### M2.7a — 检索可见性 + anchors 编辑往返修复 ✅（2026-09-24 AI 门禁收口，真实 LLM 复验 22 断言 0 mismatch；UI 观感待用户手工验收）

**目标**：让作者在对话现场感知「AI 何时检索了什么」；同时排除旧编辑面板保存即抹 anchors/ext 的毁数据隐患。
- system 气泡徽标：有注入的轮次在气泡头显示「检索：N 条设定 / M 条伏笔」，展开可见条目标题+类目+命中词+来源路径；无注入轮次零提示（零命中与不触发在数据上不可区分，一律不显示以免谎报）
- 结构化归因：profile-dsl 四类 turnContext 注入补 promptSource labels，公开 DTO 携带检索元数据
- 旧设定编辑面板（WorkspaceLorebookDetailPanel）补 anchors/ext 读写往返
- 验收标准：① 真实对话提及某角色后，该轮 system 气泡头部出现徽标，展开可见标题+类目+命中词+来源路径；② 无注入轮次不出现徽标；③ 旧面板保存后 anchors 与 ext 原样保留（回归测试钉住）；④ 测试不劣于基线
- 粗估：0.5 个周末

### M2.7b — 知识库主视图 ✅（2026-09-24 收口：knowledge 80 用例 + ide-shell 契约 25 用例绿；Playwright 真实 UI 验收 8/8 通过，含编辑保存磁盘保真断言）

**目标**：阵营分组的角色卡视图 + 章节锚定履历 + 人工纠偏入口。
- rail 新增「知识库」一级入口，主区第三 surface（三栏：阵营 tab / 卡片列表 / 详情履历）
- 分组依据 = refs 关联（relation 指向 faction 条目）；未归组条目入「未分组」桶置底，可见可纠偏
- 卡片标注：来源类型（governance.source）+ 戏份分级（character 复用 subtype 值域）+ 首次登场章节（anchors 推导）
- 履历 = anchors 按章正序时间线，note 为标题（承载获取方式）、quote 默认折叠可展开、章节名可解析为 Plot 章节时点击跳转正文
- 视图内嵌编辑（标题/别名/分级/摘要/anchors 增删改/正文），保存走作者通道（USER_LOCAL_ACTOR + 乐观锁）
- 验收标准：① rail 入口+主视图+阵营 tab（含未分组桶）+卡面三项标注；② 详情履历正序呈现、可就地编辑、保存不丢字段；③ 在 ≥20 条目、≥3 阵营、角色带 anchors 的真实文稿上人工试用全流程；④ 布局契约测试更新后绿，其余测试不劣于基线
- 粗估：1–1.5 个周末

## M7 — 章节快照时光机 ✅（2026-09-29 收口：真实验收 5/5 通过；修正轮——老迁移断言被新增迁移打破已根治）

**目标**：标签栏「打快照」+ 快照列表 diff + 一键还原，给正文章级版本兜底。
- 来源：同上 P1；机制面复用 M5 演进的 nb-history 数据面

**细化设计拍板（2026-09-29 一轮访谈 + 一道架构题，5 问全选推荐；决策笔记 .agents/notes/implemented/feature/2026-09-29-m7-chapter-snapshots.md）**：
- 快照语义 = 作者主动标记的里程碑版本（只列手动打的标记，不是全部保存记录）；diff 对照 = 快照↔快照 或 快照↔当前正文
- 还原 = 强制确认 + 还原前自动给当前正文留「还原前」快照 + 还原本身进历史（可反悔回去）
- 呈现 = 编辑器内快照面板；「打快照」落在标签栏；命名 = 可选备注，缺省时间戳兜底标题
- 存储（架构题）= 宿主 app-sqlite 独立快照表，**不动基座 nb-history**（守「基座不跟进上游」红线）；快照只存指针（路径 + entryId + 备注 + 时间），正文永远由 nb-history 提供
- 还原丢字口径（拍板 A）= 还原必然丢弃未保存修改，故确认框内动态追加提醒；被否「先自动保存」（会污染兜底版语义）与「脏时禁止还原」（生硬）
- 验收标准：① 标签栏可为当前章节打带（可空）备注的快照并落库；② 快照面板列出快照，可看它与当前正文/另一快照的差异；③ 某快照可一键还原，先确认、执行前留「还原前」快照、还原后可再还原回去；④ 文案面向作者说人话零工程词；⑤ 测试不劣于基线
