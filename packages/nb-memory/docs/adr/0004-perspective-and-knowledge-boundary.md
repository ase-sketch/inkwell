# ADR 0004 — 视角与知识边界（2026-07-31）

spike 期间 nb-memory 的抽取与消解口径默认「一个角色的第一人称记忆」，但从未把这个默认显式化。正式实现要同时支持小说创作（上帝视角）与角色扮演（角色视角），必须先把「视角」这个词拆开。

## 1. 视角是三件事，不是一件

| 层 | 是什么 | 现在由谁承载 |
| --- | --- | --- |
| 叙述视角 | 第一人称还是第三人称，影响事实文本的措辞 | 抽取 prompt（`nb-memory-bench` `src/pipeline/prepare.ts` 的 `EXTRACT_SYSTEM`） |
| 知识边界 | 哪些内容有资格进这个库 | 同上（「POV 不在场的段落一律跳过」） |
| 称呼视角 | 同一实体怎么叫、何时得知是同一个 | 注册表 alias 的 `sinceTick` |

spike 把三层捆成一条 prompt 一次交付。这在单视角下无损，多视角下会塌。

## 2. 核心洞察

**as-of tick 本质上是一个降维成一维的知识边界。**

「t=5 时我还不知道她叫艾琳娜」与「C 不知道 A 私下告诉 B 的事」是同一类约束，前者沿时间轴、后者沿人际轴。现有实现把知识边界**编码进了时间轴**——单视角下这是无损的等价变换，正是它让 as-of 语义保持单一、可证、可测（时间泄漏率 0%，见 ADR 0003）。

推论：**任何把多视角搬进库内的方案都会把 as-of 从一维扩到二维，让全部正确性论证作废。** 这不是「加个字段」的改动。

## 3. 三种模式

| 模式 | 知识边界 | 别名 `sinceTick` 的含义 | ontology 版本的含义 |
| --- | --- | --- | --- |
| 上帝视角（小说创作） | 无，全进 | 叙事揭晓时点（读者何时知道） | 读者当前的理解 |
| 角色视角（RP / 伴侣） | 该角色的感官与被告知 | 该角色得知同一性的时点 | 该角色当前的理解 |
| 多主体共存（多 POV 小说） | 每个 POV 各自的边界 | 因 POV 而异 | 因 POV 而异 |

要点：

- **上帝视角下 as-of 不但没失效，反而换了个更有用的含义**——从「角色知道多少」变成「读者读到第 N 章时知道多少」。防提前泄底、查伏笔何时揭晓全靠它。
- **ontology 历史机制天然支持角色视角**：「转校生」与「其实是敌方间谍」是两个版本，角色视角下只能见前者直到剧情揭晓。这一层不用改。
- **多主体共存不做库内支持**，走一库一视角（见决策 D1）。

## 4. 已识别缺口：角色会相信错的东西

上帝视角下 `fact = 真相`；角色视角下 `fact = 见闻`，而见闻可能是假的。

现有 facts 层「发生过就永远发生过、永不失效」隐含了「为真」。误解目前只能走 state 层表达（「我以前认为 X，现在认为 Y」），但 state 只承载可变认知，承载不了「我亲眼看见一件事，但我看错了」这种**具体的错误见闻**。

这是唯一无法在摄入侧解决的缺口——因为它影响检索时要不要把该条当真相回流。

## 5. 决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | **一个库 = 一个视角**，不在库内加 `perspective` 维度 | 保住 as-of 一维语义与全部既有正确性论证（§2 推论） |
| D2 | **知识边界留在摄入侧**，宿主决定这个库该看到什么，库不管 | 边界判定需要宿主的场景知识（谁在场、谁听得到），库无从判断 |
| D3 | **抽取策略参数化**：`ingest(..., {pov: "omniscient" \| "character", povSubject?})`，抽取 prompt 按 pov 切换 | 视角的三层里，叙述视角与称呼视角都是抽取期决定的；参数化即可，不引入新概念 |
| D4 | **库内只加事实可信度标记**，且并入 `Fact` 扩展字段一起实现，不单独设计 | §4 是唯一必须进库的缺口；扩展字段同时覆盖群聊 speaker/channel，一处解决 |

## 6. 未决

1. 可信度标记的形态：布尔（`believed`）还是三态（亲历 / 被告知 / 推测）。倾向后者——「被告知」在 RP 场景极常见，且它决定该条的可推翻性，但需要真实用例验证是否用得上第三态。
2. 检索侧如何呈现不可信事实：过滤掉、还是带标记回流交给上层判断。倾向后者，与「消解是增强不是闸门」同源——库不替宿主做语义裁决。
3. 多 POV 小说的跨库主体 id 不互通（同一人在 A 库是 `su-003`、B 库是 `su-007`）。目前无需求驱动，不做。
