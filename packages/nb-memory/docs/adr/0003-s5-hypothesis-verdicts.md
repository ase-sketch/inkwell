# ADR 0003 — S5 收口：A-F 工作假设判定与遗留问题（2026-07-27）

spike 结束时对 PLAN §3 六条工作假设的逐条判定。证据 = nb-memory-bench `results/fanpai-loli/`（nb-memory 共 11 次全量 run + baseline 同题集对照）。

| 假设 | 判定 | 证据 |
| --- | --- | --- |
| A 状态层自带轻量实现，不复用 World Engine 存储；类型词汇同源；预留导出桥 | **证实** | 四 store 事件溯源 jsonl 自洽运行；`subject.type` 开放字符串与 World Engine schema 词汇一致；导出桥未实现（无需求驱动，留正式实现阶段） |

| C happening/state 二分 | **部分证实** | 二分本身自洽：facts 永不失效 + state 带失效区间，取代链可审计、无跨 topic 矛盾残留；但 **state 对 revision 类问答的增益未被 bench 证明**（检索命中率问题，见下） |
| D 边不作存储对象（≥2 subjectIds 的事实即边） | **证实** | 关系查询按 id 对查实装；entity 单跑最高 94.4%，两跳关系题（南嘉鱼—南小风—风信子）在多跑中稳定答对 |

## 遗留问题（交正式实现阶段）

1. **状态检索命中率**（S3 未达标的直接原因）：topic 措辞与提问措辞不匹配时召不回（问「经济来源」，状态名「生计来源」）；无关状态因正文字面含主体名被 BM25 召回挤位。候选方向：注入「该主体当前状态清单」（紧凑一行 × top-N，显式标注「当前状态」以区别于旧事实）、或 topic 归一化/同义词层。**未实施**——bench 分辨率不足以验证效果（见 3）。
2. **反向专名题**（p018）：查询侧不含专名、专名在答案侧，BM25 的 query→doc 方向无从发力。候选：答题侧利用主体卡别名。
3. **评测分辨率是硬约束**：revision 计分题仅 8–11 道且污染率在 6.3–18.8% 摆动，单跑散布 25–75%——任何 <20pp 的改动都无法在噪声中辨识。继续优化前必须先扩题（≥24 道）并压低污染。
4. World Engine 导出桥、sqlite embedding 缓存、agent memory 域：均未做，无需求驱动。

## 方法论沉淀（比代码更值钱的部分）

- **跨题集分数不可比**：S2 的「77.8% 门槛」是 baseline 在旧 9 题集上的成绩，扩题后必须让 baseline 同题集复测才能裁决。
- **单跑数字不可信**：同配置 entity 9 题集两跑差 33pp。裁决协议 = 扩题量 → 双跑取均值 → 同题集对照。
- **判卷方差与摄入方差是两个独立噪声源**，需分开归因（污染率摆动属前者、状态提案内容漂移属后者）。
