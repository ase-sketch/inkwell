nb-memory NeuroBook 记忆框架 · Task 113 spike 产物

给小说 / 长叙事用的记忆库。核心命题：在任意历史时点提问，都不能泄漏那个时点之后才知道的事——同一个人早期叫「粉色头发的女生」、第 11 拍才知道她叫艾琳娜，那么第 5 拍的提问就必须答不出名字。

0%时间泄漏率（对照组 22.2%）
22次 LLM 调用完成 20 章消解
1237行源码 · 零运行时依赖
4个 jsonl 文件即全部事实源
① 形态 ② 写入链路 ③ as-of 时间机器（可玩） ③b 两条时间轴 ④ 检索融合 ⑤ 设计取舍与成绩 ⑥ API 与纪律

01形态：一条原始流 + 三种派生记忆

左边点一层，右边看它的职责、存储事件和为什么这么分。四层都是 append-only 的事件溯源 jsonl，向量索引与倒排索引是可删可重建的派生物。

为什么边不是存储对象？ 一条事实标了两个主体 id，它本身就是一条边。于是「图」塌缩成「注册表 + 倒排索引」，关系查询 = 按 id 对求交集——不需要边表、不需要图数据库，也就没有图膨胀。

02写入链路：一批事实，一次联合调用

消解不是事后跑图算法，而是写入当场把称呼归一到 id。整张注册表（几十个主体）全量进上下文，所以不存在「候选召回不到就凭空造一个新实体」这类静默错误。点每一步看细节。

03as-of 时间机器

下面是真跑的迷你版引擎：语料是 bench 的冒烟语料（24 条事实 / 三天校园日常），检索逻辑（BM25 分词打分、as-of 过滤、主体卡注入、状态失效区间）是从 src/ 直译到本页的。拖动 tick 回到过去，看记忆库当时知道什么。

这台机器演示的是摄入序那条轴。引擎另有一条故事时间轴，见下面第 03b 节——本页的交互只做了前者。

03b两条时间轴

一条轴不够用，是被倒叙逼出来的：回忆章节的摄入序在推进，故事时间却在后退。单轴系统在这里必然出错——按摄入序排会把回忆排到最后，按故事时间排会丢掉「读者何时读到」。

轴是什么单调性回答什么问题
tick摄入序 / 叙事推进序永远单调叙事推进到这里时，（该视角）知道多少 → 知识边界
instant故事时间秒数，可空可回退故事时间的这一刻，世界是什么样 → 世界状态

举个具体的。一段倒叙讲主角十年前的事，它的 tick 排在当前章节之后，instant 却回到十年前：

查询命中为什么
asOfTick: 当前包含那段倒叙读者已经读到了
asOfTick: 倒叙之前不含读者还没读到
asOfInstant: 十年前只有那段倒叙故事时间上只有它已经发生

两条轴同为 AND，各自成立。别名的「何时得知同一性」也是双轴的——上帝视角关心 tick（读者何时知道），角色视角关心 instant（角色在故事时间的何时知道）。

fail-closed：查询给了某轴而记录缺该轴坐标，一律判不可见。无法安放的记录宁可漏召回，也不能泄漏进它可能并不属于的时间窗口。

04检索：两条路，一套过滤

语义路负责「意思相近」，字面路负责「专名一字不差」——账号名、道具名这类词在 embedding 空间里是召不回的，实测就栽在这上面。两路用 RRF 融合，不需要调权重。

语义路 · embedding 余弦

归一化距离 > 1.15 截断。先过滤再截断，不是「超采一批再事后裁」——后者会让 as-of 之外的条目挤掉合法结果。

⇢

字面路 · BM25（零依赖）

中文按字 bigram、ASCII 按整词。不吃语义截断——补语义盲区正是它存在的理由。

⇣

RRF 融合（k=60）

score = Σ 1 / (60 + rank + 1)——只吃名次不吃分数尺度，两路量纲不同也能合。

红线：过滤对两路同权。 tick 与主体过滤在两条路上用的是同一个 passesFilter，字面路不给 as-of 开后门——有单测钉住。

门面还会额外做三件事

动作目的
注入 as-of 主体卡提问里提到的主体，注入一行档案：类型 + 当时已知的别名 + 当时版本的本体描述。后期才揭晓的身份不会漏进来。
按主体补充召回每个提及主体额外取 3 条融合命中 + 2 条在效状态，不挤占主 limit。状态取「与问题最相关的 top2」而非全量——全量注入会让无关状态淹没被问的那条。
主体对求交提问提到 ≥2 个主体时，直接查同时涉及两者的事实——这就是「边」的派生视图。

05设计取舍与实测成绩

别名合并这件事，业界两种做法在 as-of 视角下都是错的。第三条路是把「何时得知」记进去。

做法行为as-of 提问时的后果
全局合并
（图引擎常见）		一旦得知「粉发女生 = 艾琳娜」，历史全部改写第 5 拍提问也能答出名字 —— 泄漏
永不合并
（纯 RAG 基线）		两个称呼永远是两个无关的东西第 24 拍提问也串不起来 —— 漏召回
别名带 tick
（nb-memory）		记「t≥11 起已知同一人」，合并是显式可审计事件t<11 视作两实体，t≥11 打通 —— 两头都对

未达标的那一行照直说。 认知反转题没做到目标值，归因是状态检索命中率（问「经济来源」而状态名叫「生计来源」，召不回）与评测分辨率（该类只有 8–11 道计分题，单跑分数在 25–75% 之间摆动，小于 20 个百分点的改动根本分辨不出来）。不是形态缺陷，但也没被证明有效——留给正式实现阶段，先把题量扩到 24 道以上再谈优化。

06公开 API 与纪律

import {NbMemory, FsStorage, SqliteIndexStore, planHeuristically, executePlan} from "@notnotype/nb-memory";

const memory = await NbMemory.open({
    storage: await FsStorage.open(dir), embedder, llm,
    indexStore: await SqliteIndexStore.open({file, modelKey, filterableMeta: {speaker: "text"}}),
    deferEmbedding: true,        // 摄入只落库，嵌入交给后台补
});

// 摄入：原始内容进来，分块 → 抽取 → 联合消解 → 落库
await memory.ingestRaw([{source: "chapter:01", text: 正文, instant: 86400n}], {pov: "character", povSubject: "我"});
await memory.ingestBatch([{tick: 1, instant: 86400n, text: "……"}]);   // 已抽好的事实

// 检索：语义 + 字面 RRF 融合；全部过滤对两路同权
await memory.search("粉发女孩是谁？", {asOfTick: 20});        // 知识边界口径
await memory.search("她住在哪？", {asOfInstant: 1000000n});   // 世界状态口径

// 多跳：问题里没有专名时，主体锚点先从时间窗口解出来
const plan = planHeuristically("昨天遇到的女孩，头发是什么颜色？", {now, secondsPerDay: 86400, registry: memory.registry});
const {hits, subjectsPerStep} = await executePlan(memory, plan);

await memory.backfillVectors();   // 补齐未嵌入的向量
await memory.stats();            // {entries, pendingVectors}——语义路是否降级
memory.dump()                    // 明文导出，可审查
纪律内容
jsonl 是唯一事实源四个文件（episodes / facts / registry / state）事件溯源、可 git diff；向量与倒排都是派生物，删掉照常工作，只是慢一次。语义层因此可复现、可 A/B。
成本纪律录入用 LLM（贵，可异步可批）；检索基线永远是 0 次 LLM + 1 次 embed。任何 LLM 增强都必须可选、可降级——规划挂了就退回朴素检索，绝不让增强路径变成必经之路。
消解是增强不是闸门联合调用重试 3 次仍失败就跳过本批，事实照常落库（subjectIds 留空并计数）。摄入永不因 LLM 抽风而中断。
引擎不变式兜底，不赌提示词「一个名字不能既是 A 的主名又是 B 的别名」——出现即为分身，批末自动合并修复。提示词写得再狠也只是第一道防线。
下推只能放宽，不能收紧存储层的 SQL 过滤只负责少读几行，权威判据只有一份 passesFilter。「SQL 一份过滤、JS 另一份过滤」是让 as-of 零泄漏悄悄失效的最短路径，由差分测试逐位钉死。
tick 不是时间「昨天」「上周」只在有 instant 时解析，否则如实记入 unresolved——硬映射成 tick 窗口会得到一个看似能用、实则随语料密度漂移的结果。
禁 better-sqlite3它要 node-gyp 编译，Bun / Windows 装不上。被禁的是这个包，不是 SQLite——向量持久化就用 runtime 内置的 bun:sqlite / node:sqlite，零编译。
