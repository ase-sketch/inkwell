# Changelog

## Unreleased

- - 新增第一方 SSE 帧序列化（ADR-0041）：根导出 `serializeSseEvent`（WHATWG event-stream 帧；本实现固定 event/id/retry/data 顺序、多行 data 拆分、空行终止）、`serializeSseComment` 与 `serializeSseJsonEvent`；单行字段拒绝 CR/LF、data 拒绝 CR、retry 非负安全整数。HTTP 服务、连接管理与 DTO 仍归宿主；第 71 轮 SSE 消费切片改用本 helper。
- ADR-0038（Model Context Window Protection）、ADR-0039（Prepare Write Auto-Injection）、ADR-0040（Attachment Reference Content Blocks）在独立审查与验证数字补录后升格 `Accepted`（standalone Core scope；真实宿主/Provider 验收边界保留在各 ADR 正文）。
- `retry(sessionId, invocationId, options)` 现在接受 `RetryOptions {caller?, messageIdentity?, signal?}`（旧 `AgentCaller` + `messageIdentity` 重载保持兼容）：`signal` 为 runtime-only 父取消连接，与 `invoke` 对齐——pre-aborted 不创建 durable Invocation，运行中取消复用 bounded abort。公共 admission/用法失败统一抛根导出的 `HarnessAdmissionError`（message 原文不变，12 处：steer×3/followUp/cancelFollowUp/reorder 置换/resume 审批门禁与非 waiting/retry 不存在/未配置 ContextCompactor/悬挂 Tool Call 启动拒绝/appendEntries 空 drafts）；`AbortBoundaryError` 与 `InvocationWriteFenceError` 从根导出；`waitForFollowUpQueueDrain` 改用独立选项类型名 `WaitForFollowUpQueueDrainOptions`（形状不变）。第一百零五轮（规划 A 的 C3）。
- `AgentMessage` 的 user `content` 扩为 `string | readonly AgentUserContentBlock[]`（ADR-0040）：`AgentUserContentBlock = text 块 | attachment 引用块`（`AgentAttachmentRef {id, mimeType, bytes}` + 可选 name，provider-neutral、不携带数据）；根导出 `userMessageText` 把 attachment 降级为 `[attachment omitted: ...]` marker（不读 blob）。blob 存储/授权/admission/预算/base64/hydration 全部留宿主（ModelRuntime Adapter 负责 hydrate，ContextCompactor.estimate 负责估算）；JSONL/codec 零迁移；TS 消费者对 user content 的直接字符串操作需加 typeof 收窄（唯一源级影响）。toolResult 与 assistant 输出不扩块类型（待消费者证据）。
- **合同变更（ADR-0039，第一百零三轮）**：Profile `prepareWrites` 中 kind 为 `agent.message` 的贡献在成功落盘后自动注入当前 Invocation 的模型请求——首个请求立即可见且恰好一次，位置先于随后提交的当前用户消息（与 durable transcript 顺序一致）；重启/resume 不重复注入。这是单源合同：此前「durable 但当前 Invocation 不可见、宿主须经 context sections 重复提供」的双写消费方现在会看到两次，需迁移（context-lifecycle 测试 2/4 已改单写，test 5 按新合同改写）。Tool writePlans 与 hook writePlans 的同轮注入明确不吸收（维持第九十一轮合同）；custom 事实不注入。
- 新增 `NeuroAgentHarness.appendEntries(sessionId, drafts, options?)`：宿主追加条目免手拼五层 `SessionWritePlan`（`cause`/`expectedVersion`/`expectedActiveInvocationId` 可选，空 drafts 拒绝，Core-owned kind 仍被写 admission 拒绝）；`JsonlSessionStore.listSessionIds()` 枚举当前目录正数 Session ID（重启恢复不再自维护索引）。README 新增「实现自定义 SessionStore」文档节，并修正 compactSession 的 ContextCompactor 前置条件与 `createAgentMessageEntryDraft` 的 `parentId` 选项说明（第一百零二轮，规划代理 A 的 C2 + C1 文档节 + (d) 偏差修复）。
- `ModelRuntime` 新增可选 `contextWindow`（token）：声明且 Harness 配置了 `ContextCompactor` 时，每轮模型调用前用 `compactor.estimate` 估计请求消息，超过窗口即 fail closed（明确错误、不发送超窗请求，phase 归 `run`）；未声明 `contextWindow` 或未配置 compactor 时守卫完全跳过（Core 无内置 tokenizer）。对齐 NeuroBook `assertContextWithinWindow`（第一百轮，parity C10 收口）。
- follow-up 队列在 Invocation 终态（failed/aborted）自动 durable 暂停（对齐 NeuroBook pauseFollowUps）：终态结果 resolve 后，队列非空且未暂停时写入 `harness.followUp.paused {paused: true, itemId: 队首, reason: "error" | "aborted", invocationId}`；`FollowUpQueueState.pausedBy` 新增可选 `invocationId`（admission_failed 路径形状不变）；completed 仍自动启动下一项，队列为空不写 pause 事实。pause 为单次 best-effort（宿主并发写使 CAS 冲突时静默丢 pause、不重试，与 NeuroBook 原子 pause 的差异为既定取舍）；pause 落盘晚于终态结果（宿主用 `follow_up_state` 事件或轮询 `followUpState` 观测）。Tool 抛异常仍按可恢复 error toolResult 提交并让模型继续——致命意图由显式 `ToolResult.terminate` 承载（与 NeuroBook「throw 即 fatal」的分流为既定设计，第九十九轮测试钉住）。
- `InvocationError.phase` 现在对 Run Kernel 内部 stage 做细粒度归因：model（`runTurn`）、ingest（transcript 提交，含 user/assistant/toolResult/steer）、compaction、settleRun 的失败分别得到对应 phase（对齐 NeuroBook RunKernelStageError；内部包装保留 cause，`SessionConflictError` 的 retryable 语义不变）；未包装阶段（prepare/hook/context provider 等）保持粗粒度 `run`/`abort`/`approval`。
- 新增 `NeuroAgentHarness.compactSession(sessionId, {keepRecentTokens, instructions?, signal?})`：宿主驱动的历史折叠（ADR-0037），只在 idle Session 上运行（active 时抛 `InvocationConflictError`），复用自动压缩的切分/摘要/落盘语义（pending Tool Call 拒绝、keepRecent walk-back、toolResult cut、空窗口 skip、悬挂 firstKeptEntryId fail-closed）；entry 不带 invocationId；摘要失败抛错且不落盘；不创建 Invocation、不发布 invocation-scoped runtime 事件。`CompactionRequest` 新增可选 `instructions`（摘要提示）。
- follow-up 自动 drain 失败现在 durable 自动 pause：`follow_up_error` 发布后，`harness.followUp.paused` 事实写入 `pausedBy {itemId, reason: "admission_failed", message ≤ 500 UTF-8 字节}`（`FollowUpQueueState.pausedBy` 投影，`follow_up_state` 事件随之发布），宿主据原因 cancel/reorder 队首后 `resumeFollowUps()` 恢复；手动 resume 失败仍原样抛出。对齐 NeuroBook pausedBy 语义（第九十三轮）。
- `turn_end` runtime 事件新增 `status: "waiting"`：进入 approval waiting 的 turn 以 `turn_end(turn, waiting)` 闭合（此前标 `completed`，与「工具待批、turn 未完成」语义不符；对齐 NeuroBook turn_end status 含 waiting）。resume 后从下一 turn 继续，最终以 `turn_end(completed)` 闭合；`failed`/`completed` 路径不变。
- `compactIfNeeded` 改用最新 Snapshot 的对齐投影做触发/切分/摘要窗口（此前用 run 的 messages 工作副本）：prepareWrites / hook / Tool writePlans 提交的宿主 `agent.message` 贡献会正确进入摘要窗口，cut 点与 `firstKeptEntryId` 不再因 work-copy/path 索引错位而指向错误 entry——修复前贡献会被投影整体丢弃、且已被摘要的旧消息会在保留区重复出现（宿主贡献 + compaction 组合，第九十一轮探针复现）。
- `followUp()` 不带 `caller` 选项时默认 caller 改为 `{kind: "user"}`（此前静默缺省 `{kind: "system", name: "followUp"}`）；旧队列项缺 caller 时自动启动的回退同样为 user。与 `invoke()` / `retry()` 的缺省一致，并对齐 NeuroBook `normalizeInvokeCaller`——用户提交的 follow-up 不再对 hooks/Pi trace/授权呈现为 system。显式 `caller`（如 Workflow 的 `{kind: "system", name: "workflow"}`）透传不变；ADR-0011 已补缺省记录。
- 全新 Invocation（`invoke()` / `invokeAt()` / `retry()` / follow-up 自动启动）现在从存在悬挂 Tool Call 的 Session 显式 fail closed：assistant 消息在 Tool 执行前提交，forced abort 或 Store 中途失败会留下「有 call 无 result」的 durable transcript；启动入口（`startOnce`）在 startInvocation 落盘前检查 `pendingToolCalls`，idle Session 存在未完成 Tool Call 时拒绝启动（错误 `存在未完成 Tool Call，不能启动新 Invocation：<name>`），不再把悬挂 call 喂给 provider（避免重复副作用或模型报错）。`resume()` 的待批 approval call 不受影响（waiting 由独立路径处理）；悬挂状态需要宿主显式处理（如 fork 后继续）。
- 新增 `NeuroAgentHarness.waitForFollowUpQueueDrain(sessionId, {timeoutMs, signal?, pollIntervalMs?})`：有界等待 follow-up 链排空（队列为空且无 active Invocation 时返回），队列已暂停或 active 处于 waiting（审批待决）视为稳定态直接返回；超时抛 `FollowUpDrainTimeoutError`（携带剩余项数与 active 状态，interrupted 视为未终态），signal 中止以 reason reject。纯读侧、不启动运行；宿主入队 N 个 follow-up 后可等整条链跑完再回写汇总。
- 新增 `NeuroAgentHarness.waitForInvocation(sessionId, invocationId, {timeoutMs, signal?, pollIntervalMs?})`：以 `invocationResultFromSnapshot` 为判据的有界等待，terminal 与 waiting 都返回 `InvocationResult`（waiting 由宿主决定 resume），running/interrupted 视为未终态；超时抛 `InvocationWaitTimeoutError`（携带最后状态），signal 中止以 reason reject，Session 缺失/Store 错误立即传播。纯读侧、不启动运行、不新增 Job/Lease/Heartbeat 语义，宿主在跨进程/重启后无需自写轮询循环即可等待旁路 Invocation 收口。
- ADR-0035（Session Entry Parent Reference Admission）在独立复审（Carson，2026-08-12）后升格 `Accepted`（standalone Core, first-party Memory/JSONL scope）：第六十三轮保留条件（abort/waiting 竞态 P1）与第六十七轮 approval 安全洞均已收口，第六十四至七十三轮同族证据链完整；ADR 正文补证据与范围边界，ADR 索引补齐 0036。
- `snapshot_required` session 事件的 `reason` 收窄为 `"commit_order"`：`epoch_mismatch` / `cursor_ahead` / `replay_expired` 三个声明值从未发布（订阅期恢复由 `EventConnected.snapshotRequired` 标志承担），已从公开类型移除；新增 `docs/events-inventory.md` 事件发布点清单与 `tests/event-publisher-coverage.test.ts` 运行时覆盖 smoke，防止「声明但未发布」漂移再次发生。
- `HarnessRuntimeEvent.message_committed` 现在在消息 durable 提交后真实发布（此前类型声明但全仓无发布点）：user（turn 0）、assistant、sequential/parallel Tool 结果与 approval resume 恢复的 Tool 结果都会发布 `{turn, message}`；合同明确为「仅 Harness 发起的 transcript 提交发布」——宿主通过 write / prepareWrites / writePlans / forkSession 提交的消息只经 `session_entry` 投递。发布受 attempt fence 约束，abort 后迟到提交不发布 runtime event；跨事件类型相对顺序不作承诺。
- 新增 `NeuroAgentHarness.forkSession(sourceSessionId, options?)`：从源 Session 的 active path 派生持久 fork，复制 `agent.message` 与宿主条目并丢弃 Core-owned 内部事实（usage/partial/compaction/followUp.*，与 write admission 保留集对齐；其它 `harness.*` 宿主扩展事实保留），不复制 invocationId 归属、Invocation/approval/follow-up 队列；新 Session 以 `parentSessionId` 溯源、profileKey/initial/hostContext 默认继承且可覆盖，源不被修改。ADR-0036 Accepted（standalone Core scope）。手工复制路径会踩保留 kinds、幽灵队列与 compaction 引用断链。
- 新增根导出 `invocationResultFromSnapshot(snapshot, invocationId)`：从 Store Snapshot 投影 Invocation 的 durable terminal 或 waiting 结果（与 `invocationUsage` / `invocationPartial` 同级），宿主编排器在进程重启后无需复制 private 映射即可重建 `InvocationResult`；running / interrupted / 不存在的 Invocation 返回 `undefined`。`resultFromSnapshot` / `confirmedResult` 内部实现委托该函数，行为不变。
- waiting Invocation 的 approval fact 现在在 Snapshot 读取时 fail closed：显式空或缺失 `pendingApprovals` 会在 `resume()` 绕过审批门禁直接执行 Tool（安全洞，读侧拒绝）；重复 `toolCallId` 与 turnCount 低于自身已提交最大 turn 的损坏 waiting 状态同样拒绝。错误在 `normalizeSessionSnapshot()` / Store read / reconcile 前以 `SessionInvariantError` 抛出，不自动修复。
- Snapshot 读取现在对矛盾的 Invocation/Session 状态 fail closed：重复 Invocation ID、悬挂或 terminal 的 active owner、非 active 的 running/waiting Invocation、以及无 active owner 的 running/waiting/aborting Session 在 `normalizeSessionSnapshot()` / Store read / reconcile 前以 `SessionInvariantError` 拒绝（`activeInvocationId` 缺失按 null 归一）。写侧 reducer 本已无法产生这些状态，该收紧只影响先前可读的损坏历史文件。
- Session Entry parent reference 现在在 shared reducer、`normalizeSessionSnapshot()` 与 `activeSessionPath()` 统一 fail closed：draft 省略 `parentId` 继承当前 active leaf、显式 `null` 建立 root branch、显式非空必须指向同一 Session 已存在 Entry；悬挂/空/空白 parent、空/空白/重复 Entry ID 与 parent 环在任何 durable 写入前拒绝，历史损坏读取 fail closed 不自动修复。ADR-0035 Accepted（standalone Core, first-party Memory/JSONL scope）。
- `agent.compaction` 是 Core-owned 事实：公开 `write()` 与 Profile/Tool/hook effect 的共享 write-plan seam 在 durable 写入前拒绝伪造，仅 Harness 内部 compaction 路径允许精确 plan（第六十二轮补录）。
- 并发 Interrupted Reconciliation 有界收敛：竞争 loser 观察到同一 Invocation 已不再 active running 时跳过并继续扫描，不得再次完成它；无关的 Store、I/O、lock 或 invariant 错误仍然 fail closed。
- `turn_end(failed)` runtime 事件按公开类型实际发布（声明即实现）：Model 抛错时先闭合 started turn，再发布 failed Invocation terminal，不伪造未闭合的 turn。
- 根导出 `createAgentMessageEntryDraft(message, {turn, invocationId, messageIdentity})`：构造 canonical `agent.message` draft，供 Profile/Tool/Workflow 写入 plan 复用。
- `MessageIdentity` 与 `InvocationInputOptions.caller/messageIdentity`：system/user identity 可随 durable message 持久化，legacy 缺省为 user；follow-up 入队携带 caller/identity，跨 JSONL 重启保持。
- `ContextMessageSections.modelContextAppending`：provider-neutral 当前请求分区，按 history → transcript → modelContext → modelContextAppending → appending 顺序组装。
- `abortGraceMs` 可配置取消宽限期 + bounded abort：非合作式依赖到期后强制 durable `aborted` 收口，释放 owner 并发布唯一 terminal event，迟到结果不再等待或写入。
- `SessionWritePlan.expectedActiveInvocationId` durable owner CAS：start/resume 建立不可复用 attempt，取消后迟到 Model/Tool/Hook/ContextProvider/Approval/Capability 结果在副作用与持久化前被 fence 拒绝。
- `ReadCapability` host-neutral 只读数据合同：opaque reference、offset/limit 分页提示、文本结果与 provenance/truncated 状态；路径、权限与 offset 单位由宿主 Adapter 决定，Core 不读取文件系统。
- `PreparedRun.contextProviders`：每 turn 在最新 Snapshot 上按声明顺序解析只读 ContextProvider，只把 `modelContext` 放入当前 provider request；失败在 model call 前结束 Invocation，不写入 Session。
- 第六十二轮补齐 abort 与 Store durable write 的竞态 fence：active Invocation-owned commit 通过 runtime-only `SessionCommitOptions.signal` 在 Memory/JSONL 最终写边界前 fail closed；abort overlay 下迟到计划被拒绝，重启时未完成的 aborting owner 收口为 aborted。新增 ADR-0034；不改变 durable Snapshot shape，也不覆盖忽略 signal 的第三方 Store Adapter。
- 新增显式 opt-in `createReadTool({capability, name?, description?})`：复用 `ReadCapability` 的基础 reference/offset/limit schema，将 content 与 provenance/truncated/nextOffset 映射为普通 ToolResult；不创建全局 token、不注册默认 Tool、不读取文件、不固化路径/权限策略。ADR-0033 已在 standalone Core Read Tool Adapter 范围 Accepted。
- Event cursor 恢复现在对 `after > 0` 且缺少 `eventEpoch` 的 partial/malformed cursor fail closed：订阅标记 `snapshotRequired` 且不 replay；`after: 0` 与空 cursor 保持兼容。ADR-0032 已在 standalone EventHub cursor-admission 范围接受。
- aborted Invocation 的 durable terminal 现在不再持久化 provider abort exception、forced-abort 说明或 waiting owner CAS 说明；本地 cooperative `InvocationResult` 仍可携带原始诊断，failed Invocation 继续持久化 error，legacy aborted record 的恢复 projection 也隐藏旧 error。ADR-0031 已在 standalone Core 范围 Accepted。
- JSONL delta + checkpoint 实验模式（`checkpointEvery > 1`）补齐公开回归：交替 delta/checkpoint 恢复、torn 尾残片修复、`reconcileInterrupted()`、跨模式/跨实例读取与 entry ID / version 连续性 fail-closed 合同均有测试锁定；写入与读取模式解耦，`checkpointEvery` 本身不进入 durable record。
- Tool `writePlans`、Profile `prepareWrites` 与 hook effect `writePlans` 数组现在先整批通过 `commit()` 同等的守卫与纯投影校验，再逐 plan CAS 提交；任一 plan 内部不合法时整批在任何 durable 写入前失败，不再产生无后续解释的孤儿 durable 写入。并发外部 writer 的 CAS 冲突仍可能在较早 plan 已提交后失败，该边界不承诺原子批或 exactly-once。
- `ValueSchema` 现在区分 raw decode 与 Parsed Value validation：可选 `validateParsed` 支持非幂等 decoder，`defineSchema({parse, validateParsed, jsonSchema})` 提供显式入口。Session initial、Invocation input、durable follow-up、retry、approval resume、Tool 参数与 entry codec 不再静默重复转换 canonical JSON；不稳定 schema 会在 durable mutation 或副作用前 fail closed。
- running Invocation 现在固定使用 start/resume admission 捕获的 Profile payload parser 解析 steer；Registry replacement 只影响之后的 Profile resolution，不再把新版 parser 混入旧 attempt。
- Profile `manifest.version` 现在是 waiting approval 的 durable resume 兼容身份；新 Invocation 保存有效版本（省略时为 1），跨版本 resume 在 claim/Capability/prepare/Tool/Provider 前以 `ProfileVersionConflictError` 拒绝。legacy 缺字段按版本 1 恢复，显式 `null` 或其它非法持久值拒绝恢复。
- `PreparedRun.tools` 现在把 Tool name 作为每次 prepare 结果内的唯一 provider-visible identity；同名定义会在 prepare writes、Model、approval 和 Tool 副作用前失败，approval resume 重新加载 Profile 时同样检查。
- `NeuroAgentHarness.dispose()` 现在为 concurrent/reentrant caller 提供同一个 shutdown barrier，并排空已进入的 Invocation 与 public mutation；已经开始的 Store create/commit 会在 barrier 内完成 publication，read/validation 后尚未 mutation 的操作会停止，observer/reporter 重入 shutdown 不再形成死锁。
- active transcript 与 terminal commit 可在同一 durable owner 下有界追上连续的 `harness.followUp.*` ledger 写入；第三次仍冲突或出现 unrelated Session mutation 时继续 fail closed。
- `setStatus` 现在拒绝与 durable active Invocation 矛盾的 Session projection：running/waiting owner 只允许对应状态或 `aborting`，无 owner 不得伪造 active 状态。
- Model Runtime 最终 assistant message 的 Tool Call ID 现在必须是非空字符串且在当前 active durable transcript 内唯一；冲突在 transcript/approval/Tool 副作用前失败，已发生的 Model usage 保留为 terminal fact，旧 waiting transcript 改为按 call/result occurrence 恢复。
- JSONL `reconcileInterrupted()` 现在只把缺失的 `sessions` 目录视为空恢复集；路径形状、权限、占用及其它目录扫描错误保留原始 errno 并 fail closed。
- 共享 `SessionEventHub` 的多个 Harness 现在按 Store identity、opaque Session generation 与 version 审核 durable entry/status batch；identity 变化、倒退、重复、gap 或 batch 序列化失败不再形成 seq 连续的错误 projection，而会原子降级为可 replay 的 `snapshot_required(commit_order)`。
- `snapshot()`、`createSession()` 与 `write()` 现在返回 replay-safe Snapshot/Event Cursor cut；并发 durable event 可能与 Snapshot 重叠，但不再落在旧 Snapshot 与新 cursor 之间被静默跳过。
- JSONL Session ID 分配与初始创建现在跨 Store/进程串行；相同显式 ID 至多一个成功，自动 ID 不复用已分配 gap，损坏或非法的 `session-seq.json` 会 fail closed。
- `CommitWorkflowScheduler.dispose()` 新增可配置的 bounded abort grace；不合作的 `run` / `onError` 不再永久悬挂 Scheduler shutdown，pending dirty rerun 与关闭后的 admission 会被丢弃。
- approval `resume()` 在 Capability/Tool/Provider 前以 Store CAS claim waiting Invocation；跨 Harness resolution 竞争只有一个执行者，重复/缺失 resolution ID 在 durable claim 前拒绝。
- JSONL per-session commit lock 可修复 crash 留下的 malformed final record，并保留完整但缺 newline 的合法 record。
- `storage/jsonl` 公开 `JsonlLockError`、`JsonlLockBusyError`、`JsonlLockCorruptError`、`JsonlLockLostError` 与 `JsonlLockIoError`，宿主可区分 CAS、锁状态和 Windows I/O 失败。
- `InvocationResult.persistence` 明确区分 Store confirmed 与 unknown；terminal plan 原子保存非零 provider-neutral usage，`invocationUsage()` 兼容旧 transcript。
- 新增 provider-neutral `ModelTurnError`；Adapter 可报告失败 model turn 已观察到的 token usage，Harness 在现有 terminal persistence/abort fence 内聚合。
- `ModelTurnError.partial` 可报告失败 turn 的完整 text/thinking block；Harness 将其作为不进入 retry/compaction transcript 的 terminal fact 持久化，并通过 `InvocationResult.partial` 与 `invocationPartial()` 暴露 confirmed/unknown 恢复语义。
- `InvokeRequest.signal` / `InvokeAtRequest.signal` 可将 Workflow 或宿主取消连接到当前 Invocation 的 bounded abort，并覆盖 start commit admission window；该 signal 不进入 durable Session。
- `followUp()` 以 Store Snapshot 的 durable Invocation owner 执行 admission；独立 Harness 可向同一 JSONL Session 的 running/waiting Invocation 排队，owner 已 terminal 时以 CAS 拒绝孤立 queue item。cancel/reorder 也复核 observed Session version，不再在队首已启动后返回假成功。
- `harness.followUp.*` 现在是 Core-owned entry namespace；public `write()` 与 Profile/Tool effect 不能伪造 queue/control/consume facts，旧 Memory/JSONL 记录仍可恢复。
- `SessionEventHub` 新增 immutable publish、replay/live count + serialized-byte hard limits、slow-subscriber overflow、payload-free metrics 和完整 Async Iterator close lifecycle；Harness dispose 只关闭自己创建的 Hub。
- Capability cleanup 会逆序尝试全部资源，且不会覆盖已确认结果或 persistence unknown 时的原始运行错误。
