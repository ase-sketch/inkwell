# 故障诊断

从用户观测的症状开始，读取最小相关日志、源码与合同，提出可被证据区分的原因，再选择聚焦复现。无需先有可执行复现才能开展只读分析，也不凑固定数量假设。

- 选择能触发用户实际症状的命令、测试或运行路径；按疑点缩小输入，不要求完美最小化。
- 每次探针对应一个预测，优先调试器或定向日志；性能问题先量测再修改。压力、差分和回放仅在具体疑点需要时使用，不设固定循环次数或秒级目标。
- 无法复现时说明已尝试的方法、缺失条件与推断，继续可做的分析；需要真实环境或额外授权时只阻塞依赖部分。
- 已授权修复时针对已确定原因修改，验证原症状和受影响行为；仅诊断请求不写代码。
- 按 [测试规范](../../../docs/testing/README.md#验证门禁) 决定回归测试或聚焦 smoke；没有合适测试切入点就记录缺口，不自动扩大为架构改造。
- 秘密、授权和临时数据遵循 [项目规则](../../../.omp/RULES.md)；展示内容先脱敏，不另立凭据存储方式。

## 完成条件

说明已验证原因与推断的区别、实际验证和剩余缺口。修复交付前移除本次临时探针与复现产物；无法验证时不得声称已复现或修复。
