# M2 细化设计：拆三个串行子里程碑，知识库检索并入 M2a

- Status: proposed（2026-09-21 用户批准设计，待 M2a 开工）
- Date: 2026-09-21
- 相关：docs/milestones.md（M2/M2.7 节）、docs/research/2026-09-21-feature-gap-analysis.md、docs/research/2026-09-21-knowledge-base-taxonomy.md

## Problem

M2 扩项后同时扛三件交付物（卡文追问 / 长篇上下文策略 / Skill 双轨骨架），粗估 2–3 周末，且 milestones.md 自己声明「长篇上下文策略与 Skill 骨架的具体验收口径在 M2 开工前的细化设计中定」。同时朋友实证的知识库需求（章节锚定角色/势力状态 + AI 检索注入 + 人工纠偏锚点）需要在路线上落位。另存在顺序张力：调研结论是卡文追问库为首个内置 skill 的天然载体，若 Skill 骨架排在追问之后，追问脚本要先写死再迁移，产生一次返工。

## Decision

经两轮澄清访谈，用户拍板六项：

1. **M2 拆三个串行子里程碑**，各自独立验收：M2a 长篇上下文策略 → M2c Skill 双轨骨架 → M2b 卡文追问。
2. **知识库检索层并入 M2a**（World Engine 章节状态机制是「第 X 章时角色是什么状态」的对位引擎）；呈现层（阵营分组/力量履历界面）另立 M2.7，位于 M2.5 后、M3 前。
3. **M2a 范围 = 三件套**：未决伏笔/问题清单恒定注入（基于伏笔账本 promise.service.ts）+ 提及实体正则/别名命中按需注入 lorebook 条目 + 条目锚点规范（来源标注 AI/人工 + 章节号 + 原文引用）。章节锚定状态切片不进 M2a，划入 M2.7 做检索深化。
4. **M2c 范围 = 骨架最小集**：.nbook/skills/{name}/SKILL.md（YAML frontmatter：name/description）目录扫描 + 运行时注入；约定目录即拷即生效，不做管理 UI。红线机制：交互型 profile 物理上不持有 manuscript/ 正文写入工具，profile 系统提示词置顶声明 skill 仅作分析参照。
5. **M2b 卡文追问形态**：编辑器划词触发为主入口（带选段发问），聊天里可手动进入为兜底；追问脚本以 skill 形态交付，卡文三连问（意图/阻力/代价）为首个内置 skill。
6. **顺序骨架先行**（M2c 在 M2b 前）：追问库直接以 skill 形态出生，骨架有真实载荷验证，零迁移返工。

验收口径随各子里程碑写入 docs/milestones.md 对应节。M2b 顺带修 UI/UX 巡视归属 M2 的 UX-1/3/4/5（docs/research/2026-09-21-uiux-review.md）。

## Alternatives considered

- **M2 保持单里程碑三交付物一次验收**：周期最长、风险集中，中途无可停点——被否（拆分后每个子项可独立收口、随时可停）。
- **拆两个（上下文+追问一体，Skill 骨架单列）**：上下文与追问耦合验收会让追问失败时无法区分是注入层还是追问脚本的问题——被否。
- **知识库全部并入 M2**：检索+呈现一起做，M2 变重可能 3+ 周末，违背拆分初衷——被否。
- **知识库完全独立里程碑、M2 不管**：检索注入是上下文策略的本体，拆开会造成两层检索逻辑——被否。
- **M2a 含章节锚定状态切片（World Engine「第 X 章时角色状态」）**：是朋友 KB 的核心机制，但属于三件套之外最重的一块，进 M2a 会让首个子项失去「一个周末级收口」的性质——被否，划入 M2.7。
- **M2a 只做实体提及注入**：伏笔恒定注入与锚点规范后置，但锚点规范是朋友「AI 维护 + 人工纠偏」的地基，越晚补历史条目越缺锚点——被否。
- **卡文追问只做聊天模式**：放弃划词微访谈这一对标调研确认的杀手交互——被否。只做划词：放弃兜底入口、聊天追问成本极低——被否。
- **追问先行（脚本写死 profile，骨架后至再迁移）**：追问早见但有一次迁移返工，且骨架无真实载荷验证易落空——被否。
- **M2c 附带 skill 管理 UI**：当前只有一个内置 skill，管理 UI 无对象可管——被否，等 skill 生态真实生长再做。
- **M2c 仅内置 skill、不开放作者目录**：放弃「即拷即生效」这一 skill 形态的核心价值，而成本只是约定一个目录——被否。

## Consequences

- 收益：每个子里程碑可在一个周末级收口、独立验收；追问库零返工；条目锚点规范先行，为 M2.7 人工纠偏界面与 M3 审稿引用打好数据地基。
- 影响：依赖链变为 M2（M2a → M2c → M2b）→ M2.5 → M2.7 → M3；新增 M2.7 里程碑；HANDOFF 路线拍板第 5 条登记。
- 权衡 / 已知负债：朋友最看重的「章节锚定状态履历」检索与呈现要等到 M2.7 才兑现，M2a 阶段的检索是「实体当前状态」而非「实体在第 X 章的状态」——向朋友同步预期时需讲清。M2.7 的验收口径留待其开工前细化（沿用本次的两轮访谈方式）。
