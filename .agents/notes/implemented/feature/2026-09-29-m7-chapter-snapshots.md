# Agent Note: M7 章节快照时光机——命名标记 + 快照 diff + 一键还原

Status: implemented

Date: 2026-09-29
相关：docs/milestones.md（M7 节）、packages/nb-history/README.md（数据面，本次不改）、.agents/notes/implemented/feature/2026-09-25-m5-entry-evolution.md（演进呈现面，本期沿用其 diff/归因口径）、.agents/notes/implemented/feature/2026-09-29-m6-message-to-lorebook.md（形态蓝本）

## Problem

作者码字时缺少「章节级版本兜底」。正文每次保存虽已被 nb-history 全量留痕，但那是机器的审计账本：条目多、术语是工程词、无法表达「这一版是我特别想留下的里程碑」。作者真正缺的是主动给正文打命名存档点（快照）、能看清某个存档点与当前/彼此的差异、并在写砸了时一键还原回去。数据面（nb-history timeline/snapshotBody/textDiff/restore）已具备，但没有任何作者可用的「标记一个版本」的概念。

## Decision

2026-09-29 一轮访谈 + 一道架构题，五问全选推荐，拍板：

1. **快照语义 = 作者主动标记的里程碑版本**。打快照 = 把正文的当前版本标成一个可命名存档点。快照列表只列作者手动打的这些标记（不是全部保存记录），对齐「给章节留重要存档点」的心智。diff 对照 = 快照↔快照 或 快照↔当前正文。
2. **还原安全 = 强制确认 + 还原前自动打「还原前」快照 + 还原本身留痕**。破坏性操作零防护违背写作工作台底线；还原前自动留当前版兜底，任何误还原都能反悔回去，且经既有作者写通道落历史。
3. **呈现位置 = 编辑器内快照面板/抽屉**。打快照按钮落在标签栏，快照列表 + diff + 还原都收在同一面板，贴着码字动线，不跳走。
4. **命名 = 可选备注，缺省自动时间戳**。点「打快照」弹可留空小输入框；不填则默认「8月10日 14:30」。列表默认显示时间，起名则显示名字，兼顾省事与可读。
5. **存储 = 宿主侧独立快照表，不动基座 nb-history（架构题拍板）**。nb-history 的日志是 6 种「文件内容操作」的判别联合，没有存放「标记/注记」的地方（README 虽为将来预留 ui.* 扩展位，但未实现）。本里程碑在主应用 app-sqlite 建一张轻量「快照表」：每条快照记「章节路径 + 指向的历史条目 id(entryId) + 备注 + 拍摄时间」。快照 = 指向现有历史时间线的指针。**契合项目「基座层一次性取材、不跟进上游、控制爆炸半径」红线**，对基座零返工。代价：多一个小的本地存储要维护（与项目既有 app-sqlite 共处一地，不新增第二套持久化机制）。
6. **红线（沿用既有口径，不经访谈）**：界面文案面向作者说人话，零工程词（不出现 sessionId/entryId/hash/「时间线」）；diff 的安全分支（敏感路径/超限/正文不可取）沿用 workspace-history 既有 readWorkspaceHistoryDiff 契约，不携带正文；不经作者确认不还原。

## Alternatives considered

- **快照 = 全量历史版本浏览（不区分手动/自动）**：省掉「打快照」动作，但列表极长、且失去「主动留里程碑」的意义——被否（Q1）。
- **快照手动标记但列表默认只看最近 N 个**：可兼控长度，但「快照列表」的完整语义就是作者的里程碑集，截断反而不权威；后续如遇超长可再加分页——被否（Q1，保留为后续候选）。
- **还原不自动打「还原前」快照，仅一次确认**：少一步，但误还原后回到「还原前」要靠历史里恰好有的记录，不可靠——被否（Q2）。
- **还原无确认直接执行**：最快但破坏性零防护——被否（Q2）。
- **快照列表并入既有左侧「历史/收件箱」侧栏**：架构复用度高，但码字时须切侧栏，动线长，违背「码字体验是核心面」——被否（Q3）。
- **工具栏弹出轻量浮层列快照**：最轻量但 diff 展开局促——被否（Q3）。
- **快照必须起名**：列表最可读但打断心流、增加成本——被否（Q4）。
- **扩基座 nb-history 加「标记/快照」操作类型或注记 API**：数据与历史同库同源、更统一，但改基座包公开契约（红线），基座 README 虽预留 ui.* 但未实现，改动与测试量更大，违背「基座不跟进」克制原则——被否（架构题）。
- **自建 delta/独立内容仓存快照正文**：与历史快照重复存储、体积翻倍，且失去「还原=既有 restore 通道」的复用——被否（隐含于 Q5 指针方案）。

## Consequences

- 收益：给正文章级版本兜底——作者可主动留里程碑、看差异、一键还原且可反悔；对齐验收口径「标签栏打快照 + 快照列表 diff + 一键还原」。首次把 nb-history 的版本/还原能力以「作者主动标记」形态暴露（与 M5 演进呈现互补：演进回答「谁改的」，快照回答「我留的哪个版本」）。
- 影响：新增一张 app-sqlite 快照表（含 migration）+ 快照仓储 + 3 个薄路由（打快照/列表 / diff / 还原）+ 快照面板 UI + 标签栏按钮；复用 M5 的 diff 通道（readWorkspaceHistoryDiff）与既有作者写通道（writeWorkspaceTextFileTracked）保证还原落历史。**不动 nb-history 包、不动历史写入路径契约**。
- 已知限制/权衡：① 快照指向 entryId，若该版本被 nb-history 保留策略稀疏化清理或被后续同名内容覆盖，快照可能指向不可取内容——如实降级（列表标注「内容已不可用」）；② 超大文件（>2MB）版本本就不可 diff/restore，快照打上也只能降级；③ 快照表存 entryId 而非正文，隐私上仍由 nb-history 全文快照兜底，快照表本身不含正文；④ 章节改名后快照路径需跟随（对齐 M5 followRenames 口径，路径重命名策略本次按「快照记录当时路径 + 查询时用 followRenames 定位」处理，实现时若复杂则如实降级）。

## Confirmation

- 验收标准（拍板稿）：
  ① 编辑器标签栏有「打快照」入口，作者可为当前章节打带（可空）备注的快照，快照落库；
  ② 快照面板列出该章节的快照（时间/备注/可辨标识），可查看某快照与当前正文、或两个快照之间的差异；
  ③ 某快照可一键还原：先弹确认，执行前自动为当前正文留「还原前」快照，还原本身进历史，可再次还原回去；
  ④ 文案面向作者说人话，零工程词；
  ⑤ 测试不劣于基线（typecheck + vitest 全绿）。
- 测试策略：后端路由/仓储 vitest（打快照落库、列表按路径、diff 复用通道且安全分支不携正文、还原经确认后落历史并留「还原前」快照）+ 前端纯投影/组件测试（快照行渲染、还原确认文案）；真实验收在浏览器实测：打快照→改几行→看 diff→一键还原→确认反悔能回。
## 实现与验收记录（2026-09-29 收口）

按 Decision 五条 + 拍板口径落地：

- **共享契约**：`shared/dto/chapter-snapshot.dto.ts`（前端后端唯一事实源）。快照 DTO 载 `entryId / note / createdAt / restorable`；diff 直接复用 `WorkspaceHistoryDiffDto` 不新造；还原 DTO 以 `confirm: z.literal(true)` 把「未经作者确认不还原」钉在边界层。
- **数据面**：`prisma/migrations/sqlite/20260729020000_add_chapter_snapshot/` 建 `ChapterSnapshot` 表（id / path / entryId / note 可空 / createdAt + path 索引），**只有 5 个指针列、无正文字段**——「快照不存正文」被写成迁移门禁测试的断言，不只写在注释里。基座 nb-history 零改动（`git status packages/nb-history` 为空）。
- **服务端**：`chapter-snapshots.ts`（落库/列/可取性判定/授权反查/两种 diff/取还原正文）+ `chapter-snapshot-guards.ts`（记账面内路径守卫，复用 pathPolicy 不另发明排除规则）+ 四条薄路由。
- **还原三重防护**：① `confirm` 边界拒绝；② **执行前先给当前正文（时间线末态，非目标快照）打「还原前」快照，留不下来就不还原**，绝不无退路地覆盖；③ 经既有作者写通道 `writeWorkspaceTextFileTracked(actor=USER_LOCAL_ACTOR)` 落盘并进历史，返回 `safetySnapshotId + restoredEntryId + 完整列表`。
- **授权口径**：先查快照表拿 entryId，再**反查 timeline(followRenames) 确认该 entryId 属该 path**，不接受裸 hash；安全分支原样复用 `readWorkspaceHistoryDiff`，**安全分支绝不携带正文**。
- **前端**：`chapter-snapshot-presentation.ts`（纯人话化投影，零 Vue 依赖，判别联合四分支全穷举含 default 兜底）+ `useChapterSnapshots.ts`（请求版本防竞态、diff 缓存键带对照侧、切章 reset）+ `ChapterSnapshotPanel.vue`（列表 + diff + 还原，diff 定高放包裹层照 M5 收件箱先例）+ 标签栏「打快照 / 打开存档点」。i18n 新增 `ide.chapterSnapshot.*`，en-US 由 `satisfies LocaleMessages` 编译期强制中英对齐。

**还原丢字口径（拍板 A）**：还原必然丢弃未保存修改（forceDisk 重读是唯一正确姿势），因此确认框内**动态追加**一句「当前有未保存的修改，还原会丢弃它们」——知情且只加一道拦截。被否的 B（脏时先自动保存）会把未保存内容写进历史、污染「还原前」兜底版的语义。

**过程沉淀（隐性假设）**：
1. **老测试会因新增迁移而失效**：`migrate-application-state.test.ts` 把 `changedItems` 硬编码成 1，任何新增 prisma 迁移都会打破它。修法不是把 1 改成 2（那是把坑留给下一个人），而是**从真实 migration 目录推导待应用数**做精确相等——既不写死数字也不丢断言强度；已用「临时加一条探针迁移后测试仍全绿」实测验证该坑确实关掉了。
2. **面板里「与它比较」是静态标签不是按钮**，真正的 diff 入口是点击左侧快照行——验收时点错元素会误判为「diff 区空白」。

**真实验收（m4-yan-shou 示范章节：开篇，Chromium 无头，2026-09-29）5/5 通过**：
① 标签栏出现「打快照」「打开存档点」；点「打快照」弹「给这一版留个存档点／想给它起个名字吗？留空也行，就按现在的时间叫它」，填「M7验收基线版」提交后**真实落库**（snapshot id=1、entryId=34、restorable=true），零 JS 错误；
② 用编辑器追加一段正文并保存（磁盘 301 字符），点快照行触发 `snapshot-diff` 返回 200，**双栏 diff 完整渲染**（存档的那一版 / 现在的正文 + 行号 + 新增高亮），后端直查亦为 `available`／变更 5 行；
③ 点「还原到这一版」弹确认：「确定把《示范章节：开篇》还原到「M7验收基线版」那一版吗？还原前会先帮你留一版，反悔了可以再退回来。」确认后**磁盘正文确实回到快照版本**（追加句消失）；
④ 还原前**自动留下「还原前」快照**（id=2、note=「还原前」、restorable=true）；
⑤ 点「还原前」再还原一次，**被还原掉的改动成功找回**——反悔闭环成立。全程零 JS 错误。

**测试**：typecheck EXIT=0；M7 相关 19 文件 134 测试全绿（前端 30 + 后端 104）；全量套件 3952 passed。**既有环境失败不计本里程碑**：`world-engine-profile` 与 `profile-compile-worker-preview` 在干净 M6 基线上同样失败（缺 `NEURO_BOOK_REPOSITORY_ROOT`），已用 git stash 严格验证与 M7 无关。

**遗留（已如实标注）**：① 章节改名后改名前的快照不自动跟随（决策笔记已知限制④，如实降级）；② 章节判定复用 `parseManuscriptChapterPath`，仅 manuscript/{卷}/{章}/index.md 可打快照（与「审这一章」同口径，放开到任意 md 只需改一条 computed）；③ 超大文件版本本就不可 diff/restore，快照打上只能降级。
