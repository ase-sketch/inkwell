# M2.7 知识库呈现层细化设计：拆 M2.7a/b、refs 分组、纯 anchors 履历、气泡徽标检索可见

Status: implemented（M2.7a、M2.7b 均于 2026-09-24 收口）
Date: 2026-09-24
相关：docs/milestones.md（M2.7 节）、docs/research/2026-09-21-knowledge-base-taxonomy.md（朋友实证）、.agents/notes/implemented/feature/2026-09-22-m2a-context-injection.md（anchors 地基与「注入可见 UI 留给 M2.7」拍板）

## Problem

朋友实证需求（角色卡按阵营分组、章节锚定的力量履历、可感知的 AI 检索逻辑）的底层数据地基已由 M2a 打好（anchors 规范、恒定/按需注入），但呈现层完全缺失，且 milestones.md 的 M2.7 验收标准自述「开工前细化设计中定」。开工前侦察发现四个硬事实：① 新壳主区只有聊天/码字两态，设定抽屉 280-420px 装不下三栏视图；② 数据里没有任何「条目→阵营」结构化关联；③ 唯一可编辑 lorebook 条目的旧面板（WorkspaceLorebookDetailPanel）保存即整文件覆盖、静默抹掉 anchors/ext；④ 注入消息的 promptSource 未暴露到前端，且四类 turnContext 注入不产生 label，结构化归因拿不到。

## Decision

2026-09-24 两轮访谈（12 题，用户全选推荐项）拍板：

1. **里程碑拆分**：M2.7a「检索可见性 + anchors 编辑往返修复」（小、先排雷）→ M2.7b「知识库主视图」（大、吃前两步地基），串行独立验收。
2. **检索可见性（M2.7a，已实现）**：复用现有 system 气泡通道——带注入的轮次气泡头显示「查阅 N 条设定 / M 条伏笔」徽标（落地文案用「查阅」不用「检索」，服从界面文案面向作者的红线），展开明细为条目标题+类目+命中词+来源路径；无注入轮次零提示。结构化归因：物化期产出 TurnContext:<kind> label（profile-turn-context.ts 的 turnContextLabel，注入产生那一刻打标，不依赖 DSL 书写顺序）+ 检索明细随 custom_message entry 落盘（shared/dto/agent-retrieval.dto.ts 契约）+ 投影透传 AgentChatSystemEntryDto.retrieval。
3. **anchors 往返修复（M2.7a，已实现）**：WorkspaceLorebookDetailPanel 的 draft 逻辑提成纯 TS 模块 workspace-lorebook-draft.ts（仓内 vitest 无 plugin-vue，.vue 不可导入测试），anchors/ext 以「可选字段三态」保真往返（缺省不造字段 / 显式空数组原样保留 / 有值原样搬运）；复用 workspace-frontmatter-profile.ts 既有解析渲染路径。
4. **主视图挂载（M2.7b）**：rail 新增「知识库」一级入口，主区第三 surface（与写作面同层），三栏布局（阵营 tab / 卡片列表 / 详情履历）；扩 IdeShellSurface 与布局纯函数，契约测试同步更新。
5. **阵营分组依据（M2.7b）**：refs 关联（relation 指向 faction 条目）；未归组条目入「未分组」桶置底，可见可纠偏。
6. **卡片字段（M2.7b）**：来源类型（governance.source）+ 首次登场章节（anchors 推导）+ 戏份分级（character 复用既有 subtype 值域，不改 schema）。
7. **履历形态（M2.7b）**：纯 anchors——按章正序时间线，note 为标题承载「获取方式」，quote 默认折叠，章节名可解析为 Plot 章节时点击跳转正文（解析失败降级纯文本）。
8. **编辑纠偏（M2.7b）**：主视图内嵌编辑（标题/别名/分级/摘要/anchors 增删改/正文），保存走作者通道（USER_LOCAL_ACTOR + 乐观锁）。附带任务：编辑入口需补「未知 frontmatter 键保真」（地点/规则面板已有 extra 机制可抄）与 type 口径对齐（schema 15 值 vs 面板 5 值）。

### M2.7a 实现期修正轮记录（2026-09-24）

真实链路验收抓到单测盲区：首轮写入路径（compilePrepareRunWritePlan）把「harness 已 merge 注入的 appendingMessages（merged 长度）」与「DSL 编译期 labels.appending（静态长度）」用同一下标对齐，且多条注入共用同一 appendingIndex 时 Map 按下标去重互相覆盖——首轮归因张冠李戴（缺陷 A）；「后续 invocation 首轮、无静态消息、全部注入 appendingIndex=0」形态下次轮也错配（缺陷 B，同根因）。修复：prepare-run.ts 改为按消息对象引用绑定（Map<StoredAgentMessage, insertion>），DSL 静态消息按消费顺序取下标，注入未命中即抛错；净 +59/−8，harness 累计 +19 行（基座层接线，登记于此）。回归测试先红后绿（首轮混合场景 + B 形态各一条）。

### M2.7b 实现记录（2026-09-24 收口）

按第 4-8 条拍板落地：rail「知识库」一级入口（i-lucide-library-big）→ 主区第三 surface（IdeShellSurface 扩 'knowledge'，resolveIdeShellView 三态；IdeShellModePill 收窄为两态胶囊 Exclude<'knowledge'>，不把知识库塞进聊天/工作胶囊）；进入知识库收两个抽屉、对话伴随栏保留挂载（守 M1b「AI 不消失」铁律）。三栏视图：阵营 tab（refs 指向 lorebook/faction/ 即归属，多重归属各 tab 都出现，faction 条目自身只作 tab 不进未分组，未分组桶置底）→ 卡片列表（来源/戏份分级[仅 character]/首次登场三徽标 + 别名过滤）→ 详情（anchors 章序时间线、note 标题、quote 折叠、章节点击跳正文）/ 内嵌编辑器（标题/别名/分级/摘要/anchors 增删改/正文，乐观锁保存，409 提示重读）。章序 lookup 由容器从 plot/tree 构建并统一注入卡片徽标与详情履历（闭环「投影无 chapterOrder 时按原顺序」的口径裂口）；lookup 失败降级为原顺序+一句提示，不阻塞渲染。纯逻辑全部抽纯 TS（knowledge-projection / knowledge-detail-display / knowledge-editor-save / knowledge-view-state，合计 74 用例）+ .vue 薄渲染 + 源码级接线契约测试（8 用例）。草稿模块扩展 extra/rawType 保真（未知 frontmatter 键与未识别 type 不再被保存抹掉）。

## Alternatives considered

- **tags 自由标签做分组**：无结构约束，AI 维护时标签漂移——被否（Q1）。
- **新增 faction frontmatter 字段**：动 schema 契约且与 refs 语义重叠——被否（Q1）。
- **World Engine 桥做履历/状态切片**：章→Scene→instant→queryState 技术可行（scene-world-context.service.ts 有先例），但补丁无章节号无原文引用，非朋友截图形态，且需处理无 worldAnchor 降级——被否，列远期备选（Q2）。
- **混合（anchors 履历 + WE 切片）**：范围最大，违背最小实现——被否（Q2）。
- **独立检索记录面板**：与对话上下文脱离——被否（Q3）；Context Inspector 是工程面板，不能当作者向呈现层。
- **labels 走 DSL pendingLabels 链路**：探针实证不成立——turnContext 节点 continue 后不产出消息对象，WeakMap 标签无载体；且「注入节点必须写在所有产消息节点之后」的约束与真实 profile 交错写法冲突——被否，改为物化期打标（S1 修正轮）。
- **升级设定抽屉 / 第三互斥抽屉**：抽屉定位只读且宽度不足——被否（Q4）。
- **戏份分级新字段**：动 schema 并需处理存量默认值——被否，复用 subtype（Q5）。
- **显示「本轮未检索」**：会把「没命中」误述成「没检索」，损害信任——被否（Q9）。
- **复活旧面板作编辑入口**：旧壳不可达是 M1b 刻意决策——被否（Q8）。

## Consequences

- 收益：作者可在对话现场看见并核对每轮检索（朋友核心诉求「知道并信任 AI 何时检索了什么」落地）；M2a 的 anchors 地基首次获得消费者；旧面板毁数据隐患排除；检索归因链路（物化→落盘→投影→前端）为 M2.7b 与 M3 审稿流打好通道。
- 影响：基座 harness 累计 +19 行（透传+次轮归因补写，登记在此）；session JSONL 新增可选 retrieval 字段（向后兼容，旧 entry 无字段则不显示徽标）。
- 已知限制：① 单条注入正文超 800 字符的段内截断无法在 omittedCount 表达（omittedCount 只管条数截断）；② 历史 session 里已落盘的错配 entry 不追溯回填（修复只影响新写入）；③ 每轮一次 invocation 产生两批 turnContext 写入是既有行为（多 provider turn 各自注入），本次未动；④ file-tools.test.ts 的 bash 用例存在环境抖动（临时目录 SQLite 连接，同树 5→1 红、干净树亦 1 红），与本次无关；⑤ 前端徽标的真实观感未经浏览器验收，留给用户手工试用。
- 复盘（隐性假设沉淀）：① 「跨数组位置对齐」天然脆弱——归因/元数据一律按对象引用绑定；② 手工构造的自洽夹具会绕过真实序列——写回归要走真实 DSL 编译+merge 序列（本次盲区的教训）；③ 注入存在多条写入路径（prepareRun 首轮 / appendProfileTurnContexts 次轮）——任何注入侧新机制必须逐路径核对落盘结果。
