# M2.5 码字基本盘细化设计（两轮访谈拍板）

## Problem
Inkwell 是写作工具，码字体验算核心面，但当前编辑器无字数统计、无分卷管理、无中文排版预览/导出、无敏感词自查；inline.editor 7 种操作直写 manuscript 磁盘、零作者确认，且因未登记写域白名单穿透「不代写正文」红线（M2b 侦察挂账）。

## Decision（2026-09-22 两轮访谈，用户全选推荐项）
- **切分**：M2.5a 四件套（字数/分卷/排版/敏感词）→ M2.5b inline.editor 提案卡重设计，串行独立验收。
- **字数统计**：编辑器底部轻量状态栏（当前章字数 + 选中字数）；口径=去空白与 Markdown 标记后的字符数，全书/各卷汇总放文稿树面板顶部，同口径。
- **分卷**：文稿面板「新建卷」按钮 + 拖拽归卷 + 右键菜单（重命名/移动兜底）；移动复用既有 PATCH /api/workspace-files/rename，零新 server API；001- 数字前缀维持物理排序。
- **排版**：编辑器保持 Markdown 原样；阅读预览按中文习惯排版（复用 paragraphIndent 设置 + theme-newsprint 阅读样式）；导出 txt（章节标题 + 两全角空格首行缩进 + 段间空行清洗），支持单章/整卷/全书，走既有 browser-download blob。
- **敏感词**：内置小词表 + 作品自定义词表文件（.nbook/sensitive-words.txt），手动触发扫描，命中位置标出（结果面板 + 点击跳转）。
- **inline.editor（M2.5b 方向）**：提案卡确认制——AI 产出先呈修改提案（复用 DiffWorkbench/审批卡先例），作者逐条采纳才落盘；同时把 inline.editor 登记进 profile-write-scope 写域约束。

## Alternatives considered
- inline.editor 整体下线 / 只留对话类辅助：功能损失大，用户选提案卡确认制保留。
- docx 导出：引入依赖重，用户选 txt。
- 内置大敏感词库：来源/维护/误报负担，用户选内置小表+自定义。
- 顶部标签栏放字数：显眼度低、放不下选中字数，否。
- 仅拖拽或仅右键归卷：缺兜底或操作碎，否。
- 一段做完 / 先 inline.editor：验收周期或体验收益权衡，用户选四件套先行。

## Consequences
- 侦察实证的地基：字数后端通道 100% 现成（节点 words + 前端汇总范式）；卷章树显示/拖拽/右键地基完备只缺动作层；rename 端点天然支持跨目录移动；确认制 UI 先例齐全（DiffWorkbench、AgentSwitchModeBubble）。
- M2.5a 全为确定性 UI/工具功能，验收不依赖真实 LLM；M2.5b 才需要真实 LLM 验收提案卡链路。
- 执行图：批次 1 四个并行任务（T1 字数 / T2 分卷+汇总 / T3 排版导出 / T4 敏感词），文件边界互斥（编辑器文件归 T1、文稿面板树归 T2、标签栏+新组件归 T3、全新模块归 T4）；批次 2 集成接线 + 验收。

## Confirmation（2026-09-22 收口实测）
- 门禁：M2.5a 相关 55 个测试文件 463 条全绿（含新增 100+ 条）；bun run typecheck EXIT=0。
- Playwright 实测四场景（m2a-yan-shou-2 项目，测后已还原）：①状态栏当前章 27 字、Ctrl+A 选中 27 字、全书 1,402 字+分卷徽章（仅真卷，已修根层章节/index.md 混入）；②建卷 002-vol 顺延、章节移出卷（磁盘验证 001-vol/001-ch→003-ch 序号顺延）与归卷（根层章节右键菜单曾缺失——根因是后端把根层目录默认判为 volume，前端改用 isVolumeDirectoryPath 路径判定后修复）；③阅读预览 Dialog（newsprint+缩进+上下章）、导出 txt（标题行+两全角空格缩进+单空行清洗，下载内容逐字符核验）；④自定义词表 .nbook/sensitive-words.txt 写入「黑鸦堡」→ 面板命中（第 5 行:第 1 列+上下文，内置 43+自定义 1 合并）→ 点击跳转编辑器聚焦 ProseMirror。
- 已知留尾巴：归卷保留原序号（003-ch 入空卷不变 001，仅冲突顺延），产品语义待用户试用反馈；M2.5b（inline.editor 提案卡+红线登记）未开工。
