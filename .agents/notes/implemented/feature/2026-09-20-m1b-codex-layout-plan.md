# Agent Note: M1b Codex 式布局重排 + 首次使用引导

Status: implemented

## Problem

基座 neuro-book 的 IDE 向界面对小说作者不友好：M1a 用户验收实测「UI 太难受、找不到配 API 入口、落盘验证因 UI 难用中断」。Inkwell 定位是码字工具+苏格拉底访谈，需要以 Codex 桌面版为蓝本重做壳，同时解决首次使用引导。两轮竞品调研（docs/research/2026-09-20-peer-*.md）提供布局参照系。

## Decision

经澄清访谈（2026-09-20，用户逐条确认）：

1. **UI 照 Codex 桌面版重做**，基座旧 IDE 壳废弃、不保留新旧切换；基座只留技术线。
2. **布局骨架**（四路调研共识叠加蓝本）：极窄图标栏（≈48px：会话/码字/设定/设置）+ 会话列表侧栏 + 主区情境互换 + 右侧抽屉。
3. **主区情境互换**：访谈/对话场景聊天全宽居中；打开文稿后编辑器居中、聊天收右侧伴随栏（320-380px，带一键互换把手）。
4. **设定入抽屉**：lorebook/设定以右侧抽屉承载（M1b 先做只读浏览视图），不做程序员式常驻文件树。
5. **首次引导温和不阻断**（easy-writing 教训）：空态检测无可用模型 → 显示「先配置模型」引导卡直达配置中心模型设置，配好自动消失；不卡死浏览与码字入口。空态双入口：「开始新书访谈」/「打开已有文稿」。
6. **范围控制**：M1b 只做布局重排+首次引导；提案卡确认制（调研强共识）独立立项；文件跟随/实体标蓝/改稿台待办化记入 M2/M3 备选池。
7. **旧壳处置**（2026-09-20 验收中收紧）：旧 IDE 布局代码不删，入口隐藏；lorebook 编辑、world-engine 等功能模块后续里程碑逐个迁入新壳。**补充**：「藏」不仅是导航入口——码字态主区也不得裸露旧工作区文件浏览器；智能体上下文/世界引擎/schema/project.yaml 等程序内部文件对作者一律不可见（agent 照常可用，UI 不展示）；码字态只列作者关心的正文/章节，设定查看统一走右侧抽屉。
8. **验收**：相关测试绿 + dev 冒烟 + 用户手工验收（新布局走一遍 + 引导卡验证 + **顺带回归 M1a 挂账的 lorebook 落盘**）。

## 任务拆解（派发单元）

- **B1 布局壳**：stores/novel-ide.ts 默认布局 + 新壳组件（图标栏/会话侧栏/主区互换/右抽屉）。切入点：app/pages/index.vue、NovelIdeActivityBar、既有 layoutMode='agent' 资产。
- **B2 首次引导**：空态模型检测 + 引导卡（复用配置中心打开逻辑），i18n 中英。
- **B3 旧入口隐藏**：IDE 布局入口与旧面板的可达性收口（藏而不删）。

边界：只动 packages/neuro-book/app/ 前端与必要 store；server 不动；主题只消费 app/utils/theme/README.md 登记变量。

## Alternatives considered

- **保留 IDE 布局可切换**：用户明确「不在乎基座旧布局」，两套壳长期维护负担——否决，藏而不删。
- **M1b 顺带做提案卡确认制**：布局+写入流两条战线并行返工风险大——否决，独立立项。
- **强制首次配置向导**：侵入感强，且 easy-writing 证明写作与模型解耦更友好——否决，温和引导卡。
- **墨参式对话/写作两全屏页平级切换**：切换需经侧栏、打断感强——选 Codex 式同屏主区互换+右侧伴随栏。

## Consequences

- M1b 完成后 Inkwell 外观与基座彻底分叉，上游 UI 跟进基本终止（技术线仍可跟进）——这是有意为之。
- 旧壳功能模块（world-engine 等）入口隐藏期间用户暂不可达，需在 milestones 里排回迁。
- 调研中「改稿台待办化」「实体标蓝」「文件跟随」进入 M2/M3 设计输入。
