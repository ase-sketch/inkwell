# M2.5b inline.editor 提案卡确认制重设计

## Problem
inline.editor 7 种操作（chat/rewrite/polish/expand/condense/continue_after/bridge）经 builtin.file.edit/write 同步直写 manuscript 磁盘，零作者确认；且因未登记 profile-write-scope 白名单而穿透「不代写正文」红线（M2b 挂账）。

## Decision（2026-09-22 访谈三项拍板 + 侦察实证）
- **机制**：inline.editor 摘掉 builtin.file.edit/write（只留 read），新增 profile 级自定义工具 propose_edit（defineProfileTool，**不走 approvalRequired**——侦察发现 harness 审批是整卡粒度且「批准后真实执行」，与逐条采纳语义冲突）。propose_edit 只做：校验 original 锚点精确匹配目标文件（不匹配当场报错让 LLM 修）、登记提案、返回 PROPOSAL_PENDING_AUTHOR_REVIEW 标记；不写盘。拒绝/「再改一版」由前端发起新 invocation 带作者反馈。
- **红线双保险**：inline.editor 登记进 profile-write-scope INTERACTIVE_PROFILE_KEYS（即使工具被注入也禁写 manuscript）。
- **呈现**：码字提示条/划选处就地浮提案卡，每条修改原文→改后着色对比，逐条采纳/拒绝 + 全部采纳/全部拒绝/再改一版（附言）；大改可点开 Monaco DiffWorkbenchDialog。chat 类操作不变。
- **落盘**：采纳的条目写入编辑器缓冲区并走作者保存通道（/api/workspace-files/write，USER_LOCAL_ACTOR，不受 profile 红线限制）——只有作者的手让字进正文。
- **契约**：packages/neuro-book/shared/inline-proposal.ts 是唯一事实源（propose_edit payload / 逐条 outcome / 回执类型），server 与前端都 import。
- **范围**：只动 useInlineEditorAgentController（editPreview → 结构化提案消费）与提案卡 UI；AgentChatSurface 的 135 处历史 inline 注入不动（生产主入口已不消费）。

## Alternatives considered
- harness approvalRequired 挂起审批：整卡粒度、批准后 server 真实执行（与「采纳由作者落盘」语义冲突），否。
- server I/O 层拦截转提案（profile-write-scope 扩展）：该层只能抛错无法干净挂起，伪造成功会致 LLM 落盘幻觉，否。
- 前端拦截：server 同步落盘，时序上不可行，否。
- 右侧会话面板提案列表 / 大 diff 弹窗为主形态：用户选就地提案卡+内联 diff。
- 砍续写/扩写：用户拍板 7 种全保留全走提案卡。

## Consequences
- agent 物理上失去直写正文能力（工具摘除 + 写域拒绝双保险），「不代写」红线从提示词约束升级为机制约束。
- 提案卡链路需真实 LLM 验收（M2.5b 收口门禁）。

## 验收实测修复（2026-09-22 真机 LLM 验收中发现并修复）
- **流式半截快照渲染崩溃**：流式中途偶发「合法 JSON 但 edits 缺字段」快照，parseProposalInput 原只校验顶层字段 → 提案卡 isLargeDiff(undefined) 崩溃 → Vue patch 死循环、输入条永卡「正在处理」。修复=逐条校验 edits 字段类型 + inline-diff 非 string 入参防御。
- **提案闩锁时机过早**：argsText 由服务端结构化 preview 重建（publicValuePreviewJsonValue，string 取 preview），流式中途 original 已到、replacement 未到时重建出 replacement:"" 的结构完整快照，通过校验后被闩锁（同 toolCallId 不回填）→ 采纳后段落被清空落盘。修复=watch 加状态闸门，仅 toolCall status==="success"（args 流完+服务端锚点校验已过）才建卡。replacement:"" 仍是合法删除语义，不在 parse 层堵。
- **已知限制（留尾）**：live 路径 LIVE_TOOL_PREVIEW_BYTES=16KB，单条 replacement 超 16KB 会被 preview 截断；超长改写场景需后续换非 preview 通道。

## Confirmation
- harness 层测试：propose_edit 登记/锚点校验/不写盘断言；profile-write-scope 断言 inline.editor 写 manuscript 被拒。
- Playwright + 真实 LLM ✅（2026-09-22）：划词润色 → live 10s 出卡零报错 → 采纳前磁盘哈希不变 → 全部采纳后 124 字段落被完整四段改写替换（1788→2202 字节，diff 核验）；会话恢复路径提案卡正常渲染。
- 回归测试：propose_edit 锚点校验/不写盘（server 5 条）+ profile-write-scope 互动 profile 断言 + parseProposalInput 逐条校验/状态闸门（controller 5 条）+ inline-diff 防御 4 条 + apply/卡片契约，共 36+18 条全绿；typecheck EXIT=0。
- 「再改一版」回路有单测覆盖、真机未单跑（可选场景）。
