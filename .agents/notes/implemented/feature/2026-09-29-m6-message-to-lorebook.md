# M6 对话一键沉淀设定卡：AI 起草 + 确认卡 + 会话落盘

Status: implemented
Date: 2026-09-29
相关：docs/milestones.md（M6 节）、docs/research/2026-09-21-feature-gap-analysis.md（P1 原始出处）、.agents/notes/implemented/feature/2026-09-25-m3-chapter-critique.md（自定义工具+卡片模式蓝本）、.agents/notes/implemented/feature/2026-09-22-m2a-context-injection.md（来源三值口径）

## Problem

作者在对话里和 AI 讨论出的设定结论（一个角色动机、一条世界规则、一段历史背景）只活在聊天记录里，想变成设定库条目要手动复制整理，多数人就此放弃——「讨论 → 沉淀」的循环断了。缺口调研原话：对话一键沉淀设定卡，agent 消息底栏「提取为设定」→ 选类目确认 → 写 lorebook。

## Decision

2026-09-29 一轮访谈、四题全选推荐拍板：

1. **AI 起草 + 作者确认**：点「提取为设定」后由当前会话的 AI 把内容消化成规范条目草稿（标题/别名/摘要/正文——别名是检索命中的关键，手填基本会缺位），以确认卡呈现；作者可选类目、改字段、确认或取消。
2. **AI 会话写 + source 标 manual**：确认后由会话内 AI 用既有文件写工具落盘 lorebook/<类目>/<条目>/——演进时间线（M5）归因到这场对话，可回溯「这条设定是哪场讨论沉淀的」；来源语义上是作者确认的人工结论，governance.source 标 manual，不新造来源值（守 M2a 三值口径）。
3. **双粒度入口**：agent 消息底栏按钮（整条消息）+ 划词浮出菜单加「提取为设定」（选段，与 M3「发给顾问挑刺」同位置同形态）。
4. **不拆子里程碑**，一次收口。
5. **实现形态（定为约束）**：照抄 M3 蓝本——shared/ 契约模块（自定义工具名 + 草稿 DTO）+ 服务端窄注册（工具本身不写文件，只是草稿提交通道）+ leader.default 挂载 + 聊天流渲染确认卡（tool-render-registry，M3 CritiqueCard 同款）；确认/编辑后确认 → 前端自动回发结构化确认消息 → leader 走既有写工具落盘；取消零副作用。
6. **红线（沿用既有口径）**：工具与卡片只做草稿与确认，不绕过作者确认直接落盘；界面文案面向作者说人话；草稿不修改原消息。

### 确认卡（M6-T-B 落地时定下的形态）

- **卡片挂在主聊天流的按工具名特化渲染**（tool-render-registry 里 `submit_lorebook_draft` 走 `mode: "message"`，与 M3 质疑卡同一位置同一形态）：卡常驻可见、自带折叠，字段编辑与确认按钮不藏在折叠头后面。
- **类目下拉 + 文字字段全部可改，确认以卡上当前值为准**：确认消息由卡上字段现算，不复读工具参数原文——作者改过的类目与文字必须原样生效。
- **确认 = 一条结构化消息发进当前会话**：宿主在 AgentChatSurface 里 provide 一个发送通道（卡片 inject 消费），内部走的还是作者手打那条 send() 路径，不另造 HTTP 调用。消息里同时给全最终字段（名称/类别/别名/摘要/正文/原文摘录/条目目录名）与落盘口径（写到 `lorebook/<类别>/<条目>/index.md`、frontmatter 按既有模板补齐、status: active、governance.source: manual、写完一句话回报路径）。
- **发送失败不假装确认**：只有消息确实进了会话（出现新的、非 unknown 的乐观用户消息）才把卡落到「已确认」；失败留在待确认，作者能改完再点一次。
- **取消零副作用**：只把卡标成已取消并记住这个状态，不产生任何要发送的内容、不写任何文件、也不需要会话在线。
- **卡片状态只落本机浏览器存储**（键按 Project 作用域 + 会话 + 这条草稿分区，与会话记忆同一口径）：作者改过的字段与三态在原会话重开时原样回来，读不出来一律当没动过。
- **目录名不猜音译**：建议目录名合法就用，否则按标题现算；中文标题算不出来时消息里显式留空，要求落盘方按名称另取一个小写英文目录名。

## Alternatives considered

- **纯手动对话框（零 LLM）**：即时但原标题/别名缺位，条目在检索层是死的——被否（Q1）。
- **作者通道 write API 直接落盘**：演进归因显示「你手动编辑」，丢失与那场讨论的链接，而 M5 演进链路正好能吃上归因——被否（Q2）。
- **新造来源值 dialogue**：语义最准但破坏 M2a 三值口径，检索与知识库标注都要跟进——被否（Q2）。
- **只做整条消息入口**：划词选段是同等高频场景且入口形态已有 M3 先例，一次做齐——被否（Q3）。
- **确认卡直接调写接口落盘**：绕开会话里的 AI，演进（M5）归因只剩「你手动编辑」，也失去与那场讨论的链接，且前端要多持一份写域白名单——被否（Q2 已定「AI 会话写」）。
- **确认卡另造一条 HTTP 发送通道**：与作者手打消息两条路径会漂出不同的会话状态语义（运行中 / 未选会话 / 未接受），维护成本与行为分叉都不划算——改为宿主 provide 既有 send()。
- **取消时把已取消状态写进项目文件**：取消的意义就是零副作用，落盘痕迹反而要作者去清理——取消只留本机记忆。
- **确认后再让作者回头改字段**：确认即交接，卡落定后字段转只读（要改就再走一次提取），避免「消息已发、卡还在改」的错位。

## Consequences

- 收益：「讨论 → 沉淀 → 设定库」闭环打通；M5 演进归因首次获得正向消费者（沉淀即留痕）；确认卡模式继 M2.5b/M3 后第三次复用，交互语言统一。
- 影响：leader.default 新增一个草稿提交工具（不写文件，写域不变）；确认后的落盘走既有写工具与写域白名单（lorebook/ 本就放行），无红线变动。
- 已知限制：草稿质量依赖模型；作者确认后落盘失败（如重名冲突）的处理走会话内自然语言回报，不做专门冲突 UI。

### 实现与验收记录（2026-09-29 收口）

按 Decision 六条落地，三个子任务：

- **T-A 契约+窄工具+leader 挂载**：shared/lorebook-draft.ts（工具名/9 类目枚举/zod DTO/中文标签/slug 生成）；submit_lorebook_draft 以 defineProfileTool 注册进 leader.default，**零写盘**（源码切片断言钉住）；profile-sdk 只加字面量常量不 re-export 契约（守 M3 教训）；System 区补沉淀纪律（未经确认不落盘、source 标 manual、不拿对话原话凑 anchors）；公开投影预算回归测试防 M3 的 [unsupported] 空壳。
- **T-C 双入口**：消息底栏按钮（链 Bubble→Flow→Surface 内部 send()，不动 index.vue）+ 划词菜单项（照 M3 挑刺链路至 index.vue）；extract-entry.ts 构造器两粒度共用指令正文，原文进引用块。
- **T-B 确认卡**：LorebookDraftCard.vue（mode:"message" 挂载 tool-render-registry）+ lorebook-draft-card.ts 投影 + agent-session-message-context.ts（provide/inject 卡片→会话发送通道，不注入时提示不动作）；三态 + 可编辑字段 + localStorage 状态；确认组装结构化消息由 AI 走既有写工具落盘。
- **真实验收（m4-yan-shou）4/4 通过**：① 指令出卡、参数过契约、确认前零写调用（entry 序证据）；② 确认 → 落盘 lorebook/note/caobang-rules-tbd/（source: manual、逐字段比对全绿）、知识库可见、M5 演进归因到该会话（timeline API 实证）；③ 划词选段出第二卡（带出处 chip）；④ 取消零副作用（无新文件、无写调用、entry 集合不变）。

**过程事故（已沉淀进 ptc-orchestrator 预设 R5）**：DSH 升 0.2.0-rc.1 移除父子通讯插件，send_message 只剩团队版——报到/催办纪律失效，改降级模式（任务书自带决断规则 + 终点全证据）；「failed before it finished」通知误标存活执行者，一次误重派造成双执行者撞车（T-A2/T-A3、T-C/T-C3 各存活一对）——因任务书与蓝本一致，撞车者转为独立验收反而多赚一轮互证。教训：重派前必须有「无存活写者」的二次文件证据。T-B 被 stopped 时实现已完整（复审补验：41/41 绿 + typecheck 0 + 接线/i18n 齐全）。

**顺带发现**：基线红 profile-compile-worker-preview 与 world-engine-profile 的根因是缺 NEURO_BOOK_REPOSITORY_ROOT 环境变量，设上即绿——后续可修测试环境隔离（未做，不属本期）。

**已知限制**：卡片状态只落本机浏览器（localStorage），清缓存后已落盘卡回「待确认」，重复确认靠模型核对已有文件自觉拒写（实测行为正确，非硬约束）；底栏按钮入口未经真实点击（与划词同构造器，契约测试已覆盖接线）。
