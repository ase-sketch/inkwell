# 临时 V6：概念与披露的阅读记录

状态：设计稿，方向已由开发者同意，尚未实现或运行 20 章实验。本文是新实验的模型合同，不是产品 Spec；现有 v4 数据、schema 和页面继续作为旧实验基线。

配套：[V2 ingest 管道](../t03-extraction-pipeline-design/ingest-pipeline-v2.md)。V5 已被开发者废弃；`typescript-memory-dsl.md` 是此前的探索记录，不作为本实验合同。

## 1. 目标与暂缓事项

最终目标是让读书 Agent 用图搜索、关键词搜索、向量搜索和原文读取，以读者视角回答关于一本书的问题，并提供证据。

本轮先积累前 20 章的概念与披露，观察跨章指称、检索质量和成本。不是先建立完整世界模型再抽取正文。

暂缓 Kind、继承、Trait、字段路由、固定谓词、事件本体、Fact 内容哈希和自动世界状态求值。剧情动作可以写进披露，无需先定义 Event 类型。20 章不是分类一定成立的阈值，而是本次共同观察的数据范围。

## 2. 三种核心记录

| 记录 | 定义 | 不代表什么 |
| --- | --- | --- |
| Concept（概念） | 值得持续指称或作为检索入口的对象、身份、类别或抽象内容 | 登记不证明对象真实存在，不预先确定类别 |
| Beat | 章内连续原文区间及其简短概括 | 概括不是可替代原文的事实证据 |
| Disclosure（披露） | 文本在具体位置表达的内容，附来源、相关概念和证据 | 不自动等于世界真相，不要求拆成固定主谓宾 |

“苏天晴”“黑色古书”“星界使者”都能登记为 Concept，但不会因为使用同一种记录就被当成同一种事物。具体人物与职业、群体之间的区分暂留在披露和正文中。

基本图关系由程序生成：

```text
Concept ← about → Disclosure → evidence → 原文
Beat → paragraphs → 原文
```

`about` 仅表示相关，不表示因果、归属或角色方向。两个概念共同出现在披露里，不能直接推出它们之间的关系。

## 3. 抽取尺度

原文完整保留，Beat 覆盖完整章节；披露可以涉及任何领域，但不穷举每句话能够拆出的所有命题。

概念优先登记：持续行动或被指称的角色、剧情相关物品与约定、重要地点、被解释或反复讨论的身份和设定。一次性的背景物件、数量和普通修饰语通常留在披露或原文，不各建节点。单次出现但剧情关键的内容仍可登记，不设出现次数硬阈值。

一条披露保留一个可独立检索的表达单元；同一来源、同一证据范围内紧密相连的内容可以合写。来源、语气或所述时间不同就分开，不跨多个来源拼成一个“共同确认”。

例如：

- “A 说 B 有两只耳朵”：可记为关于 A、B 的披露，来源是 A，不必建立耳朵概念。
- “B 摸了摸她两只大耳朵”：可保留整个动作描述，不额外生成耳朵数量属性。“两只”已写在正文，不是推测；不拆属性是粒度选择。
- “B 摸了摸耳朵”：不能补成两只。

## 4. TypeScript 是记录语言

LLM 输出固定结构的 TypeScript 字面量，而不是发明类、函数和字段。类型由管道提供，LLM 不修改。下列合同描述模型可见的输出形状；正式 ID 和索引由程序装配。

```ts
type Span = readonly [from: number, to: number];
type ConceptRef = string;

type Concept = {
  id: string;
  label: string;
  at: number;
};

type Beat = {
  id: string;
  paragraphs: Span;
  gist: string;
};

type Source =
  | { channel: "narrator" | "author" | "system"; holder: null }
  | { channel: "speech" | "thought"; holder: ConceptRef };

type Disclosure = {
  id: string;
  evidence: Span;
  about: readonly ConceptRef[];
  source: Source;
  mode: "assertion" | "question" | "request" | "conjecture";
  text: string;
  timeText: string | null;
};

type Extraction = {
  concepts: readonly Concept[];
  disclosures: readonly Disclosure[];
};
```

`id` 是输出内的局部键，不是 LLM 分配的全书身份。新概念引用使用本批局部键；复用概念使用输入中给定的 `known:` 引用，两种命名空间不能混用。程序检查唯一性与引用，不要求 TypeScript 推导字符串间的关系。

`label` 使用该概念首次登记处可见的称呼，不用后文名称回写。新名字、别称和身份揭晓另记披露；检索别名是带证据位置的派生索引。

`timeText` 保留“此前”“五分钟前”“从今天开始”等必要的故事时间表达；`null` 表示没有单独记录时间限定，不表示永恒成立。正文阅读顺序和故事时间不混同，本轮不强制创建 Moment 或排序倒叙。

`mode` 区分断言、疑问、请求和推测。引语中的否定、承诺、条件、犹豫等仍须保留在 `text` 中；枚举不能代替语义。抽取阶段不加入独立的读者推断。

## 5. 第一章的最小样例

以下是选段示意，不是完整章输出。概念名称取自第 6、8、45 段；第 45 段只说明古书自称星界使者，未说明该身份的完整定义。

```ts
const extraction = {
  concepts: [
    { id: "su", label: "苏天晴", at: 6 },
    { id: "book", label: "黑色古书", at: 8 },
    { id: "envoy", label: "星界使者", at: 45 },
  ],
  disclosures: [
    {
      id: "d45",
      evidence: [45, 45],
      about: ["book", "envoy", "su"],
      source: { channel: "speech", holder: "book" },
      mode: "assertion",
      text: "古书自称星界使者，表示将引导苏天晴走上完美的生活。",
      timeText: null,
    },
  ],
} satisfies Extraction;
```

第一章第 59 段古书询问“契约就算成立了？”，第 60 段苏天晴回答“成立”。必须分开记录来源和疑问、断言，不能合写成古书已确认。第 77 段系统要求走上某条道路，也不能直接转换为身份已经变化。

## 6. 证据、身份与阅读位置

本轮证据使用章内一个连续段区间；章号、书标识、正文版本由输入包绑定。完整位置为 `(chapter, paragraph)`，按章序和段序比较。

披露的可见位置由证据末段生成。证据范围必须足以支持整条表达，不能用后段信息写进前段披露。跨段指代所需上下文可以包含在证据区间中。跨章重复表述仍保留为不同披露，不拼成跨章证据，也不覆盖旧说法。

Beat 概括在读完 Beat 末段后可见。阅读位置落在 Beat 内部时，只返回已读原文部分，不返回完整概括。概念在登记位置之后可见，具体名称和同指结果各自受其证据位置限制。

一个概念可以复用多个章节的披露。名字相同不是同一概念的充分条件；无法判断时保留分立记录及可选同指候选，不能静默合并。后文揭晓同一身份时也不能把这一结论提前暴露给此前读者。

## 7. 检索与回答

最低可用能力是证据图，不依赖整理后的分类或谓词：

1. 按名称、称呼和语义查概念候选。
2. 用关键词与向量混合搜索披露、Beat 和原文片段。
3. 沿 `about` 查相关披露，返回来源、位置和短内容。
4. 读取必要原文及前后文，再形成带引用的回答。

所有工具输入包含 `readAt`，检索前过滤可见记录，返回前再次检查。跨越阅读位置的原文片段只允许返回已读部分，不能使用完整片段的未来内容或全文摘要来排序、展示结果。

回答区分正文描述、角色说法和 Agent 推断。Agent 推断不自动写回披露。没有命中不等于书里没有；“列出全部”类问题需要逐章核查或说明覆盖范围，不能把向量 top-k 当完整集合。

耳朵数量未结构化仍可回第 18 段回答。契约关系未归一化仍可从概念相关披露读取第 45、59–77 段理解。具体工具接口和索引更新流程由配套管道文档定义。

## 8. 20 章后再观察什么

集中查看概念列表和同指候选，观察人物、身份、类别、地点等差异；检查重复关系、检索失败和反复出现的问题，再决定哪些需要正式建模。

建模层若建立，只整理已有证据，不覆盖原披露。抽取层可以复用它提供的词汇，但不负责修改模型，也不能因为模型没有相应字段而丢弃内容。

验收看答案和证据，不以图节点多为成功：身份揭晓、动机与剧情顺序、来源差异、原文细节、跨章同指、阅读位置限制。统计格式成功率、错误类型、输入输出 token、实际费用和问答检索成本。

TypeScript 是否比 JSON 稳定、概念粒度是否合适、20 章候选检索是否足够，均未验证。方向确认不等于这些实验结论已经成立。
