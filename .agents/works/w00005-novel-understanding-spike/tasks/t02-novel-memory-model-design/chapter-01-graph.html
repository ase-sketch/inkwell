v2 存的是「事实」：一条断言，加一个确定性档位。v4 不存事实——它存 披露：某个来源，在第某段，往某个槽里放了一个值。 「现在为真的是什么」不再是库里的一行，而是读到第 k 段时算出来的答案。 这一页把整章手工装完，看这套换法换来了什么、又露出了什么。

一章分两份存：evidences/chapter-01-beats.json 记正文怎么切， chapter-01.json 记记住了什么。两份都是真源，靠段号和主体 id 对接。 下面每一个数都是 scripts/build-viewer.ts 调 schema.ts 算好注进来的， 这一页自己不算——省得文档、数据、页面三处各自漂移。

B

拆分层：正文怎么切，和记住了什么，是两件事

Beat 是正文的连续切分：不留缝、不重叠、铺满全章。每个 Beat 有类型和来源， 叙事与描写的 Beat 还停在某个时刻上，故事外与说明的不停。 下面每一格是一个 Beat，宽度是它占的段数，高度是它产出的披露条数—— 高度为零的那几格最要紧：它们证明 Beat 层不能省。

M

时刻层：时刻不带钟点，先后是算出来的

时刻只是「故事时间轴上的一个位置」，本身不带任何数值，名字里也不许写相对时间词。 「五分钟前」不是名字，是一条关系：主语 + 谓词 + 锚点 + 偏移 + 说这话的段号 + 来源。 锚点留空表示锚在叙述当下——具体是哪一刻，由那条关系自己的段号定位。

S

槽层：是节点的是槽，不是命题

三个词分清楚，后面才不会乱：槽是主体加谓词，是个节点，id 一旦建好永不改； 命题是槽加一个值，它没有 id，也不进库；披露是命题加来源加叙述位置， 是另一种节点，只增不改。往一个槽里放第二个值，不是「改」，是再加一条披露。

槽 · 节点

苏天晴 · 居于哪具身体

id 是 S_su_inhabits。它永远存在，哪怕一条披露都没有——那时它是空的， 「空」和「不知道」是两回事。

命题 · 不是节点

（这个槽）= 这具狐女身体

没有 id，不进库。它只是「某条披露说了什么」的那一半。

披露 · 节点

第 16 段 · 叙述者 · 直陈

命题 + 来源 + 叙述位置（+ 时间指示）。只增不改：第 16 段确实写了这句， 这件事永远为真，后文再怎么翻案也改不了它。

D

披露层：来源和位置是字段，不是备注

每条披露都必须回答三个问题：谁说的（通道 + 说话人）、说得多硬（直陈 / 带保留 / 文本明确悬置）、 在第几段说的。第三个是这一版的关键——有了它，「读到第 k 段的读者知道什么」才算得出来。 读者推断是第六种通道，它额外要写明推断自哪些槽，而且不能拿另一条推断当前提。

来源通道条数要不要写说话人
说得多硬条数进不进「为真」那一堆

R

关系层：同一个槽里两条披露，是什么关系

判据只看三样：两条披露的时刻是不是同一个、值是不是相同、来源通道是不是相同。 设计文档第 5.6 节列了五行。装数据时补了第六行「并列累加」—— 那张表默认两个值互斥，而互不互斥由基数说了算：多值谓词上两个不同的值根本不构成一对关系。 不看基数就照表判，这一章会凭空判出三处「竞争」。

关系时刻值通道命中的披露对实例

T

切片：读到第几段，库里就只有几条

每条披露都带着自己的段号，所以「读到第 k 段的读者知道什么」只是一次过滤。 名字也跟着变：这一章里，古书先叫「黑色古书」，第 30 段才拿到专名。 检索时若不做这一刀，第一段就会把全书的专名漏给读者。

下面两段步骤由 schema.ts 的 evaluateSlot() 实际跑出来，不是手写的。 第二段故意留着错答案——遮住它没有任何好处。

两个页面分工：本页是走查，只摆不算；viewer.html 是工具，自带一套独立实现的求值与校验， 和 schema.ts 相互印证。
