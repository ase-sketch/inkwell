# 小说记忆模型 v3：读者视角（设计稿）

状态：**设计稿，等待开发者审查。** 不改 `schema.ts`、不改 `chapter-01.json`、不改 `viewer.html`、不改 `t03`。这一轮只有这一份文档。

来源标注：**全文为设计推导，未经实测。** 唯一的实测输入是 `t03/evidences/` 里那两次 DeepSeek 调用（见第 1.2 节），它只支持第 1.2 节那一条论证，不构成对本模型的任何验证。

与 v2 的关系：`memory-model.md`（`nbook.novel-memory/v2-spike`）继续有效，本稿**只写要改的部分**。`Kind`、`Individual`、`Predicate`、`Summary`、`Question`、`Mention` 六类的定义原样沿用 v2 第 4.1、4.2、4.3、4.7、4.8、4.9 节，本稿不重抄。要改的是模型的**立场**，以及立场带来的两个核心记录（v2 的 `Fact` 与 `Episode`）和整条故事时间轴。

## 1. 换掉的那个前提

### 1.1 v2 在记录「世界的真相」，这做不到

v2 从来没有明写它在记什么，但它的字段泄露了立场：`Fact.validFrom` / `validUntil` 是一对故事时间上的区间端点，`Episode.precedes` 是世界时间线上的先后。这两样东西合起来只有一个意思——**这张图在描述虚构世界里什么时候什么为真**。

这个立场做不到，因为它要求的信息量远大于文本给的。举一个最短的例子：

> 现在爱丽丝深爱着罗兰。殊不知三年前爱丽丝对他恨之入骨。

要把它记成世界真相，就得给爱丽丝的态度画一条完整的曲线：某个时刻从恨翻成爱。**文本从来不说这个翻转点在哪。** 于是只有两条路——编一个，或者留一个洞；而 v2 没有任何字段能表示这个洞。

这不是个别的疑难句。它是通例：**世界真相要求一个定义在整条时间线上的全函数，而文本永远只给几个采样点。** 中间怎么走，读者不知道，因为读者不是作者。

### 1.2 实测数据事先就指出了这件事

`t03` 那次真实调用（DeepSeek 官方 `deepseek-v4-flash`，S1 场景切分，第一章全文）在同一次响应里：

- **算错**了 `storyAfter`——把倒叙那一场排到了它出现的位置之后
- **抄对**了 `storyOffset: "五分钟前"`

两件事的差别正是两个立场的差别。`storyAfter` 问的是「这一场在世界时间线上排第几」——文本没给答案，只能推。`storyOffset` 问的是「文本在这里用了哪个时间词」——答案印在纸上。

**读者视角这个立场，事先就能预测哪一个会成功。** 这是本稿唯一一条有实测支撑的论证，也是最重要的一条。

### 1.3 数据自己也招了

`chapter-01.json` 的 26 条 `Fact`：

```
26 / 26   有 assertedAt（叙述位置）
 8 / 26   有 validFrom（故事时间）
 2 / 26   有 validUntil
 1 / 8    Episode 有 storyTime
```

叙述轴填满，故事轴三成。而 v2 第 5.1 节自己写着「**叙述位置是三条里唯一永远可得的**，应该是默认排序键」——然后把 `Fact` 的时间语义建在了故事轴上。**结论已经被写出来了，模型没有照着做。**

### 1.4 v2 内部有一处矛盾，也是同一个前提造成的

v2 第 4.4 节：

> | `narrated` | **叙述层认定为真** | 苏天晴居于狐女身体 |

v2 第 5.4 节：

> 倒叙、伏笔、**叙述性诡计**全都活在两条轴的差值里。

这两句不能同时成立。叙述性诡计的定义就是叙述者说的不为真；把 `narrated` 定成「认定为真」，等于宣布不支持它。

读者视角一句话解决：**`narrated` 不是「为真」，是「叙述者告诉我的」。** 它和「某个角色告诉我的」是同一类东西，只是来源不同、默认可信度不同。叙述者不可靠时，它只是又一个后来被推翻的来源，不构成模型危机。

### 1.5 上帝视角在这个仓库里已经有主了

`t01/context.md`：

> World Engine 是动态世界状态与**时间线真相源**；Plot System 是**作者视角**的剧情结构系统。

也就是说 v2 一直在做 World Engine 的活，做得不好；同时把只有它能做的那件事落下了。本稿把这个模型放回正确的一侧。这不是新增一个架构决定，是与已有架构对齐。

### 1.6 新立场

> **这张图记录的是「文本向读者披露了什么」，不是「虚构世界里什么为真」。**
>
> 每一条记录都是一次**披露**：谁说的、读者在第几处读到、说的内容是什么、内容里带没带时间指示。
>
> **故事时间不再是坐标系。它降级成披露的内容之一，并且和内容一样带认识论状态。**

最后半句是本稿最实质的改动。爱丽丝在第三章说「三年前」——那个「三年前」和她说的内容一样，可能记错，也可能撒谎。v2 的 `validFrom: Ref<Episode>` 没有 `status` 字段，**根本没法给时间打认识论标签**。

## 2. 三条时间轴，现在各归各位

| 轴 | 是什么 | 载体 | 性质 |
| --- | --- | --- | --- |
| **叙述位置** | 读者在文本第几处读到 | `at: DiscoursePos`，每条记录必填 | 全序，永远可得，**默认排序键** |
| **故事时间** | 文本说这件事什么时候 | `when: Ref<Moment>?`，可空 | 偏序，常缺失，**是内容不是索引** |
| 事务时间 | 我们的库什么时候写的 | 不进模型 | 只用于管线审计 |

v2 的问题一句话：**故事轴没有自己的载体，寄生在 `Episode.precedes` 上。** 叙述轴有 `DiscoursePos`，事务轴被明确排除，只有故事轴借住在别人家里——而房东（`Episode`）是不可变的，客人（故事顺序）却必然被后文修改。第 5.5 节那个死锁就是这么来的。

**关于「入库顺序等于叙述顺序」**：首次顺序入库时成立，但重跑、回填、章内并行时都不成立（这正是 `t03` 的 R1 只读前缀要防的四种场合）。所以模型不能拿入库顺序当叙述顺序用。不过这不影响结论，因为叙述位置是**显式存的**，不是从入库顺序推的。

## 3. 核心：一条披露

### 3.1 共同的脊梁

所有记录共享四样东西：

```
at        DiscoursePos      必填。读者在第几处读到。{chapter, paragraph}
source    Source            必填。谁披露的
when      Ref<Moment>?      可空。内容自带的时间指示
evidence  [Ref<Episode>]    承载它的场面
```

**`source` 必填是本稿与 v2 最大的形状差异。** v2 里 `status` / `holder` 是给「不确定的情况」打的补丁，默认值 `narrated` / `world` 意思是「这条是真的」。v3 里没有「默认为真」这一档——**每条记录都有来源，叙述者只是来源之一**。

### 3.2 来源：两个维度，不是一个枚举

```
Source {
  channel   narration | utterance | thought | inference
            叙述者说的 / 角色说出口的 / 角色心里想的 / 读者推断的
  holder    Ref<Individual>?     channel = narration 时为空
  hedge     plain | hedged | suspended
            直陈 / 带保留（「似乎」「大概」） / 文本明确悬置
}
```

v2 的六值枚举是这两个维度的一个不完整投影：

| v2 `status` | v3 `channel` | v3 `hedge` |
| --- | --- | --- |
| `narrated` | narration | plain |
| `claim` | utterance | plain |
| `belief` | thought | plain |
| `speculation` | utterance 或 thought | hedged |
| `disputed` | （随原来源） | suspended |
| `inference` | inference | plain 或 hedged |

拆开之后多出来两格是 v2 表达不了的，而且都常见：

- **`narration` + `hedged`** —— 叙述者自己带保留：「她似乎哭过」。v2 只能塞进 `speculation`，但 `speculation` 被定义成「某角色推测」，于是持有者要么错写成 `world`，要么丢掉。
- **`narration` + `suspended`** —— 叙述者明确悬置：「究竟是不是太奶，她自己也说不清」。v2 的 `disputed` 没有说这是谁悬置的。

**给抽取器的简化**：模型仍然只吐一个短名（沿用 v2 的六个词），由代码按上表展开成两个字段。抽取端不变复杂，模型端不失表达力。

### 3.3 时刻：故事时间的身份锚

```
Moment {
  id
  grain       point | interval
  label       string?        文本原话，如「三年前」「天元三年春」「那天晚上」。永远保留
  ofEpisode   Ref<Episode>?  若这个时刻就是某一场发生的时候
  mergedFrom  [Ref<Moment>]  同一性合并，与 Individual 同机制
  worldRef    string?        留给 World Engine 的对齐点，本期不用（第 10 节）
}
```

`Moment` 之于时间，正如 `Individual` 之于人物：**它是身份锚，本身不携带内容。**「三年前」是个称呼，不是坐标；两个「三年前」是不是同一个时刻，是一个同一性问题，走和实体合并完全一样的流程。

**时间关系不需要新类型——它就是一条披露。**

```
主语 = Moment      谓词 = before / after / during / overlaps / equals
宾语 = { t: "momentOffset", ref: Ref<Moment>, value?: 数, unit?: 串, approx?: 真假 }
```

`value` / `unit` 可空：「三年前」有距离，「后来」没有。没有距离就是纯先后关系，这是常态，**不编造。**

于是「三年前」在库里长这样：

```
M_now   Moment  interval  ofEpisode = 第一章那一场
M_3y    Moment  point     label = "三年前"

D_t     主语 M_3y  谓词 before  宾语 {momentOffset, ref: M_now, value: 3, unit: "年", approx: true}
        at = 第 1 章第 N 段    source = {narration, plain}
```

**时间关系本身带 `source`**，所以爱丽丝声称的时间和叙述者陈述的时间在库里是两种东西。这是 v2 缺的那一格。

比较两个 `Moment` 的先后 = 在这些关系上做偏序推理。**推得出就答，推不出就答「文本没给」**——后者是合法答案，不是失败。（区间之间的十三种关系是 Allen 1983 那套，本稿只用得到其中五种，不引入完整机制。）

### 3.4 `Disclosure`（原 `Fact`）

```
Disclosure {
  id
  subject     Ref<Individual|Kind|Moment|Disclosure>
  predicate   Ref<Predicate>
  object      ObjectValue          v2 的联合类型 + momentOffset 一档

  at          DiscoursePos         必填
  source      Source               必填。取代 v2 的 status + holder
  when        Ref<Moment>?         取代 v2 的 validFrom / validUntil

  evidence      [Ref<Episode>]
  inferredFrom  [Ref<Disclosure>]

  support     int                  几个来源披露过同一条
  centrality  float
  strength    float
  modality / volatility            沿用 v2
}
```

三处要说明：

**一、改名的理由不是洁癖。** 叫 `Fact` 就会被当成事实用——v2 的 `narrated = 叙述层认定为真` 正是这么来的。而且 `Fact` 在这个仓库里已经有两个意思了（`nb-memory` 的 `Fact` 指「发生过的事」，见 v2 附录 B），再加第三个只会更乱。**名字本身就是那个 bug。**

**二、`subject` 可以是另一条 `Disclosure`。** 这是取代 `retractedAt` 的机制，见第 4.3 节。

**三、`validFrom` / `validUntil` 整对删掉。** 理由：「现在爱丽丝深爱着罗兰」告诉你的是**在某个时刻为真**，没告诉你**从什么时候开始**。写成 `validFrom = M_now` 就编造了一个文本没给的坐标——而 v2 第 5.2 节自己立的原则是「永远不用编造文本没给的时间坐标」。**区间端点就是坐标。v2 把推论存成了断言。**

有效区间不是不能有，而是**派生**的：认知层按同一属性的若干观测点、谓词的基数规则和已知的时刻偏序推出来，随新披露收窄，随反驳作废。存的是观测，算的是区间。

### 3.5 `Episode`：从「发生的事件」改成「叙述的场面」

```
Episode {
  id
  at            DiscoursePos              必填。排序键
  span          {chapter, paragraph:{start, end}}   原文区间
  content       text                      释义，不含原文
  source        Source                    ★ 新增
  when          Ref<Moment>?              ★ 取代 storyTime
  context       {chapter, scene, location, pov}
  participants  [{entity, role}]
  outcome, valence, arousal, register, surprise      沿用 v2
                                          ✗ 删除 precedes
                                          ✗ 删除 partOf（改由 Summary 反向引用）
}
```

含义的变化是这一节的全部内容：

| | v2 | v3 |
| --- | --- | --- |
| Episode 是 | 世界里发生的一场事件 | **文本叙述的一次场面** |
| 所以要定位在 | 世界时间线 → 需要 `precedes` | 叙述轴 → `at` 就够了，且必填全序 |
| 倒叙是 | 一个「更早发生」的 Episode，要往链表前面插 | 一次**在第 11 段进行的叙述**，其内容带时间词「五分钟前」 |

**`source` 补上了 v2 的一个硬缺口。** v2 的 `Episode` 没有 `status` 也没有 `holder`，所以每一场都隐含是叙述者直陈的。**角色转述的场景在 v2 里没有表示**——「爱丽丝说：那天晚上我们在桥上吵了一架」是一场戏，但它是爱丽丝说的，可能是假的。这在小说里极常见，v2 一条也记不下。v3 里它就是 `source = {utterance, alice, plain}`。

**`precedes` 删掉之后，默认顺序去哪了？** 去了查询层，作为一条可被推翻的默认规则：

> **相邻叙述的两场，故事时间默认顺序推进，除非文本给了反向的时间指示。**

倒叙就是那个例外：第 11 段那一场带着 `when = M_b`，而库里有 `M_b before M_a distance 5分钟`，默认被推翻。**不需要拓扑排序，不需要 `storyAfter`。** 抽取阶段只要把时间词抄下来。

### 3.6 `Episode` 的编号跟着叙述顺序，不再重排

v2 里 `E1` 在第 11 段而 `E2` 在第 5 段——`E` 编号走故事序、`discoursePos` 走叙述序，两份文档和一个 HTML 都要专门解释这处「看起来最别扭的地方」。

v3 里它消失了：**编号按叙述位置分配，永不重排。** 故事顺序是查出来的，不是编出来的。

这顺带解开了一个死锁。v2 里 `E` 编号由 S1 的 `storyAfter` 拓扑排序决定，而 `Episode` 不可变（R3）——一旦 S1 换个提示词重跑并给出不同的故事顺序，全章 `Episode` 的 id 会整体重排，`validFrom` / `evidence` / `precedes` 全部失配，但 R3 又不许改。**最不可逆的东西由最弱的一步决定。** v3 里编号只依赖叙述位置，S1 判错时间关系只会让一条时间关系是错的，不会让全章 id 洗牌。

## 4. 两层：披露层与读者认知

### 4.1 为什么必须分两层

只有一层日志的话，一个属性在三十章里被提到三十次就是三十条记录，检索会被淹掉。

```
披露层    只增不改的日志。一条披露 = 命题 + 来源 + 叙述位置 + 时间指示
读者认知  派生视图，可重算，可作废。「读到第 k 处为止，一个读者认为什么」
```

这是事件溯源。仓库里 `nb-history/` 已经是这个模式（「事件溯源 + 内容寻址快照」），词汇是现成的。

### 4.2 读者认知怎么算

`readingState(k)` 是**唯一的**访问入口，输入一个叙述位置：

1. 取 `at ≤ k` 的全部披露
2. 应用其中的反驳（主语是另一条披露的那些）
3. 按命题分组：同命题不同来源的合并，`support` 计数
4. 用已知的时刻偏序给每组排序，推不出的保持并列
5. 产出三堆：**当前认为为真的** / **悬而未决的** / **已被推翻的**

v2 的 `snapshotAt()` 是这件事的一半（它只做第 1 步），可以作为起点。区别在于 v2 把它当成一个特殊函数，v3 把它当成默认路径。

**副作用：`t03` 的 R1「只读前缀」从一条需要防守的规则，降成一条自然性质。** 读者视角下「读到第 k 处的候选表」就是 `readingState(k)`，不需要额外机制来防止第 27 段的专名泄漏到第 5 段。

### 4.3 反驳是一条披露，不是一个字段

v2 用 `Fact.retractedAt` 记「后文推翻了它」。v3 删掉这个字段，改成：

```
D_99  主语 = D_07（那条披露）   谓词 = is_false   source = {narration, plain}   at = 第 20 章第 M 段
```

三个好处：

- **披露层完全只增不改**，没有任何原地回写。「第 1 章确实说了这句话」永远为真，这件事不该被后来的字段改动碰到
- **可以有多条互相矛盾的反驳**，各自带来源。v2 的单字段只能记一次
- 「我是从哪一章开始不信它的」照样答得出——找那条反驳的 `at`

v2 第 5.3 节那张表（追溯性揭示改哪些字段）整节作废，因为 v3 里**不改任何字段，只追加**。

### 4.4 「读者」必须是查询参数

否则立刻遇到「首次读者还是重读者」的歧义。

**库里存全部披露；「读到第 k 处的读者」是一次带参数的查询。** 重读就是拿全量查（`k = 末尾`）。首读第三章就是 `k = 第三章某段`。同一个库，不同参数，不同答案。

## 5. 关系判定：四种，不是两种

v2 只有「冲突 / 不冲突」两档，把四种不同的关系压进去了。同主语同谓词时，先比时刻，再比来源：

| 关系 | 判据 | 怎么处理 |
| --- | --- | --- |
| **竞争** | 时刻相同或重叠、值不同、来源通道相同 | 冲突。两条并存，回答时必须都给 |
| **认识论并存** | 时刻相同、值不同、来源通道不同 | 不是冲突。叙述者说 A、角色说 B，两条并存 |
| **接续** | 时刻可判定为不相交、值不同 | 不是冲突。各自为真，按时刻排序呈现 |
| **印证** | 时刻可判定相同、值相同、来源不同 | 合并，`support` 加一，来源列表追加 |
| （判不了） | 时刻推不出相同也推不出不同 | **候选同指**，进人工队列，同实体合并流程 |

v2 里第三行（接续）被压进「不冲突」，两条会一起返回，回答变成「她爱他，但她也恨他」；第四行（印证）也被压进「不冲突」，`support` 不涨，两个来源说的同一件事在库里是两条孤立记录。

最后一行是新的，而且不能省——见下一节爱丽丝的第二种写法。

---

## 6. 爱丽丝走一遍

### 6.1 第一种：同一章里的追述

> 第一章：现在爱丽丝深爱着罗兰。殊不知三年前爱丽丝对他恨之入骨。

```
M_a    Moment  interval  ofEpisode = Ep_1
M_3y   Moment  point     label = "三年前"

D_t    M_3y  before  {momentOffset, ref: M_a, value: 3, unit: "年", approx: true}
       at = ch1第N段    source = {narration, plain}

D_1    alice  loves         roland "深爱"      at = ch1第N段  source = {narration, plain}  when = M_a
D_2    alice  attitude_to   roland "恨之入骨"  at = ch1第N段  source = {narration, plain}  when = M_3y
```

`D_1` 与 `D_2` 的时刻可判定为不相交（`D_t` 给了）→ **接续**，不冲突。

「殊不知」这个叙述者姿态落在两条披露的 `at` 相同（同一段读到）而 `when` 相差三年上。**不需要建立任何世界时间线。**

### 6.2 第二种：跨章，且出自角色之口

> 第三章：爱丽丝说，其实她三年前对罗兰恨之入骨。

```
M_c    Moment  interval  ofEpisode = Ep_3       （第三章说话那一刻）
M_3y'  Moment  point     label = "三年前"

D_t'   M_3y'  before  {momentOffset, ref: M_c, value: 3, unit: "年", approx: true}
       at = ch3第M段    source = {utterance, alice, plain}      ← 时间关系本身是爱丽丝声称的

D_3    alice  attitude_to  roland "恨之入骨"
       at = ch3第M段    source = {utterance, alice, plain}    when = M_3y'
```

**这里有一处必须诚实的地方。** `M_3y` 是「第一章当下往前三年」，`M_3y'` 是「第三章说话时往前三年」。**如果第一章和第三章之间隔了时间，这两个不是同一个时刻。** 文本通常不给这个间隔。

所以判定落在第 5 节最后一行：命题相同、来源不同、**时刻推不出相同也推不出不同** → **候选同指**，走和实体合并一样的人工确认流程。批准后 `M_3y'` 合并进 `M_3y`，`D_2.support` 从 1 涨到 2，来源列表变成「叙述者@ch1、爱丽丝@ch3」。

v2 会怎么处理这种情况？**它会静默地当成两条无关记录**，因为 `status` / `holder` 不同就判「不冲突」，然后再也没有下文。两个来源说的是同一件事这个信息，永远不会被发现。

### 6.3 如果第三章她说的是反话

> 第三章：爱丽丝说，她三年前就深爱着罗兰。

```
D_3'   alice  attitude_to  roland "深爱"   source = {utterance, alice, plain}   when = M_3y'
```

与 `D_2` 同时刻候选、值不同、来源通道不同 → **认识论并存**。回答「爱丽丝三年前对罗兰什么感情」必须两条都给：叙述者说她那时恨他，她自己说是爱。

**这正是「不可靠角色」在数据层的样子**，而且不需要任何专门机制。

### 6.4 三个问题，三个答案

| 问题 | 走哪条轴 | 答案 |
| --- | --- | --- |
| 爱丽丝对罗兰什么感情 | 故事轴（时刻偏序） | 分两段：三年前恨，第一章当下爱 |
| 读者什么时候知道她曾经恨他 | 叙述轴 | 第一章 |
| 爱丽丝什么时候自己承认的 | 叙述轴 | 第三章 |
| 她什么时候变的 | —— | **文本没说**（合法答案） |

v2 能答第一问但会漏掉时间限定，第二三问答成同一个东西，第四问只能编。

## 7. 第一章重看：哪些记录会变

不改 `chapter-01.json`，这里只推演，用于说明改动幅度。

**大多数记录一个字不用动。** 26 条里 `assertedAt`、`status`、`holder`、`evidence` 全都是读者视角原生的东西——`F02`（她推测死因是心梗，`holder = su_tianqing`）与 `F03`（叙述层留白 `UNKNOWN`）本来就是两条来源不同的披露并存，这在 v3 里是模范样例，照抄即可。库里甚至已经有一条 `holder = reader` 的记录，那就是 `inference` 通道。

要变的集中在两处：

**一、`F06` / `F07` 的区间是编出来的。**

```
v2   F06  attitude_to "兴奋"  validFrom = E7  validUntil = E8   assertedAt = ch1第50段
     F07  attitude_to "后悔"  validFrom = E8                    assertedAt = ch1第64段

v3   D06  attitude_to "兴奋"  when = M(第七场)                   at = ch1第50段
     D07  attitude_to "后悔"  when = M(第八场)                   at = ch1第64段
```

`validUntil = E8` 断言了「她的兴奋恰好在第八场结束」。**文本没这么说。** 文本说的是第七场她兴奋、第八场她后悔，中间怎么变的没写。v3 存两个观测点，「取代」由认知层按谓词基数和时刻偏序算出来，「她什么时候不再兴奋的」诚实答「文本只给了两个时点」。

**连第一章的金标准都在这一点上多说了话**，说明这不是罕见情况。

**二、倒叙那一场。**

```
v2   E1  discoursePos = 第11段  precedes = [E2]  storyTime = {relative, anchor: E2, offset: "五分钟前"}
     E2  discoursePos = 第 5段  precedes = [E3]
     ……一条八节点的链，且编号按故事序重排

v3   Ep_1  at = 第 5段
     Ep_2  at = 第11段  when = M_b
     D     M_b  before  {momentOffset, ref: M_a, value: 5, unit: "分钟"}  label = "五分钟前"
           source = {narration, plain}   at = ch1第11段
     ……另外七场没有时间词，走「相邻默认顺序推进」，库里一条时间关系都不存
```

八条 `precedes` 变成一条时间关系加一条默认规则。要往过去插一个时刻，只是再加一条关系，**不碰任何已有节点**——v2 那个「插入必须改邻居，而 `Episode` 不可变」的死锁不存在了。

## 8. 不可妥协的规则（重写）

v2 第 6 节五条，改后如下。变动的地方标了。

1. **凡是需要来源或时间边界的东西，必须是节点，不能是节点属性。** 属性单值，装不下并存的多个值。（**沿用**）

2. **披露层只增不改。** 没有任何原地回写，包括撤销和取代。「第 k 段说了什么」永远为真。（**改**：v2 的不可变只覆盖 `Episode`，`Fact` 上仍留了 `validUntil` 与 `retractedAt` 两处原地回写，v2 第 6 节规则 4 是明确允许的。v3 把不可变扩到整个披露层，那两处改成追加。）

3. **证据只能指向 `Episode`；推断不能成为另一条推断的证据。** `evidence` 与 `inferredFrom` 严格分开。（**沿用**）

4. **有效区间是派生的，不是断言的。** 存观测点，算区间。任何写进库的时间端点都必须能追溯到一条文本给的时间指示。（**新，取代 v2 的「取代而非覆盖」**）

5. **来源必须一路传到最终回答。** 四个通道加三档保留，回答就必须携带对应的措辞强度。这是防幻觉的主要防线。（**沿用，口径从六档改成两维**）

6. **时间指示不得脱离来源。** 角色说的「三年前」和叙述者说的「三年前」在库里是两种东西，不得在检索或生成时被抹平成同一个。（**新**）

第 6 条是本稿的核心结论，也是 v2 完全没有的一条。

## 9. 与 v2 的对照

| v2 | v3 | 为什么 |
| --- | --- | --- |
| `Fact` | `Disclosure`（披露） | 名字本身诱导「当成事实用」，且 `Fact` 在本仓库已有另一个意思 |
| `Fact.status` + `holder`（六值） | `source`（通道 + 持有者 + 保留度） | 六值是两个维度的不完整投影，漏了「叙述者带保留」等两格 |
| `Fact.validFrom` / `validUntil` | `when: Ref<Moment>?` + 派生区间 | 区间端点是文本没给的坐标，v2 把推论存成了断言 |
| `Fact.retractedAt` | 一条主语是披露的新披露 | 让披露层完全只增不改 |
| `Episode.precedes` | 删除。默认顺序 + 时间关系推翻 | 链表对插入最不友好，而往过去插是小说的常态 |
| `Episode.storyTime` | `when: Ref<Moment>?`，与 `Disclosure` 同一类型 | v2 里 `Episode` 的时间表达力比 `Fact` 强一档，无理由 |
| `Episode` 无来源 | `Episode.source` | 角色转述的场景在 v2 里记不下 |
| `E` 编号按故事序重排 | 按叙述位置分配，永不重排 | 重排会让不可变的 id 随弱模型的判断整体洗牌 |
| （无） | `Moment` | 故事轴终于有自己的载体，不再寄生 |
| `snapshotAt()` 是特殊函数 | `readingState(k)` 是唯一入口 | 读者视角下这就是默认访问方式 |
| 冲突 / 不冲突 | 竞争 / 认识论并存 / 接续 / 印证 / 候选同指 | v2 把四种关系压成两档 |
| 第 5.3 节「追溯性揭示」 | 整节作废 | v3 不改字段，只追加 |
| `Kind` / `Individual` / `Predicate` / `Summary` / `Question` / `Mention` | 原样沿用 | 它们是词表和派生物，不涉及真相立场 |

**要动的部分是集中的。** v2 已经有一半是读者视角（`assertedAt`、`status`、`holder`、`evidence`），世界真相的部分集中在故事时间轴那几个字段。这不是推倒重来。

## 10. 留给上帝视角的对齐点

本期**只做读者视角**，不定义差值算法，不碰 World Engine。只留一个对齐点：

```
Individual.worldRef  string?      本期不用
Moment.worldRef      string?      本期不用
```

留它的理由写在这里，免得将来被当成无用字段删掉：

World Engine 是时间线真相源（上帝视角），本模型是读者视角。两者按实体身份和时刻身份对齐之后，**它们的差值就是伏笔**：

```
上帝视角：爱丽丝三年前恨罗兰，因为 X
读者视角（读到第三章）：知道她恨他，不知道 X
差值：X 还没揭
```

一个写作工具最该告诉作者的话是「读者到现在还不知道 X，你打算第几章揭」，以及反过来「你在第 12 章当成已知信息用了 X，但读者要到第 18 章才知道，这里会读不懂」。**单一真相图永远算不出这个**，因为它没有「读者不知道」这个概念。两个视角一分，它是免费的。
