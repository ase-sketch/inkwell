## 0. 前置：这份文档在做什么

### 0.1 要解决的问题

把一本已经写完的长篇小说读进一个**图数据库**，让一个 LLM 能回答关于这本书的问题——而且回答时**不能剧透**：问第三章的事，就不能用第二十章才揭晓的信息。

「图」在本稿里指一张普通的知识图：节点是人物、概念、时刻、事实槽等，边是它们之间的关系。**下文说「这张图」，指的就是这个库。**

典型的问题长这样，这四类是本模型的设计靶子：

| 问题 | 要的是什么 | 走哪条路 |
| --- | --- | --- |
| 讲一下这个世界的力量体系 | 一段综述 | 概念主体 → 它的自然语言介绍 |
| 苏天晴的关系网是什么 | 一张表 | 主体 → 挂在它身上的槽（第 5.4 节） |
| 现在剧情发展到哪了 | 一条线 | Beat 按叙述位置排（第 3.2 节） |
| 她为什么签了契约 | 一条因果链 | 顺着披露里的「推断自」往回走，再看支持它的原文（第 6 节） |

这个模型只负责**读已有的书**。写新书是另一套系统（产品里的 Plot System 与 World Engine），第 4 节说明两者的关系。

## 1. 立场：沿用 v3

v3 换掉的那个立场，v4 原样继承：

> **这张图记录的是「文本向读者披露了什么」，不是「虚构世界里什么为真」。**

一句话说清区别。假设书里写：

> 现在爱丽丝深爱着罗兰。殊不知三年前爱丽丝对他恨之入骨。

**记「世界的真相」**，就得说清她的态度是什么时候从恨翻成爱的——而文本永远不说这个翻转点在哪，模型只能编一个。

**记「披露」**，就只记两条：第一章告诉了读者「她现在爱他」，第一章也告诉了读者「三年前她恨他」。这是**两条独立的披露**（披露的完整定义见第 2 节词表和第 5.5 节），各自带着自己的来源和读者读到它的位置。中间怎么变的，答「文本没说」——这是一个合法答案。

我们是读者不是作者，拿不到的信息就不假装拿得到。

v4 不动这一条，只补上 v3 没写的那一半——**正文本身的结构**。v3 只说了记什么，没说正文怎么切开、切出来的东西挂在哪。

## 2. 词表

「Episode」这个词在本仓库已经有三个意思（`nb-memory` 包里的、认知科学里的情景记忆、v2 模型里的节点）。**v4 起停用它**，正文结构的节点叫「场 Scene」。

| 概念 | 是什么 | 是节点吗 | 例子 |
| --- | --- | --- | --- |
| **段** | 原文的一行，全局编号 | 否，是坐标 | 第 5 段 |
| **Beat** | 叙述的最小单位。一句话能说明的一段文字 | **是** | 第 9–12 段「这具身体的外貌」 |
| **场 Scene** | 章内时刻、地点连续的一段 Beat 区间 | **是**，派生 | 第 5–77 段（去掉回述那一段） |
| **章** | 外部给定的硬边界 | **是** | 第 1 章 |
| **卷 Act** | 章的分组，可空 | **是** | —— |
| **命题** | 一句「谁的什么是什么」。槽 + 值。**不带来源，不带位置** | 否，是载荷 | 苏天晴的发色是金色 |
| **披露** | 一次「说出」：命题 + 谁说的 + 读者在第几段读到 [+ 时间指示] | **是**，只增不改 | 上面那条，叙述者说，第 5 段 |
| **Fact / 槽** | 主体 + 谓词。一个可以被填的位置 | **是**，id 永不变 | (苏天晴, 发色) |
| **值** | 槽在某个阅读位置上的取值 | 否，算出来的 | 金色 |
| **主体 Entity** | 人物、组织、概念、地点、物品、身体 | **是** | 苏天晴、墨丘利秘典、力量体系 |
| **类 Kind** | 主体的归类标签，一个主体可以挂多个 | **是**，词表 | 狐女、典籍 |
| **谓词 Predicate** | 槽的第二个部件。带基数和易变度 | **是**，词表 | 发色、态度、居于 |
| **时刻 Moment** | 故事时间上的一个身份锚。有 id，没有坐标（第 5.7 节） | **是** | `M_a`：第一章那场对话发生的时刻 |
| **来源 Source** | 通道 + 持有者 + 保留度 | 否，是字段 | 叙述者 / 直陈 |
| **综述 Summary** | 一段自然语言，派生，可重建 | **是**，派生 | 主体介绍、剧情梗概 |
| **读者认知** | 读到第 k 段为止，对所有槽求值的结果 | 否，是查询结果 | —— |

「Beat」这个词与产品里的 `StoryPromiseBeat` 撞名。那个是「Promise 在某场戏上的推进记录」，与叙述单位无关。本 spike 内裸的 `Beat` 指叙述单位；合并回产品时建议把 `StoryPromiseBeat` 改名（见第 11 节 W2）。

**Beat 是叙述的最小单位，不是动作的最小单位。** 编剧里的 beat 只指戏剧动作，而本稿的 Beat 包含描写、说明和副文本——第一章的第 1–4 段（章标题与作者声明）是一个合法的 Beat，它在任何戏剧意义上都不是 beat。

### 2.1 Beat、命题、披露：三个最容易混的词

这三个词在本稿里出现得最密，先按**各自回答什么问题**分开：

| | 是什么 | 回答的问题 | 有 id 吗 |
| --- | --- | --- | --- |
| **Beat** | 一段连续的正文 | 这段文字在讲什么？读者读到哪了？ | 有 |
| **槽** | 主体 + 谓词 | 关于苏天晴，我们能问哪些问题？ | 有，永不变 |
| **命题** | 槽 + 值 | 答案的内容是什么？ | **没有**，它是一对值 |
| **披露** | 命题 + 来源 + 叙述位置 | 谁、在第几段、说了这句？ | 有，只增不改 |

一句话：**Beat 切的是文本，披露记的是内容，命题是披露的载荷。**

用 B03（第 9–12 段，那段外貌描写）走一遍就清楚了：

```
一个 Beat
   B03   第 9–12 段   类型 描写   时刻 M_a
         一句话「这具身体：金色长发、兽耳、精致五官、白皙肌肤、炸毛大尾巴」

若干条披露（每条落在一个具体段号上）
   (身体, 发色)   = 金色         叙述者/直陈   第 9 段
   (身体, 耳型)   = 兽耳、毛茸茸  叙述者/直陈   第 9 段
   (身体, 肤色)   = 白皙         叙述者/直陈   第 10 段
   (身体, 类)     = 狐女         叙述者/直陈   第 11 段

命题就是上面每一行里「槽 = 值」那一对
   比如「(身体, 发色) = 金色」
```

**为什么「命题」这个词非留不可**：如果第二十章又出现一句「她那头金发」，那是**同一个命题的第二条披露**——第 5.6 节表里的「印证」（合并、来源列表追加、支持数加一）判的就是这个。没有「命题」这个词，「同一件事被两个人说过」就没法表达。

**Beat 与披露之间不存边。** 披露自带段号，段号落在哪个 Beat 里是算出来的（第 6 节）。**一条披露只落在一个 Beat 里**，因为它只有一个段号。

**一个 Beat 的「一句话」不是披露。** 那是给人看的概括，由人或模型写；披露是给图用的结构化内容。B03 的一句话和它产生的四条披露是两码事，不要拿一句话当证据。

## 3. 正文的结构

```
卷（可空）
  └ 章                        外部给定的硬边界
      └ Beat                  章唯一的孩子。全覆盖，不跨章
            段号区间
            类型      故事外 | 叙事 | 描写 | 说明
            来源      多值
            时刻      可空，指向一个 Moment
            一句话    这个 Beat 在干什么

场 = Beat 序列上的一个区间标记，不是章的孩子
```

### 3.1 段是坐标，不是标注的载体

段只有编号，没有任何标注。归一化之后一行就是一段，段号就是行号。

**不给段打标签的理由**：一章 77 段就是 77 行元数据，而这 77 段原文本来就在。标签的价值在于**它划出的边界**，不在于每段贴了什么。既然价值在边界上，产物就该是边界围出来的区段，不是逐段的标签。

### 3.2 Beat

一个 Beat 是一段连续的段号区间，带四样东西。

**判断类型用两个问题：**

```
问一：它说的东西属于这个虚构世界吗？
   不属于 ──────────────────────────→  故事外
   属于  → 问二

问二：读完它，故事时间往前走了吗？
   走了 ────────────────────────────→  叙事
   没走，讲的是某一刻的具体状态 ──────→  描写
   没走，讲的是一般规律 ─────────────→  说明
```

| 类型 | 定义 | 第一章的例子 | 别的书 |
| --- | --- | --- | --- |
| 故事外 | 作者直接对读者说的话，不属于虚构世界。也叫**副文本** | 第 3 段「严正声明：本书出场角色均已满18岁」 | 三国演义开篇词、作者的话、章末求票 |
| 叙事 | 故事里发生的事，时间往前走 | 第 17 段「苏天晴鬼使神差地伸手，在尾巴上用力薅了一把」 | 绝大部分正文 |
| 描写 | 某一刻的具体状态，时间不走 | 第 9–12 段外貌 | 环境、人物外观、静物 |
| 说明 | 一般规律或设定，不发生在某一刻 | 第 72 段「王道系是什么？魔法少女们面对强敌逐渐成长……」 | 西游记开篇讲开天辟地、设定介绍、地理志 |

三国演义开篇那首「滚滚长江东逝水」是作者的感慨，在故事之外，属于**故事外**；西游记开篇讲开天辟地，属于这个世界但不推进任何一场戏的时间，属于**说明**。两首诗分在两边，说明这两个问题有区分力。

**这套分类与一套现成的文体分类（Carlota Smith 2003 讲的五种语篇模式）大体重合，她的判据也是「时间推不推进」。** 这只说明判据不是拍脑袋定的，不构成任何验证。

**来源是多值的，不是切分依据。** 试过把来源当切分依据，结果第一章第 42–77 段被切成二十来个一两行的碎片，因为对白你一句我一句、来源每行都在变——等于退回逐段标注。所以一个对白往复的 Beat，来源就是「古书说出口 + 苏天晴说出口 + 叙述者」，不切开。

来源沿用 v3 的三个字段，**通道从四个增加到六个**：

```
通道   叙述者 | 角色说出口 | 角色心里想 | 读者推断 | 系统通知 | 作者
持有者 指向一个主体；通道是叙述者、系统通知或作者时为空
保留度 直陈 | 带保留（「似乎」「大概」） | 文本明确悬置
```

v3 只有前四个。新增两个的理由都来自第一章：

**「系统通知」**——第 74、76、77 段：

> 【墨丘利秘典绑定成功。】
> 脑子里响起的声音让苏天晴欲哭无泪。

这不是古书说的（第 75 段明写「脑子里响起的声音」），说话人从未出现。四个旧通道一个都不匹配。硬塞进「角色说出口」就得为它造一个不存在的主体。这类写法（系统面板、金手指提示）在网络小说里极常见。

**「作者」**——第 3 段那句满18岁声明。**作者和叙述者是两个人**：叙述者是故事里那个讲述的声音，作者是现实中写书的人。故事外的 Beat 一律出自作者，不出自叙述者。这一条是把第一章的 Beat 真装进数据（`evidences/chapter-01-beats.json`）时暴露出来的——原本只列了五个通道，装不下第一个 Beat。

**时刻可空。** 故事外的 Beat 没有时刻（它不在故事世界里）；说明 Beat 没有时刻（讲的是一般规律，不发生在某一刻）；叙事和描写 Beat 有时刻。**时刻本身是什么、怎么量化，见第 5.7 节。**

### 3.3 Beat 的边界

```
硬边界（必须切）   类型变、时刻变、地点变
软边界（决定尺度） 一个 Beat 必须能被一句话概括，概括不了就切
```

只靠硬边界不够：第一章第 17–71 段同一个房间、同一个时刻、全是叙事，硬指标一路不变，会合成一个 55 段的巨块。

**软边界是语义的，不是结构的。这一点直接决定了管线的形状：Beat 只能由模型切，代码切不了。** 代码能做的只有校验——区间连续、不重叠、覆盖全章、段号在范围内。

判断「一句话能不能说明」的操作方式就是真去写那一句话。写不出来，或者写出来的句子里有「并且」「同时」「之后又」，就该切。

**推测这正是产品 Plot System 里 Scene 之下那一层「尺度定不好」的原因**：它曾经想切得比 Scene 更细，但结构规则在长对话里根本不变，而这一层的尺度本质上由语义决定。这一条是从产品文档和本次拆分推出来的，未与该模块的历史决策核对。

### 3.4 章边界优先于 Beat 边界

Beat 由段组成，段属于章，所以 Beat 不跨章。作者在一次交换中间断章时，那次交换会被章边界切成两个 Beat。

**这在实际文本上基本不成问题**，因为作者选断章点的标准和切 Beat 的标准是同一个——都要求断在一个能独立成立的地方。用第一章构造两个例子（第一章本身没有断章）：

**好的断章点正好落在 Beat 边界上：**

```
59  【既然你答应，那我们之间的契约就算成立了？】
60  "成立。"苏天晴不假思索。
61  但片刻后，狐狐突然反应过来了什么，好奇地问道：
62  "那个……我能问问契约的具体内容吗？"
63  总不能是激活了什么奇怪的奴隶契约吧！那样的话可就亏大发了！
    ———— 假设这里断章 ————
64  【反派魔法少女。】
```

第 59–63 段本来就是一个完整的 Beat（「契约算成立，她不假思索地承认；随后才想起问契约内容，担心是奴隶契约」），一刀没切到任何 Beat。

**真被切开时，两半各自仍然成立：**

```
50  "这就是你思想狭隘了，小破书。"
51  "我问你，世界上最通用的愿望是哪两个。"
52  【……哪两个？】古书愣愣地反问。
    ———— 假设这里断章 ————
53  只见金毛狐狐俯下身子，伸出两根手指……
54  "取之不尽的财富！以及变成萝莉！"
```

切开后两半分别是「她严肃地反问古书：世上最通用的愿望是哪两个？古书愣愣地反问哪两个」和「她伸出两根手指宣布：取之不尽的财富，以及变成萝莉——变成可爱狐狐本身就是最大的奖励」，都是一句话说得清的 Beat。

**粗暴断章（凑够字数就断）会切出半截 Beat，本稿的处理是不修，让它半截。** 不加标志位，因为这件事可以算出来：一个 Beat 结束在本章最后一段，下一个 Beat 从下一章第一段开始，两者的时刻和地点一致。这个判断与第 3.5 节「跨章的两个场要不要合并」用的是同一条，一次判断两处用。

### 3.5 场

```
场 = 章内的、时刻地点连续的 Beat 区间
```

五条性质：

**一、场是派生的，不是标注的。** 时刻和地点都是 Beat 上的字段，场的硬边界由它们算出来。

**视角不在这个列表里，这是有意的。** 详见下面第五点。

**二、场是区间，不是集合。** 区间内允许含不推进因果的 Beat。第一章有现成的例子：

```
第 71 段   叙事   时刻 M_a   她突然有点后悔了
第 72 段   说明   无时刻     王道系是什么……
第 73 段   叙事   时刻 M_a   她想能不能反悔……
```

第 72 段没有时刻，如果场是「有时刻的 Beat 的集合」，这一场就有个洞，或者被切成两段。改成区间就没有洞——**成员资格由区间决定，类型只决定这个 Beat 对因果推进有没有贡献**。副文本同理（网文的「作者的话」经常插在章中间）。

**这条规则只对「没有时刻」的 Beat 成立。区间内出现一个带着不同时刻的 Beat，就必须切开**，因为那是另一场戏。第一章的回述（第 16 段，文本说它发生在「五分钟前」）就是这种情况：它把房间里那场对话切成了前后两条场记录，两条共享同一个时刻，见下面第三点。

**三、场不跨章。** 一场戏被章切成两半时，会产生两条场记录。「这是同一场戏」靠**两条记录的时刻字段指向同一个 `Moment` 节点**来表达，而不是靠让它们变成同一条场记录。

代价是：抽取器分章处理时，第二章会新建一个 `Moment`，不会自动知道它和第一章那个是同一个。要让两者指向同一个节点，得走**候选同指 → 人工确认**，与实体合并、时刻合并同一条流程（第 5.6 节表格最后一行）。不是免费，但不是新机制。

第一章内部就有一个不跨章的同款例子——回述把房间里那场对话切成了 `SC1` 和 `SC3` 两条记录，两条的时刻都指向 `M_a`，见第 8 节第一条。

**四、场不是章的孩子。** 章唯一的孩子是 Beat；场是覆盖在 Beat 序列上的区间标记。这样章只有一种孩子，遍历、排序、编号都不用处理两种东西。

**五、视角不切场，参与者不存字段。**

**视角**指叙述贴着谁的意识写。第一章通篇贴着苏天晴，但有三个 Beat 漂到了古书身上（原文见第 8 节第三条）。

**视角漂移不构成场的硬边界。** 如果它是硬边界，第一章那一场连续对话会被三处漂移切成七段，而它显然是一场戏。所以视角在场上的形态是**一个主视角加一份漂移清单**，不是切分依据：

```
SC3   pov = 苏天晴   povDrift = [B07, B09, B17]
```

**这里有一个已知缺口，本稿不解决。** 三处漂移在数据里的可恢复程度不一样：

```
B07  第 20-22 段  有 心里想 + 持有者=古书       视角能从来源算出来
B09  第 28-29 段  只有 叙述者 + 带保留           算不出来
B17  第 57-58 段  只有 叙述者 + 带保留           算不出来
```

后两处是「像是在思考」「好像有哪里很对」这种写法——叙述者贴着古书写，却用「像是」「好像」表明自己没有真的进到它脑子里。持有者字段在通道是叙述者时按定义为空，所以**这两处的视角归属，现有字段一个都表达不了，只能靠 `povDrift` 人工标注**。这条记为待裁决 W8。

**参与者不给场加字段**，因为它可以算：区间内所有 Beat 的来源持有者的并集，再并上区间内被披露提到的主体。第二项不能省——只有第一项的话，**在场但从不说话也不思考的角色会算不出来**（第一章没有这种角色，两个角色都说话，所以这个缺口在本章不暴露）。加了第二项之后，「角落里的老仆低着头」这种一句带过的旁观者也能进来，因为那句话本身会产生一条披露，主体就是老仆。

加字段的代价是它会和 Beat 派生出的答案打架，还要维护一致性；算出来则和第一点「场是派生的」保持一致。

## 4. 与产品两棵树的关系

产品的 Plot System（`packages/neuro-book/assets/reference/plot/system.md`）有两棵树：

```
承载树（结构）  Story → Act(卷) → Chapter(章) → Prose(正文)
因果树（剧情）  Story → Phase(阶段) → Thread(线) → Scene(场)
交汇点          Scene.chapterId 挂章
```

本稿补的是**承载树底下缺的一层**：产品里 `Chapter → Prose` 之后就没有了，Prose 内部是一整块。加上 Beat 之后，交汇点从 Scene 下沉到 Beat，而且是**全覆盖**的——每个 Beat 必然属于某个章，不像 `Scene.chapterId` 是可空的。

**这也是产品那边「副文本、说明、通知这类文字无法表达」的解法**：它们不是漏掉了，是两棵树覆盖范围本来就不同。副文本和说明属于章，按定义就不进因果树。

### 三处必须写明的差异

**一、方向相反。** Plot System 是作者视角（先规划后写），本模型是读者视角（先有正文后拆）。作者写的 Scene 是规划意图，本模型算出的场是文本事实。两者应该大体对得上，**对不上的地方本身是信息**——「你规划了一场，写出来读者感受到的是三场」。

**二、Prose 的归属方向相反。** 产品文档写的是「一个章可关联多份 Prose（通常一份，草稿/重写版可共存）」，是章挂多份正文；本模型是一条连续正文被章切开。两者都对，因为写作时草稿并存、阅读时只有成品。**合并时要说清：本模型只对接定稿的那一份 Prose**，否则「一个 Beat 属于哪个章」在有两份草稿时会有两个答案。

**三、Thread 本 spike 不做。** 「这一场属于哪条线」是作者的意图，读者只能猜。后果是**因果树只有一半能自动对齐**：场能从正文算出来，线不能。合并时 Thread 仍然靠人手写或作者视角那一侧生成。

## 5. 记忆的结构

### 5.1 主体

v2 的 `Individual` 改叫**主体**，定义放宽：**人物、组织、概念、地点、物品、身体都是主体。**

改名的理由是叫 `Individual` 会让人以为只能装人，而「魔力体系」「力量体系」这种概念节点是检索的主要入口之一——问「讲一下这个世界的力量体系」时，它就是那个要被找到的节点。

**主体带一段自然语言介绍**，是派生的、可重建的，用途是一次性塞进上下文（比列十几个槽好用）。

**这段介绍必须带阅读位置，不能是一份全局介绍：**

```
读到第 11 段：「一本浮在半空的黑色古书，能以低沉的声音说话。来历不明。」
读到第 32 段：「墨丘利秘典。自称跨越星空而来，为寻找最出色的适格者。」
```

只存一份全局介绍，第一章的检索就会泄漏后文的专名。这与 v2 的 `Alias.since` 防的是同一件事。

### 5.2 类

**一个主体可以挂多个类。类只是标签，不给主体发字段，类与类之间没有父子关系。**

不建类树的理由：黑色古书同时是**物品**、**智慧体**、**知识载体**，单继承必须选一个当父类，选哪个都是错的。

**类不能当推理前提。** 「黑色古书是智慧体」当索引用没问题；但如果「智慧体」自带定义（有意图、有自我），就等于从我们发明的分类里推出了文本没说的东西——这本书从没说古书有自我意识，它可能只是个复读机。允许从类推事实，编造就从这里进来。

**预制类本轮不做。** 讨论过「预先注入一批通用类（智慧生物等）供组合」，开发者裁定先不考虑，等模型跑起来之后再作为优化方向。记录当时算出的两条约束备查：预制类只能当抽取阶段的提问清单（主体被标成「人」就去找姓名、年龄、外貌、关系），清单进提示词、标签进库、类的定义不进库；预制表只能是种子不能封闭，因为第一章出现的「适格者」「星界使者」「魔法少女」「反派魔法少女」「造物主」五个类，任何预制表都不会有。

### 5.3 谓词

沿用 v2，两个字段在本稿里承担了新职责：

- **基数**：这个槽是单值还是多值（发色单值，朋友多值）
- **易变度**：这个槽的值多久变一次

易变度决定要不要建槽。举例：

```
(身体, 耳型)         兽耳、毛茸茸        几乎不变      建
(身体, 耳朵数量)     两只                不变          建
(身体, 耳朵当前姿态) 耷拉 → 竖起         每一拍都在变  不建
```

第一章第 9 段说耳朵「耷拉」，第 18 段说「竖起」。如果这是同一个槽，两条就打架了；实际上它们不打架，是先后。**易变度太高就不建槽，留在 Beat 的一句话里。**

需要说明的是，**具体哪些槽值得建是偏好和精细度问题，不是模型问题**。开发者的口径是 `(身体, 外观)` 和 `(身体, 耳朵)` 都合理。本节给的是判据，不是清单。

### 5.4 Fact 是槽，不是值

**这是本稿对 v3 最大的一处改写。**

v3 把 `Fact` 改成了派生视图（一个叫 `readingState(k)` 的函数）。那样做的问题是：**函数的返回值没有 id，导航不过去。** 而检索路径里明确要求「有『力量体系』这个节点」「直接查 Fact，Fact 绑定的 Beat」——要的是能导航过去的节点。

修法是把身份和值拆开：

```
Fact（槽）    = 主体 + 谓词           是节点，有 id，永不变
填槽记录      = 值 + 来源 + 叙述位置 + 时间指示     只增不改
读者认知      = 在给定阅读位置对槽求值
```

举例：

```
槽 F: (苏天晴, 头发颜色)
  值 = 金色    来源 = 叙述者   第 5 段

槽 F: (爱丽丝, 对罗兰的态度)
  值 = 深爱      来源 = 叙述者    第 1 章    时刻 = 当下
  值 = 恨之入骨  来源 = 叙述者    第 1 章    时刻 = 三年前
  值 = 恨之入骨  来源 = 爱丽丝    第 3 章    时刻 = 三年前
```

拆开之后四件事同时成立：

- **「苏天晴的关系网是什么」变成一次纯图查询**：查她身上挂了哪些槽。不需要嵌入，不需要推理
- **槽的 id 永不变**，读到第几章都是同一个节点，可以稳定引用、稳定缓存
- **值随阅读位置变**，但那是求值结果，不是节点属性
- **披露层依然只增不改**，上面三条谁都不覆盖谁

v3 是把槽和值压成了一个东西，所以只能二选一：要么 `Fact` 可导航但会被改写，要么只增不改但导航不过去。**拆开就都能要到。**

**这条推翻了 v3 的待裁决 V1。** V1 原来问「`Fact` 要不要改名 `Disclosure`」，答案不再是改名，是**两个都留**：`Fact` 是槽，`Disclosure` 是填槽记录。

**三个名字指同一样东西，本稿统一用「披露」**：`Disclosure` 是它的英文名，「填槽记录」是它在槽这个视角下的说法。下文一律写「披露」。

### 5.5 披露

**所有往槽里填值的动作是同一种东西，区别只在来源。**

```
披露 = 槽 + 值 + 来源 + 叙述位置 [+ 时间指示]
       └─────┬─────┘
          这一对就是命题

来源是叙述者、角色、系统、作者  → 文本直接给的，这条披露可以当别人的支持
来源是「读者推断」              → 推断，另带「推断自 = [槽]」，不能当别人的支持
```

一个槽可以被多条披露填。用第一章的 `(身体, 尾巴)` 走一遍：

```
第 12 段  背后一只正在炸毛的大尾巴                叙述者，直陈   写的是外观
第 18 段  触感无比柔顺，被薅时的摩挲拉拽感直冲天灵盖  叙述者，直陈   写的是触感
```

两条都为真，两条都不推翻对方——它们描的是同一条尾巴的两个面。**这一处本模型处理得并不干净**：为了让两个值不互相排斥，`尾巴` 这个谓词的基数被迫写成多值，可她只有一条尾巴，多值这个名分不正当。真正缺的是「同一个东西的多面描写」，第 5.6 节那张表没有这一行。记在第 11 节 W12。

**这里有一条看着很自然但不许写的推断**：第 11 段说她是「一只娇小的金毛狐女」，于是推「狐女有狐耳，所以她有狐耳」。**不行**——这是从「狐女」这个类的定义里推事实，正是第 5.2 节禁止的那件事。这本书从没说过狐女长什么样，那个定义是我们自己带进来的。

**合法的推断长什么样，看第 7 节那条**：「苏天晴居于狐女身体」，它推断自的每一个槽里都装着文本里的具体句子，没有一处来自类的定义。

**没有槽就没有披露。** 不是文本里每句话都产生披露——建不建槽由第 5.3 节的易变度和价值判据决定，够不上的就留在 Beat 的一句话和原文里。第一章第 12 段「这应该是一只乖巧可爱的毛茸茸金毛狐狐」是叙述者的一句评价，**不建槽，也就不产生披露**，它只活在 B03 的原文里。同一段里「耳朵耷拉在头顶」的那个「耷拉」也是：耳朵姿态每一拍都在变，够不上建槽，进库的只有耳型本身。

**记下来不等于当真。** 这是另一件事，由保留度承担：第 29 段「古书……像是在思考眼前这只呆头呆脑的狐狐到底是不是自己要找的人」填了槽 `(古书, 目的) = 在找某个特定的人`，来源是叙述者、保留度是**带保留**。这条披露进库了，但它没有被当成确定的事——求值时它落在「悬而未决」那一堆里（第 5.6 节第 5 步）。

（注意填的是 `目的` 而不是 `在做什么`。「在做什么」每一拍都在变，按第 5.3 节的易变度判据够不上建槽。）

### 5.6 关系判定与读者认知

**读者认知 = 给定一个阅读位置，把所有槽求值一遍。** 沿用 v3 第 4、5 节，这里把它写全，因为它是本模型的主要查询方式。

设「读到第 k 段」，求值分五步：

1. 取 `叙述位置 ≤ k` 的全部披露，后面的一概看不见
2. 应用其中的反驳（见下）
3. 按槽分组，同一个槽的多条披露放在一起
4. 用已知的时刻先后给每组排序，推不出先后的保持并列
5. 每个槽产出三堆：**当前认为为真的** / **悬而未决的** / **已被推翻的**

第 3 步里同一个槽的多条披露怎么处理，看五种关系：

| 关系 | 判据 | 怎么处理 |
| --- | --- | --- |
| **竞争** | 时刻相同或重叠、值不同、来源通道相同 | 冲突。两条并存，回答时必须都给 |
| **认识论并存** | 时刻相同、值不同、来源通道不同 | 不是冲突。叙述者说 A、角色说 B，两条并存 |
| **接续** | 时刻可判定为不相交、值不同 | 不是冲突。各自为真，按时刻排序呈现 |
| **印证** | 时刻可判定相同、值相同、来源不同 | 合并，来源列表追加，支持数加一 |
| **候选同指** | 时刻推不出相同也推不出不同 | 进人工队列，与实体合并同流程 |

**这张表少一行，装第一章时才发现。** 上面五行**默认两个值互斥**，而互不互斥由第 5.3 节的**基数**说了算：多值谓词上两个不同的值根本不构成一对关系，它们只是并排放着。补第六行：

| 关系 | 判据 | 怎么处理 |
| --- | --- | --- |
| **并列累加** | 谓词是多值、值不同 | 不是冲突，也不是接续。两条都为真，都留着，不比先后 |

这一行优先于上面五行判——先看基数，再看时刻和来源。**不补这一行，第一章会凭空判出三处「竞争」**：「取之不尽的财富」和「变成萝莉」是同一个人主张的两个通用愿望，「苏天晴」和「古书」是同一份契约的两个相对方，尾巴的外观和触感是同一条尾巴的两个面——三处都被判成同一个来源前后打架。这不是新裁决，是把第 5.3 节已有的基数接进第 5.6 节。

（并列累加也不是终点。尾巴那一处真正缺的是「同一个东西的多面描写」——把基数写成多值只是绕过去，见第 11 节 W12。）

**反驳是一条披露，不是一个字段。** 后文推翻前文时，不去改前面那条记录，而是**追加一条新披露，它的主语就是被推翻的那条披露**：

```
第 1 章第 7 段    披露 D07：这具身体的主人是苏天晴      来源 = 叙述者
第 20 章第 M 段   披露 D99：D07 是假的                  来源 = 叙述者
                        ↑ 主语是另一条披露
```

这样做的好处是**披露层完全不用原地回写**：「第 1 章确实写了这句话」永远为真，不该被后来的修改碰到；而且可以有多条互相矛盾的反驳，各自带来源。「我是从哪一章开始不信它的」照样答得出——看那条反驳的叙述位置。

**本稿对 v3 改一处措辞。** v3 说这套求值是「唯一的访问入口」。加上槽之后不再是——**按主体导航到槽是另一条入口，而且是「苏天晴的关系网是什么」这类问题的主入口**（第 0.1 节那张表的第二行）。求值是对槽取值的那一步，不是全部。

上面这张表里「时刻相同」「时刻可判定不相交」这几个判据怎么算，见下一节。

### 5.7 时刻

v3 第 3.3 节写过这一层，**v4 第一版漏抄了**，只在第 2 节词表里留了一句「故事时间的身份锚」。本节补回，并改三处。

#### 5.7.1 为什么必须有它

一句话：**叙述位置回答「读者什么时候知道」，时刻回答「事情什么时候发生」。这是两件事，一条轴装不下。**

爱丽丝那个例子就是证明。「现在深爱」和「三年前恨之入骨」是同一个槽的两个值，**读者在同一段里读到，叙述位置完全相同**，来源也相同（都是叙述者）。差别只在故事时间上，差三年。

去掉时刻，具体会塌三样东西：

**一、第 5.6 节那张关系表整个失效。** 表里五行的判据全都要比较时刻。没有时刻，五行里没有一行能判定，所有同槽披露一律落到最后一行「候选同指」，也就是**全书每一对同槽披露都进人工队列**。这不是精度下降，是这套机制不能用了。

**二、回述分不出来。** 第一章的 B05（第 16 段，面摊猝死）与前后 Beat 的唯一区别就是时刻——地点是算出来的，类型都是叙事，来源都是叙述者。去掉时刻，第一章就只剩一个场，那句回述会被并进房间里那场对话。

**三、「三年前」只能当字符串存。** 两个「三年前」是不是同一个时刻，答不了。

这三条时间轴的划分沿用 v2 第 5 节（故事时间 / 叙述位置 / 事务时间），本节只补第一条轴的载体。

#### 5.7.2 它是什么

**时刻是故事时间上的一个身份锚：有 id，没有坐标。**

```
时刻 Moment
    id        永不变
    grain     点 | 区间      文本把它当一瞬还是当一段
    label     可空          见下面的限制
    note      人写的说明
```

「三年前」不是坐标，是一个称呼。两个「三年前」是不是同一个时刻，和两个「黑衣人」是不是同一个人一样，是同一性问题，走第 5.6 节最后一行那条流程。

**改 v3 一处：label 只能放绝对时间词。** v3 说 label 存「文本原话」，举的例子是「三年前」「天元三年春」「那天晚上」。这里面「天元三年春」当名字没问题，**「三年前」不行**——相对时间词脱离锚点就没有意义，把它写成节点的名字等于存了一条没有锚点、也没有来源的时间指示，直接违反规则 6。相对词只能进关系，不能当名字。

所以第一章五个时刻的 label 全是空的：M_a 是「房间里这场对话发生的时刻」，文本没给它任何名字；M_b 是「面摊那一刻」，文本管它叫「五分钟前」，而那是相对说法。**这一章连一个绝对时间词都没有。**

**时刻的来路有两条**，这一点 v3 没写清（v3 的 `ofEpisode` 字段暗示时刻是从场来的）：

```
一、一个 Beat 需要一个锚      哪怕文本没给任何时间词（M_a 就是）
二、一个时间词指向了它        哪怕这一刻从来没被演出来（见第 5.7.6 节）
```

推论：**时刻的集合比场的集合大，所以时刻不能由场生成。** v3 的 `ofEpisode` 是反的方向，v4 删掉它——`Episode` 这个节点本身也已经不在了，那个字段现在是悬空引用。

#### 5.7.3 放在哪一层

三个候选。**放在场上不是「完全不行」，是「够用但会亏两样」**，下面把账算清楚。

| 放在哪 | 结论 |
| --- | --- |
| **场上** | **不采用**，理由见下面两条 |
| **Beat 上** | **要。** 这段叙述停在故事时间的哪一刻 |
| **披露上** | **也要，而且不是同一件事** |

先说清楚为什么它看着可行：**同一个场里所有 Beat 的时刻必然相同**（不同就得切开，第 3.5 节）。既然场内恒定，把它提到场上就只是一次归一化，不丢信息。所以这个方案不是错的，它是**亏的**。

**亏的第一样：没有时刻的 Beat 表达不了。**

B22（第 72 段，说明，「王道系是什么」）夹在 SC3 中间，它**必须没有时刻**——一般规律不发生在某一刻。场级的一个字段会把它连同整段区间一起钉在 `M_a` 上，那是错的。要修就得在 Beat 上再加一个「本段不适用」的开关；而那个开关和直接在 Beat 上放一个可空的时刻字段信息量一样，还少了指向具体哪个时刻的能力。**纯亏。**

**亏的第二样：「时刻变」就不能再当场的硬边界了。**

这是一个真正的两难，得说明白：

```
时刻放 Beat 上   →  「时刻变」可以当硬边界，回述能被切出来
时刻放 场 上     →  场得先由别的判据切出来，时刻只能事后贴上去
                    于是「时刻变」不能出现在硬边界清单里
```

第二条路的代价是**同地点的回述切不出来**。第一章证明不了这一点——它的回述（第 16 段，面摊）同时换了地点，光靠地点就能切。要构造一个：

```
17  三年前，也是在这个房间里，母亲把这枚戒指交给她。
```

同一个房间、类型同样是叙事、来源同样是叙述者，**唯一变的就是时刻**。这种写法在小说里到处都是。时刻不在 Beat 上，这一刀就切不下去。

**两个挂钩，一种节点：**

```
Beat.时刻       这段叙述停在哪一刻
披露.时间指示   这条披露说的那件事在哪一刻为真
```

第一章有现成的例子证明它们必须分开：**B05 的时刻是 M_b（面摊那一刻），但它产生的披露「她连上了三个夜班」，时间指示是 M_b 之前的一段。** 一个字段装不下两个答案。

**场的时刻是派生的，不存字段。** 由区间内 Beat 的时刻算出来，规则见第 3.5 节第二点：区间内允许有没时刻的 Beat，出现第二个不同的时刻就说明该切了。

**一处需要澄清的措辞：「时刻变」指跳到另一段故事时间（回述、预叙、换场），不指场内正常的时间流逝。** 一场对话进行了一个小时，中间写「一小时后他才开口」，那仍然是同一个时刻区间 `M_a` 里叙述当下在往前走，不切场。

#### 5.7.4 怎么量化

**时刻本身不量化。量化的是时刻之间的关系。**

理由：「三年前」没有告诉你任何一端在哪，只告诉你差多少。要存坐标就得先编一个原点。**第一章整章没有一个绝对时间词**——它的时间线是一团浮着的相对位置，没有任何一点能钉在日历上，而这完全不妨碍回答「面摊那一刻在房间那一刻之前」。

```
时刻关系 = 主语 + 谓词 + 锚点 + 偏移 + at + 来源

主语   一个时刻
谓词   早于 | 晚于 | 同一 | 包含 | 重叠
锚点   关系的另一端。空 = 叙述当下（由 at 定位，见第 5.7.5 节）
偏移   可空。数值 + 单位。只对早于、晚于有意义
at     读者在第几段读到这条时间指示
来源   通道 + 持有者 + 保留度
```

**`at` 和来源必填，这是规则 6 的直接要求**：角色说的「三年前」和叙述者说的「三年前」是两条不同的记录，不得抹平。

**偏移可空。** 「后来」「片刻后」有先后没有距离，就只记谓词，**不编一个数字**。第一章大多数时间词是这一类：「随后」「接着」「良久后」「片刻后」「没有丝毫停顿」。

**精度由单位承担。** 「三年前」的单位是年，解出来的范围就到年为止，不许收窄到天。**所以 v3 的 `approx` 字段可以删掉**：真出现「大约三年前」，那个「大约」由来源的保留度（带保留）承担，不必再开一个字段。这是第二处改 v3。

**求值时解出来的是区间，不是点。** 把所有关系当成一组不等式一起解，每个时刻得到一个可能范围，再拿范围去喂第 5.6 节那张表：

```
两个范围不相交       → 判定先后        走「接续」
两个范围重合成一点   → 判定相同        走「印证」或「竞争」
范围重叠但不相等     → 判不出          走「候选同指」，保持并列
```

**这就是规则 4「存观测点，算区间」在时间轴上的样子。** v4 之前只把这条规则用在了槽的有效区间上，没说它同样管时刻。

区间之间那十三种关系是 Allen 1983 那套，本稿只用得到五种，不引入完整机制——沿用 v3 的裁定。

#### 5.7.5 「三年前」到底记成什么

```
不记成  2023-01-01              编了一个文本没给的原点
不记成  -3                      丢了单位，也丢了锚点
不记成  label = "三年前"        相对词当名字，没锚点等于没意义，而且这份 label 没有来源

记成一条关系：
   主语   M_恨          「她恨他」这条披露的时间指示指向的那个时刻
   谓词   早于
   锚点   空             也就是叙述当下：第 N 段那一刻
   偏移   3 年
   at     第 N 段
   来源   叙述者 / 直陈
```

一个数字丢掉的三样东西，这条记录都留着：**锚点、精度、来源。**

**锚点是「叙述当下」，不是 Beat 的时刻。** 这一条第一章就能证伪错的写法。

第 16 段的「五分钟前」是相对于**她此刻醒来的那一刻**说的，不是相对于面摊那一刻——否则就成了「面摊比面摊早五分钟」。**而这个 Beat（B05）的时刻恰恰就是面摊那一刻。** 所以锚点不能取 Beat 的时刻。

叙述当下指的是读者被带到的那个「现在」。绝大多数时候它等于 Beat 的时刻；**回述 Beat 里不等于**——回述 Beat 的时刻是被回述的那一刻，叙述当下仍然停在框架那一刻。它由 `at` 定位：第 16 段的叙述当下，就是包着这段回述的那个场（M_a）走到第 16 段时的那一点。所以锚点空着就行，不用另存。

故事外的 Beat 没有叙述当下（它不在故事世界里）。里面真出现相对时间词，只能显式给锚点，或者记成锚不上。

#### 5.7.6 第一章暴露的两处

**一、锚点写成时刻会凭空造出一条推论。**

数据里原先那条关系写的是「M_b 早于 M_a 五分钟」，锚点是 M_a 这个时刻。**这是错的**，因为 M_a 是一个区间，从第 5 段一直铺到第 77 段。把区间当成一个点用，两条锚在区间不同位置上的关系就会被当成锚在同一点上。

第一章正好有两条可以对撞：

```
第 16 段   面摊那一刻     早于 叙述当下   5 分钟
第 29 段   开场白那一刻   早于 叙述当下   2 分钟
```

两条都写成「早于 M_a」，直接推出**面摊比开场白早 3 分钟**——文本从没说过这句话。

改成锚在各自的叙述位置上之后，能推出的只有「**开场白至少比面摊晚 3 分钟**」：第 16 段那一刻不晚于第 29 段那一刻，中间隔了多久文本没说，所以只有下界没有等式。**一个是凭空造的等式，一个是老实的下界。**

**二、有一个时刻从来没有被演出来。**

第 29 段：

> 古书沉默了一会儿……良久后方才**重复了一遍两分钟前的开场白**：

接下来第 30、31 段是那段自我介绍。文本明说这是**重复**，而正文第 5 到 29 段里没有这段话——**原话说在正文开始之前，读者从来没读到过。**

于是这一刻：

- 没有任何 Beat 停在它上面，因为它不在正文里
- 没有任何场包含它
- 却被一条时间关系明确指向，还带着一个量化的偏移

**这就是第 5.7.2 节「时刻不能由场生成」的实物证据。** 时刻是场的属性也好、从场派生也好，这一刻都无处安放，而它是本章仅有的两条量化时间关系之一。

**同一章里还有第二个这样的时刻，成因不同。** `M_nightshifts`（连续三个夜班那一段）在正文里是被提到了的，问题不在于它没被演出来，而在于**提它的那个 Beat 停在别处**：B05 停在面摊那一刻（M_b），可它产出的披露说的是夜班那一段。这一条走的是第 5.7.3 节「两个挂钩，一种节点」——Beat 挂时刻和披露挂时间指示是两个不同的挂钩。两个时刻凑在一起说明：**「没有 Beat 停在上面」有不止一种成因，而它们都得能存下来。**

（这一条依赖一处阅读判断：「开场白」指的是第 30、31 段那段自我介绍，不是第 5 段的【姓名。】——因为被重复的内容就是自我介绍。作者也可能只是写得随意，但按字面读，结论如上。）

## 6. 证据

**证据统一指向披露，不指向 Beat 也不指向场。**

理由：披露自带段号，段号落在哪个 Beat、哪一场是算出来的，不需要再存边。而且证据的粒度天然是披露级的——「谁在第几段说了这句」才是证据，光有内容不算。

证据只有两种，必须分开：

```
支持     = [披露]     文本直接给的那些披露（来源不是「读者推断」）
推断自   = [槽]       从别的槽推出来的
```

**只有「推断自」进库，「支持」不进。** 支持是查询时算出来的：给定一条披露，扫同一个槽里叙述位置不晚于它、来源不是读者推断、且与它判成「印证」的那些披露，数出来就是支持数。存下来只会有两份真相，而且翻案之后那份存的还是旧的。`schema.ts` 里这一条叫 `supportOf()`，是个函数，不是字段。

**推断自指向槽而不是指向披露，是故意的。** 指向槽意味着「我是从那几个槽当时的取值推出来的」，槽的取值随阅读位置和后续披露变，所以这条推断可以重算——这正是第 7 节「做梦必须可重跑」的前提。指向具体几条披露就把推断钉死了，翻案之后重算不出来。

沿用 v2 的规则：**推断不能成为另一条推断的证据**，否则推断会自我循环放大。`schema.ts` 的 `validate()` 把这一条查死：每个「推断自」的槽里必须至少有一条非推断的披露，而且那条不能晚于推断本身。

**披露不一定有承载它的场面。** 叙述者直接给的设定不发生在任何场里——「这个世界有五种元素」可能就是一句旁白。第一章 66 条披露里，有 1 条来自作者（第 1 段的章标题）、3 条来自系统提示，这几条都不属于任何场，按本稿是正常状态，不是遗漏。

所以披露的来路有三种：**场面观察、他人告知、自己推断**。旁白设定属于第二种（叙述者告知），不需要场面。

## 7. 抽取：读与做梦

抽取必须分两步，两步的性质完全不同。第二步之所以叫「做梦」，是因为它干的事和人睡觉时干的事一样：**白天只管把见到的记下来，晚上离线整理——把零散的经历归纳成结论，把认错的人合并成同一个。** 这个名字只是比喻，不代表任何具体算法。

| | 第一步：读 | 第二步：做梦 |
| --- | --- | --- |
| 看多少 | 一章 | 全书已读部分 |
| 干什么 | 切 Beat、抽披露 | 跨场推断、合并同指、重建综述与介绍 |
| 能不能并行 | 能，章之间独立 | 不能，要全局 |
| 怎么验 | **能验**：每条披露必须能对回一个段号 | **验不了单条**，只能看支持链是否合理 |
| 什么时候跑 | 顺序入库时 | **离线批量，且必须可重跑** |

**推断不该在读的时候做。** 读第 4 段时不知道第 12 段有倒叙，硬要当场推断只会推错。等一章或若干章读完再统一整理。

**做梦这一步必须可重跑**，因为推断会失效：第二十章翻案了，之前推出来的值就得变。这件事之所以做得到，正是因为披露层只增不改——文本直接给的那些披露永远在，重跑一遍推断即可。

用第一章的一条推断说明为什么必须分两步（`chapter-01.json` 里的 `D22`）：

```
槽 (苏天晴, 居于哪具身体) = 这具狐女身体      来源 = 读者推断，叙述位置 = 第 16 段

推断自  (身体, 称呼)             第 8 段  「一道陌生的娇小身影」      叙述者
                                 第 11 段 「一只娇小的金毛狐女」      叙述者
        (身体, 类)               第 11 段 狐女                        叙述者
        (身体, 尾巴)             第 12 段 背后一只正在炸毛的大尾巴    叙述者
        (苏天晴, 前世的工作状况)  第 16 段 连续三个夜班后刚下班        叙述者
```

**四个槽的支持横跨三个 Beat（B02、B03、B05），没有一处是直说的。** 读到第 15 段这条还立不住，读者只知道「她觉得这身体陌生」；要到第 16 段那句回述才成立。第一步不可能得出它。

**注意写的是「推断自 = 槽」，不是「支持 = 披露」，而且这一处正好能看出区别。** `(身体, 尾巴)` 这个槽在第 18 段还会再进一条披露（「触感无比柔顺」），第 41 段还会冒出第五个佐证槽 `(身体, 原来的主人)`——古书承认它不知道原主是谁。做梦阶段重跑这条推断时，因为记的是槽而不是当初那几条具体的话，这些后来的都会自动被收进来。要是当初把披露 id 钉死，重跑就看不见它们。

```
M_c            第一次说开场白那一刻   没有 Beat，也不属于任何场——它落在正文之外
M_today        第 67 段的「今天」     没有 Beat，粒度是日，包着 M_a
M_nightshifts  连续三个夜班那一段     没有 Beat。B05 停在 M_b，这一段是 B05 产生的披露指过去的地方
```

**`SC1` 和 `SC3` 共享时刻 `M_a`，是被回述打断的同一场戏。** 「是同一场」由共享时刻表达，不由场的身份表达——所以场的区间保持连续，模型不需要支持带洞的区间。

**五个时刻里有三个没有任何 Beat 停在上面**，M_c 更是完全落在正文之外。这是第 5.7.2 节「时刻的集合比场的集合大」的实物：让场去生成时刻，这三个就没地方放。

**其中 `M_nightshifts` 是第 5.7.3 节「两个挂钩，一种节点」的实物证据。** B05 那一段写「结束了连续三个夜班后刚下班的自己坐在街边面摊上」——Beat 本身停在面摊那一刻（`M_b`），可它产出的披露「连续三个夜班后刚下班」说的是另一段时间。**Beat 挂时刻和披露挂时间指示是两个挂钩，指向同一种节点。** 只留一个挂钩，这一句就得二选一记错。

除了那一句回述，第一章就是一个房间里两个角色的一场连续对话，没换过地点，没跳过时间。

**而 `t03` 那次真实 S1 调用切出了 7 个窗口**（`t03/evidences/s1-windows.json`）。它切的不是场，是话题——也就是本稿说的软边界。**模型实际在做 Beat 切分，只是当时管它叫场。**

**二、场对检索来说太粗，Beat 才是检索单位。** 一个 73 段的场对检索没有用。分工是：

| | 尺度 | 用来干什么 |
| --- | --- | --- |
| **Beat** | 第一章平均 3.2 段 | 检索命中、Fact 的证据、摘要的输入 |
| **场** | 可能整章 | 与产品因果树的 Scene 对齐 |

**三、视角会在两个主体之间漂移，而产品的 Scene 只有一个视角字段。**

第 21、22、29、57–58 段四处，叙述贴到了古书身上：

```
21  黑色古书发出低沉的言语，不太明白眼前这只狐狐为什么要突然用怪异的手法去薅她自己的尾巴。
22  不疼的吗？
29  古书沉默了一会儿，像是在思考眼前这只呆头呆脑的狐狐到底是不是自己要找的人……
57  沉默。
58  好像有哪里很对，好像又根本不对……
```

`t03` 那次 S1 调用给七个窗口全部标了 `pov = 苏天晴`，**四处全漏**。

**而本稿现在的字段也只标得下三处。** `evidences/chapter-01-beats.json` 里 SC3 的 `povDrift` 是 `["B07","B09","B17"]`——Beat 级的，不是段级的。第 21、22 段同属 B07，被压成一条；第 29 段落在 B09；第 57–58 段落在 B17。**段级看是四处，Beat 级只标得出三条**，这是 W8 还没定下来的直接后果：视角现在挂在场和 Beat 上，而它实际是句子级的。

**四、一个 Beat 可以有多个来源。** 第 21 段前半句是叙述者报事实，后半句是叙述者贴着古书的脑子写。本稿的处理是**类型单值、来源多值**，不为此把 Beat 再切碎——段号是唯一永远可靠的坐标，允许切到句子这个坐标就没了。

**五、副文本没有时刻，但有叙述位置。** 第一章的第 1、2 段是章标题，原文就是「第1章 反派魔法少女」（归一化时重复了两遍）。它是故事外的 Beat，然而**读者在第 1 段就读到了「反派魔法少女」这个词，比正文第 64 段古书说出契约内容早了 60 多段**。

所以**故事外不等于不产生披露**。标题会剧透，而剧透就是一次披露，只是它的时刻永远为空、来源是作者。`chapter-01.json` 里这一对是 `D01`（第 1 段，作者）和 `D48`（第 64 段，古书说出口），**同槽同值、来源通道不同，判成印证——隔了 63 段**。

**六、「死因是急性心肌梗死」的唯一来源是第 73 段，是她自己在慌乱中猜的。**

> 我还能有反悔的机会吗？能不能把我送回原来的身体里啊我觉得急性心肌梗死还有抢救的机会——

不是诊断。`chapter-01.json` 把这条记成通道「角色心里想」、持有者苏天晴、保留度「带保留」，**记对了**，可以留作抽取的标杆样例。求值时它落在「悬而未决」那一堆里，全章没有第二条披露印证它。

## 9. 不可妥协的规则

沿用 v3 第 8 节六条，改两条、加一条。

1. **凡是需要来源或时间边界的东西，必须是节点，不能是节点属性。**（沿用）

2. **披露层只增不改。** 没有任何原地回写，包括撤销和取代。「第 k 段说了什么」永远为真。（沿用）

3. **证据分两种，严格分开：支持指向披露，推断自指向槽。推断不能成为另一条推断的证据。**（改：v3 里证据指向 `Episode`，本稿改为指向披露）

4. **有效区间是派生的，不是断言的。** 存观测点，算区间。任何写进库的时间端点都必须能追溯到一条文本给的时间指示。（沿用）

5. **来源必须一路传到最终回答。**（沿用）

6. **时间指示不得脱离来源。** 角色说的「三年前」和叙述者说的「三年前」是两种东西，不得在检索或生成时被抹平。（沿用）

7. **每一段正文属于且只属于一个 Beat；每个 Beat 属于且只属于一个章。**（新）没有这一条，副文本和说明就会重新变成没人管的正文，也就是产品那边现在的状态。

## 10. 与 v2、v3 的对照

**这一节只对读过 v2 或 v3 的人有用**，是一份改动清单。第一次读本稿可以跳过——前面九节已经是完整的模型，不依赖这张表。

| v2 / v3 | v4 | 为什么 |
| --- | --- | --- |
| `Episode`（v2 的节点） | 拆成 **Beat**（叙述单位）与**场**（因果单位） | 一个节点同时当检索单位、证据单位和因果单位，三个尺度要求不同 |
| `Episode.precedes`（v2） | 已在 v3 删除，v4 不恢复 | 链表对插入最不友好，往过去插是小说常态 |

| v3 待裁决 V1「Fact 改名 Disclosure」 | **作废，改成拆分** | 两个都要：Fact 是槽，Disclosure 是填槽 |
| v3 的 `readingState(k)` 是唯一入口 | 是**求值那一步**，不是全部入口 | 按主体导航到槽是另一条入口 |
| v3 证据指向 `Episode` | 证据指向**披露** | 披露自带段号，Beat 和场都能算出来 |
| `Individual` | **主体**，允许概念、组织、地点、物品、身体 | 概念节点是检索主要入口之一 |
| 类（v2 的 `Kind`） | 多标签，不建类树，不给主体发字段 | 一个主体常同时属于多个类，单继承选谁都错 |
| 来源四通道（v3） | **六通道**，新增系统通知与作者 | 网文的系统提示音没有说话人；作者与叙述者是两个人 |

| `Kind` / `Predicate` / `Moment` / `Summary` / `Question` / `Mention` | 原样沿用 | 不涉及本轮改动 |
| v3 的 `Moment.ofEpisode` | **删掉** | 方向是反的：时刻不由场生成，还有从没被演出来的时刻（第 5.7.6 节）。而且 `Episode` 节点本身已不存在，这是个悬空引用 |
| v3 的时刻关系宾语 `{ref, value, unit}` | 拆成**锚点 + 偏移**，锚点默认是**叙述当下** | 锚点写成时刻时，区间被当成点用，第一章会凭空推出「面摊比开场白早 3 分钟」（第 5.7.6 节） |
| v3 的 `approx` 字段 | **删掉** | 精度由单位承担；「大约」由来源的保留度承担 |
| v3 的 `Moment.label` 存「文本原话」 | 只许存**绝对**时间词 | 「三年前」当名字等于存了一条没锚点、没来源的时间指示，违反规则 6 |
