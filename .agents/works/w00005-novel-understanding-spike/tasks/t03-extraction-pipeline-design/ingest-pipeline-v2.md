# V2 ingest：先积累 20 章概念与披露

状态：设计稿，尚未实现、未执行 V6 真实调用。本次授权是文档落盘，不包括真实模型、嵌入服务调用或 20 章 ingest。

唯一数据合同：[临时 V6 模型](../t02-novel-memory-model-design/memory-model-v6.md)。本管道使用 V6，与旧 `extraction-pipeline.md` 的 v2 记忆模型不是同一个版本体系。旧调用器和旧证据保持不变，不宣称支持本管道。

## 1. 目标与边界

把前 20 章顺序转成可搜索的阅读记录，让 Agent 通过概念、披露、Beat 和原文回答问题，再据实际数据决定建模层。

本期不做概念分类、固定谓词表、世界时间排序、自动真值裁决和完整事件模型。不接产品数据库和页面，不把历史金标直接当 V6 的逐字段标准。

旧 t03 README 记录过 S1/S2 各一次真实调用，出现格式、时间排序和来源混淆问题。这说明本次需要测格式与语义，不证明 TypeScript 已经优于旧记法或 JSON，也不足以推出所有模型都需要相同阶段配置。

## 2. 主流程

```text
编号正文
  → A：切 Beat（LLM）
  → 准备旧概念候选（程序检索）
  → B：抽概念与披露（LLM）
  → 解析与结构检查（程序）
  → 装配章级证据图（程序）
  → 更新关键词和向量索引
  → 读书 Agent 查询
```

正常短章先采用一次 A、一次 B，不给每个 Beat 启动独立 Agent。长章超过配置的输入上限时，B 按完整 Beat 分批顺序抽取。单个 Beat 本身过长则报告需要重新切分，不静默截断正文。

章节按顺序处理；模型修改不在这条链里。候选检索与索引计算不必使用生成模型。真实调用数量取决于批次大小和失败情况，不宣称全书固定 40 次调用。

## 3. 各步输入输出

| 步骤 | 输入 | 输出与责任 |
| --- | --- | --- |
| 编号正文 | 获准的 20 章正文、章序 | 固定书标识、章节号、段号、正文哈希和归一化版本；原文只读 |
| A 切 Beat | 一章编号正文、固定 Beat 类型合同 | `const beats = [...] satisfies Beat[];`，连续覆盖全章的区间和简短概括；不生成故事时间排序 |
| 候选准备 | 当前正文的名称/词语与片段、此前已发布概念和披露 | 按关键词和语义召回有限候选，包含稳定引用、可见称呼、短上下文和证据位置 |
| B 抽取 | 当前批正文、Beat、候选、V6 类型合同 | `const extraction = {...} satisfies Extraction;`，新概念及披露；候选匹配明确时复用 `known:` 引用 |
| 解析检查 | 未改写模型输出、输入包 | 可接受字面数据或具体错误；检查语法、形状、引用和段号 |
| 装配发布 | 合法批次、来源元数据 | 稳定 ID 映射、完整章记录、概念到披露的连接；不解释自然语言关系 |
| 建索引 | 已发布记录和原文 | 关键词索引、向量索引、按概念查披露的邻接索引 |

首次运行没有旧概念候选也可抽取。检索遗漏旧概念时允许暂时重复登记，后续集中观察；不能为了去重按同名强制合并。批内局部引用由模型选择，程序仅做确定性解析和映射，不假装代码能完成语义消歧。

候选表按章前缀快照固定，重跑同一章不能读取后面章节才出现的名字和身份。章内大批次虽能看到稍后正文，仍必须只使用证据范围支持的称呼和内容；这是语义风险，结构检查无法保证，实验需要专门检查提前揭晓。

## 4. 抽取提示词的职责

A 只回答“这一章如何切成可概括的连续区间”。类型、来源和事件本体均不作为切分的新增必填分类；沿用 V6 的最小 Beat 形状。

B 只完成三个动作：识别值得持续追踪的概念；选取或新建引用；记录带证据的披露。明确要求：

- 不分类概念，不修改类型定义，不创造 model/trait/predicate。
- 披露可以写动作、观点、疑问、承诺、请求和设定；保留表达的语气和归属。
- 不把提问改成确认，不把计划或命令改成已发生事件，不把角色判断改成叙述者结论。
- 不把全部修饰语展开为独立属性，不为了图谱完整而补常识。
- 多来源分开记录；证据选择能支撑整条披露的最小充分区间。
- 输出纯 TypeScript，不输出解释性 Markdown，不自行定义类型或函数。

类型合同由程序注入，不由 LLM 每次重写。章号、书标识、来源哈希、Provider 信息和正式 ID 由程序负责。与旧管线不同，证据范围是模型选择的语言判断；代码只能核对坐标，不能凭空推导准确证据。

## 5. TypeScript 解析边界

本期允许固定顶层 `const` 声明、对象、数组、字符串、数字、布尔值、`null`，以及约定的 `satisfies` 类型名和 `as const`。A 只接受 `beats`，B 只接受 `extraction`，结构见 V6。

禁止 import、函数调用、new、赋值更新、展开、计算属性、插值模板以及任意可执行表达式。禁止 eval、动态 import 和转译后执行；从 AST 直接读取允许的字面量。TypeScript 类型检查使用管道提供的固定合同，不接受模型自带声明来绕过检查。

检查边界：

- Beat 连续、无重叠且覆盖本章；证据和概念登记位置落在输入范围。
- 局部 ID 唯一；`about` 和来源持有者只能引用本批概念或提供的旧候选。
- `source`、`mode` 和各字段值形状合法；完整原文坐标由程序补齐。
- 一条披露可以跨段或跨 Beat，Beat 关联按证据重叠派生；可见位置统一取证据末段。

检查不证明释义正确、同指正确、候选没有遗漏或概括没有剧透。失败输出原样保留，不自动改成看似合法的内容。TypeScript 格式优劣需要实际成功率与 token 证据。

## 6. 发布、失败与恢复

A 通过后可以保存中间结果，但只有 B 的全部批次通过结构检查，才发布该章的完整证据图。中间结果不进入读书 Agent 的正式查询。

同一次运行中，正式 ID 由书、章、阶段/批次和局部键映射生成。复用概念保留已有稳定 ID。完整输入、提示词、类型合同及模型配置共同标识运行版本；完全相同的已完成步骤恢复时复用产物，不重复调用和追加记录。

语法、引用或输出截断失败时记录错误并暂停该批。首轮默认不自动重试；开发者决定修正或重跑，失败调用也计入成本。修复提示词或重新切分产生新运行版本，不覆盖原始输出。需要替换已发布章时重新装配受影响的后续引用和索引，V2 不承诺任意修改旧章后自动无成本更新全书。

关键词和向量索引由发布数据派生。嵌入失败不删除已合法抽取的数据，标记索引未就绪；完整混合检索验收只使用索引就绪的章，不能把缺向量索引当成成功。

## 7. 检索接口与读书 Agent

以下是拟议工具职责，不是现有可调用 API：

| 工具 | 输入重点 | 返回内容 |
| --- | --- | --- |
| `searchConcepts` | 查询、`readAt`、数量上限 | 概念候选、当时可见的称呼和证据位置 |
| `searchText` | 查询、`readAt`、记录范围 | 关键词与向量混合命中的披露、Beat、原文位置，标出匹配类型 |
| `getDisclosures` | 概念引用、`readAt`、游标 | 相关披露、来源和证据，可分页 |
| `readSource` | 章与段区间、`readAt` | 不超过阅读位置的原文与真实坐标 |

概念名称用关键词匹配，长内容用语义检索补充。首次仅为披露和 Beat 概括建立向量；原文建立关键词索引并通过证据读取。若细节问题召回不足，再加入原文片段向量，而不是默认把所有粒度重复嵌入。嵌入按文本哈希与模型版本缓存，概念索引不单独生成一套易剧透的全书介绍。

检索服务先按可见位置过滤，再参与匹配和排序。跨 `readAt` 的 Beat 不使用完整概括；原文检索只考虑已读文本。不能只在 top-k 返回后删除未来结果，因为那会漏掉本应召回的已读结果，也不能让未来全文参与重排。

Agent 先获取短候选，必要时沿概念展开或读取原文；回答附章节段号，区分角色说法与推断。一次查询的工具轮次、返回条数、上下文量有配置上限；不足以判断时说明缺少的证据，不自动扫描全书。需要“全部事件”时采用显式分页或逐章扫描，并报告覆盖范围及额外成本。

## 8. 20 章实验顺序与成本

先用第一章走通 A/B、解析和检索，再用第二章检查概念复用。方向和调用预算确认后，顺序扩展到前 20 章；这两章属于 20 章实验，不是另一份数据集。

每次调用记录阶段、模型、提示词版本、来源哈希、输入输出及缓存 token、耗时、成功状态和实际请求次数；计费按对应 Provider 当时价格记录。缺少价格就标为费用未知，不捏造金额。分别统计抽取、失败/修复、嵌入、问答成本，不只展示成功输出的费用。

控制成本的初始决定：每章两步而非每 Beat 多 Agent；旧概念只召回相关候选；披露不穷举属性；已完成步骤可恢复；向量只重建变化文本；建模整理不随章节反复运行。

实际调用前仍需明确：获准的章节范围、抽取模型、嵌入模型、数据去向、费用上限和失败重跑预算。当前文档没有指定或授权这些受限动作，也没有测得推荐参数。

## 9. 验收与后续建模依据

最小问题集覆盖：古书何时揭晓名字；苏天晴为什么答应、何时后悔；星界使者是谁的说法；契约成立的各来源；耳朵数量等未结构化细节；跨章同名/同指；指定阅读位置下的答案。

检查四类结果：

1. 格式：A/B 原始成功率、失败类型、修复次数。
2. 阅读忠实性：证据支持、来源混淆、疑问变断言、身份提前揭晓、重要内容遗漏。
3. 检索与回答：能否定位证据、细节召回、跨章混淆、引用正确性和全量问题的覆盖范围。
4. 成本：每章和累计抽取费用、嵌入费用、每次问答 token、工具次数及耗时。

样本回答与正文人工对照，不用另一模型的认可代替真实证据，也不把第一章结果外推为全书准确率。出现剧透或来源误归，应定位抽取、同指、索引或回答中的实际错误，再决定是否继续扩章。

20 章产物应包括逐章原始输出、合法的概念与披露记录、可恢复的运行账本、索引、同指待观察列表和问题结果。随后一起看哪些概念值得分类、哪些关系值得规范化。分类与本体设计不属于此次 ingest 的前置步骤。
