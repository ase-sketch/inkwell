### 2. F-016（high）DTO 明确允许 `http://` 到任意主机

`shared/dto/passport.dto.ts` 的 `.regex(/^https?:\/\//)`。口子是为本机 dev 站开的（`DEFAULT_PASSPORT_SITE_URL` 是空串，注释写「开发环境通常是本机 nb-workshop dev 站」），**但没限定在本机**。

用户填了非本机的 http 地址之后：每次 token 轮换明文发送 `refreshToken`；`unlink` 明文发送 `refreshToken`；**备份上传把整个 State Root 连同 `Authorization: Bearer` 明文发出**。

修法：`http://` 只放行 `localhost` / `127.0.0.1` / `[::1]`。

与 F-017 是同一种毛病：**为本地开发方便开的口子，没有限定在本地。**

### 3. F-009（high）备份会静默丢掉整棵子树

`server/backup/backup-archive-service.ts` 的 `collectFiles`：

```ts
try { entries = await readdir(dir, {withFileTypes: true}); }
catch { return; }   // 注释写「目录不存在」，实际吞掉 EACCES/EPERM/EIO
```

任一子目录读不动，**整棵子树从备份里消失，而备份照样返回成功 + sha256 + 空 warnings**。用户到恢复那一刻才发现少了几章正文。

同文件 `snapshotSqlite` 的调用点证明 warnings 上报通道存在且工作正常——`collectFiles` 的签名里根本没接。修法：只把 `ENOENT` 当正常缺失，其余接进 warnings。

### 4. F-006 + F-008（high ×2）配置与状态文件非原子写，且读取端只兜 ENOENT

同一模式两处：

- **F-006** `server/workspace-files/novel-workspace.ts` 的 `writeUserSystemAssetsSyncState` / `readUserSystemAssetsSyncState`
- **F-008** `server/config/config-service.ts` 的 `writeJsonFile` / `readJsonFile` / `readJsonFileSync`（Global / Project Config）

写入是裸 `fs.writeFile` 就地重写；读取只 catch `ENOENT`，`JSON.parse` 的 SyntaxError 直接抛。写入瞬间被打断（掉电、容器被杀、磁盘满）后每次启动都崩，`product-start.mjs` 顶层 `await` 又没有 try/catch → **Product 永久起不来且不自愈**，用户只看到一段 JSON 解析栈。

**⚠️ 两处修法必须不同，这一点最容易搞错**：

- F-006 的 sync state 是**派生缓存**（`novel-workspace.ts:547` 的重建分支证明可重建）→ 写入原子化 **+** 解析失败按「文件不存在」处理
- F-008 的 `config.json` 是**真实用户数据**（含 API key）→ **只能**写入原子化，绝不能「解析失败就当不存在」——那是静默清空用户的全部设置

## 两条主线（比逐条看更有用）

**线一 · 持久化：代码没有一致地区分「预期内的缺失」和「意料外的失败」**

两个方向症状相反、病因相同：**兜得太窄**（F-006 / F-008 只认 `ENOENT`，文件损坏就掀翻进程）与**兜得太宽**（F-009 裸 catch 全吞，真错误变成静默丢数据）。巧的是两处注释都写着「文件不存在时……」——**写的人心里想的是 ENOENT，手上写的却不是**。

统一判据一句话：**每个 catch 都要说清楚，我想放过的是哪个 errno？**

附带缺口：全仓没有「原子写 JSON / 原子替换文件」的公共 helper，五个受害点各写各的。

**线二 · 安全：为本地开发方便开的口子，没有限定在本地**

F-017（Portable 免登录却绑全网卡）与 F-016（允许 http 却不限本机）是同一个思路的两次落地。附带的 F-013/F-014/F-015 则共享另一个小主题：**撤销只清了引用，没有失效凭据本身**——三条一个修法，给凭据加代次标记，`unlink()` 递增，消费点每次网络分片前校验。
