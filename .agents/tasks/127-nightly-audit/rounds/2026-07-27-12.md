## 这是 skill 的真缺陷，不是本次运行的意外

Phase 1 原本的基线命令是：

```bash
echo "$(git rev-parse --short HEAD) $(git status --short | wc -l)f $(git diff --shortstat | tr -d '\n')"
```

它不排除追踪目录。后果：

1. 夜审每轮都写 round 文件、改 `AUDIT-STATUS.md`。这些落在已存在的目录里时不改变行数，所以**前十一轮侥幸没出事**
2. 但**一旦新建一个顶层文件**（第 11 轮的 `REPORT-<日期>.md`），基线就变一格
3. 于是 Phase 4 的活跃度判据（上一轮基线 == 本轮基线）不成立 → **构建型命令的闸门再也打不开**
4. **而且完全看不出原因**：round 文件里只会写「另一会话仍在改动」，把自己的写入记成了别人的动静

**第一晚就会中招**：Phase 0 一次建 `AUDIT-STATUS.md`、`CHECKLIST.md`、`FINDINGS.md`、`rounds/` 四项，第 1 轮到第 2 轮的基线必然不同。今夜之所以没在开头暴露，只是因为前六轮 Task 118 确实在改，两个原因的表现一模一样——**真实的并发把这个 bug 完美地盖住了**。

### 修法（已写进 skill）

```bash
D=docs/tasks/127-nightly-audit; echo "$(git rev-parse --short HEAD) $(git status --short -- . ":(exclude)$D" 2>/dev/null | wc -l)f $(git diff --shortstat -- . ":(exclude)$D" 2>/dev/null | tr -d '\n')"
```

实测两侧都干净地排掉了追踪目录：

| 口径 | 结果 |
|---|---|
| 含自身 | `136f  120 files changed, 1461 insertions(+), 2969 deletions(-)` |
| 排除后 | `130f  119 files changed, 1393 insertions(+), 2960 deletions(-)` |

`git diff` 那侧也需要排除——追踪目录里的 `README.md` 是已跟踪文件，会进 `--shortstat`（120→119 files，1461→1393 insertions）。

顺带加了 `2>/dev/null`：Windows 上成片的 CRLF 警告会把输出淹掉，前面几轮每次取基线都刷四十多行噪音。

### 口径变更的处理

本轮起用新口径，所以「上一轮基线」（旧口径）与本轮不可比。按**保守方向**处理：视同已变化，本轮不跑构建型命令。已在 RUN 块里写明，下一轮起两侧同口径。
