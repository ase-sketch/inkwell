## 发现

### F-016（high）：DTO 明确允许 `http://`，refresh token 与整份备份可走明文

第 7 轮的怀疑成立。`shared/dto/passport.dto.ts`：

```ts
export const PassportLinkStartRequestSchema = z.object({
    siteBaseUrl: z.string().trim().min(1, "请填写官方站地址").max(200)
        .regex(/^https?:\/\//, "官方站地址必须以 http:// 或 https:// 开头"),
});
```

`https?` —— **`http://` 是被明确允许的**，错误文案还专门写出来了。允许它的理由能看懂：`DEFAULT_PASSPORT_SITE_URL` 是空串，注释说「开发环境通常是本机 nb-workshop dev 站」。

但**规则放得太宽：它允许 http:// 到任意主机，不只是 localhost**。一旦用户填了个非本机的 http 地址：

1. `refreshAccessToken` 每次轮换都把 `refreshToken` 明文 POST 过去
2. `unlink` 把 `refreshToken` 明文 POST 到 `/revoke`
3. **备份上传把整个 State Root（workspace + `config.yaml` + `.env`）连同 `Authorization: Bearer` 明文发过去**——`.env` 里有 `NUXT_SESSION_PASSWORD`

修法很窄：`http://` 只放行 `localhost` / `127.0.0.1` / `[::1]`，其余强制 https。

触发条件说清楚：**需要用户主动填一个非本机的 http 地址**。仓库没有内置任何 http 默认值（`DEFAULT_PASSPORT_SITE_URL` 是空串），所以不是开箱即中。

### F-017（high）：Windows Portable 默认「绑 0.0.0.0 + 完全关闭鉴权」

本轮最重的一条。三个前提**全部在代码里确认**，不是从文档抄的：

**前提一** —— 鉴权守卫在关闭时是彻底的空操作。`server/middleware/auth.ts`：

```ts
export default defineEventHandler(async (event) => {
    if (!isAuthEnabled()) {
        return;                    // ← 整个守卫直接放行
    }
    ...
});
```

（守卫本身写得很好：deny-by-default，`publicApiPaths` 只放行 5 个端点，`/api/passport/**` 不在其中。问题不在守卫的逻辑，在它可以被整体关掉。）

**前提二** —— 默认监听地址是全网卡，且**不分 profile**。`packages/neuro-book-manager/src/config.ts` 的 `ensureStateFiles`：

```ts
await writeTextAtomic(bootConfigPath, stringify({
    server: {host: "0.0.0.0", port},        // ← 无条件
    ...
    auth: {enabled: authEnabled},
}));
```

`config.example.yaml` 同样写 `host: "0.0.0.0"`。

**前提三** —— Portable profile 默认关鉴权。`packages/neuro-book-manager/src/cli.ts:98`：

```ts
authEnabled: options.auth ?? profile !== "windows-portable",
```

**三者相乘 = 默认的 Windows Portable 安装，把服务开在所有网卡上、且完全没有鉴权。** 同一个局域网（公司、宿舍、咖啡馆 WiFi）上的任何人都能直接调所有 API：读写用户的全部小说、触发并下载整份备份（含 `.env`）、解除 passport 关联、下载日志包、改配置。

「本地桌面应用不需要登录」这个取向本身没问题——但它正确的搭配是 `host: 127.0.0.1`。**当前代码把「不要鉴权」和「监听所有网卡」这唯一不该同时出现的两项配到了一起**，而且 host 那行根本不看 profile。

修法二选一：host 默认跟着同一个 profile 条件走（Portable 用 `127.0.0.1`）；或者在 host 非环回时强制打开鉴权。

## 读对了、不是缺陷的地方

- **`auth.ts` 的守卫逻辑本身是对的**：`isPublicPath` 白名单只有 5 个 API + 静态资源，其余一律要登录；API 返 401、页面重定向到 `/login`。还有测试锁住「`/api/app/version` 放行但 `/api/app/logs/status` 不放行」
- **`request-logger.ts` 做得很好**：只记路径与 query 的**键名和个数**，从不记值，键名命中 `token|secret|password|...` 还额外标 redacted。测试里直接断言日志不含正文和 token 值
